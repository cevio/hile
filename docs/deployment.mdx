## 基本步骤

```bash
# 1. 编译 TypeScript（脚本名以你的 package.json 为准）
pnpm run build

# 2. 生产模式启动（示例）
NODE_ENV=production hile start
```

若生产环境需要 env 文件：

```bash
NODE_ENV=production hile start --env-file .env.prod
```

## 生产模式与开发模式差异

| 特性 | `hile start --dev` | `hile start`（生产） |
|------|-------------------|---------------------|
| `NODE_ENV` | 强制设为 `development` | 强制设为 `production`（除非之前已被外部设定） |
| TypeScript | **tsx** 直接执行 `src/` | 运行 **编译后的 JS**，扫描 **`dist/`** |
| 容器事件日志 | 默认输出（除非带 `--silent`） | 不输出 |
| TypeORM SQL 日志 | 开启（`logging: true`） | 关闭 |

确保 **`tsconfig`** 的 **`outDir`** 与 CLI 在生产环境下扫描的目录一致（`dist/`），且 boot 与控制器路径在编译产物中存在。

## 优雅关闭

进程管理器（systemd、Kubernetes、Docker STOP）通常发送 **SIGTERM**。**`@hile/cli`** 通过 `async-exit-hook` 库捕获进程退出信号，触发 **`container.shutdown()`**，按 **LIFO**（后注册的先关闭）依次执行各服务的 shutdown 回调（关 HTTP、断 Redis、销毁连接池等）。服务级别的 shutdown 超时可通 `Container` 构造参数的 `shutdownTimeoutMs` 配置。

## 全栈（Next + HttpNext）注意点

含 **Next.js** 的模板往往需要 **先 `next build`** 再启动（具体以模板 **`package.json` scripts** 为准）；静态资源与 **`.next/static`** 需在部署产物中可用。
