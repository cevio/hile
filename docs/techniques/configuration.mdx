## 概述

Hile 的配置管理分布在多个层次：

1. **环境变量** —— 通过 `process.env` 访问，集成包的主要配置方式
2. **package.json** —— `hile.auto_load_packages` 声明自动加载的包
3. **YAML 配置文件** —— 通过 Registry 分发，适合运行时动态配置

## 环境变量

### NODE_ENV

CLI 根据 `--dev` 选项自动设置：

```typescript
// start.ts 中的逻辑
if (options.dev) {
  process.env.NODE_ENV = 'development'
} else {
  process.env.NODE_ENV = 'production'
}
```

影响的行为：

| 场景 | development | production |
|------|-------------|------------|
| 控制器目录 | `src/` | `dist/` |
| 文件编译 | tsx 实时编译 | 预编译 JS |
| 容器事件日志 | 自动订阅彩色输出 | 不输出 |
| TypeORM 日志 | 开启 | 关闭 |

### 集成包环境变量

**@hile/typeorm：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `TYPEORM_TYPE` | 数据库类型 | `mysql`、`postgres` |
| `TYPEORM_HOST` | 主机 | `localhost` |
| `TYPEORM_USERNAME` | 用户名 | `root` |
| `TYPEORM_PASSWORD` | 密码 | `password123` |
| `TYPEORM_DATABASE` | 数据库名 | `my_app` |
| `TYPEORM_PORT` | 端口 | `3306` |
| `TYPEORM_CHARSET` | 字符集 | `utf8mb4` |
| `TYPEORM_ENTITY_PREFIX` | 表前缀 | `app_` |
| `TYPEORM_ENTITIES` | 实体路径 | `dist/entities/**/*.js` |
| `TYPEORM_SYNCHRONIZE` | 自动同步 | `"true"` 开启 |

**@hile/ioredis：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `REDIS_HOST` | 主机 | `localhost` |
| `REDIS_PORT` | 端口 | `6379` |
| `REDIS_USERNAME` | 用户名 | `default` |
| `REDIS_PASSWORD` | 密码 | `redispass` |
| `REDIS_DB` | 数据库编号 | `0` |

### 设置方式

**命令行：**

```bash
TYPEORM_HOST=db.example.com hile start --dev
```

**.env 文件（推荐）：**

```bash
# .env
TYPEORM_TYPE=mysql
TYPEORM_HOST=localhost
TYPEORM_PORT=3306
TYPEORM_USERNAME=root
TYPEORM_PASSWORD=password123
TYPEORM_DATABASE=my_app
REDIS_HOST=localhost
REDIS_PORT=6379
```

## --env-file 加载

```bash
# 单个文件
hile start --dev --env-file .env

# 多个文件（先加载优先）
hile start --dev -e .env -e .env.local
```

加载规则：
- 使用 Node.js 原生 `process.loadEnvFile()`
- **先加载的文件优先级更高**（同一 key 不被后加载的覆盖）
- 不会覆盖 `process.env` 中已有的值

### 多环境配置

```bash
# 开发
hile start --dev -e .env -e .env.development

# 生产
hile start -e .env -e .env.production
```

推荐文件组织：

```
.env              # 基础配置（所有环境共享）
.env.development  # 开发覆盖
.env.production   # 生产覆盖
.env.local        # 本地配置（.gitignore）
```

## package.json 中的 hile 配置

### auto_load_packages

```json
{
  "hile": {
    "auto_load_packages": ["@hile/typeorm", "@hile/ioredis"]
  }
}
```

CLI 启动时对每个包名执行：`import(pkg)` → `isService(mod.default)` → `loadService(mod.default)`。

## Registry 配置管理

### 工作目录

```
~/.registry/
└── configs/
    ├── my-service.config.yaml
    └── payment.config.yaml
```

### YAML 文件格式

```yaml
# my-service.config.yaml
server:
  port: 8080
  host: "0.0.0.0"
debug: true
```

Registry 启动时扫描 `configs/` 目录，每个顶级 key 被发布为 topic：`registry:{namespace}/{key}`。

### 配置文件监听

Registry 通过 `fs.watch` 监听 `configs/` 目录，文件变更时自动重新读取并推送变更给订阅者。兼容 vim 的保存方式（写临时文件再重命名）。

## 配置分层最佳实践

| 层次 | 存储方式 | 作用范围 | 典型用途 |
|------|----------|----------|----------|
| 环境变量 | `process.env` | 进程级 | 数据库连接、密钥 |
| package.json | `package.json#hile` | 项目级 | 自动加载包 |
| YAML 配置 | `~/.registry/configs/` | 全局实时 | 运行时开关 |

**1. 敏感信息用环境变量**：`.env` 加入 `.gitignore`

**2. 运行时开关用 Registry**：通过 topic 订阅实现无需重启的配置变更

**3. 项目级配置用 package.json**：跟随代码版本控制

**4. 多环境用不同 env 文件**：`.env.development` / `.env.production`

## 常见问题

<AccordionGroup>
  <Accordion title="--env-file 和 Node.js 的 --env-file 有什么区别？">
    语义完全相同。CLI 内部使用 `process.loadEnvFile()`。
  </Accordion>
  <Accordion title="Registry 配置变更需要重启吗？">
    不需要。Registry 通过 `fs.watch` 监听文件变化，自动推送变更。
  </Accordion>
  <Accordion title="如何保护敏感配置？">
    - `.env` 和 `.env.local` 加入 `.gitignore`
    - `.env.example` 提交到 git（不含真实值）
    - 生产环境通过 CI/CD 或 K8s Secrets 注入
  </Accordion>
</AccordionGroup>
