## @hile/http 架构概览

`@hile/http` 是 Hile 框架的 HTTP 服务核心包。它建立在两个强大的底层库之上：

- **Koa** —— 业界知名的 Node.js HTTP 框架，提供优雅的中间件机制
- **find-my-way** —— 高性能的 HTTP 路由器（Fastify 同款）

`@hile/http` 将两者结合，形成了一条清晰的请求管线：

```
客户端请求
    │
    ▼
┌─────────────────────────────────────────────────┐
│ Koa 全局中间件链（按 use() 注册顺序）              │
│  ├─ 中间件 1（如：请求日志）                      │
│  ├─ 中间件 2（如：CORS）                         │
│  ├─ 中间件 3（如：鉴权）                         │
│  └─ ...                                         │
├─────────────────────────────────────────────────┤
│ router.routes()（listen 时自动注入为最后一道中间件）│
├─────────────────────────────────────────────────┤
│ find-my-way 路由匹配                              │
│  ├─ 匹配成功 → 路由级中间件 → 控制器 → 响应插件    │
│  └─ 未匹配 → defaultRoute（next()）→ Koa 默认 404 │
└─────────────────────────────────────────────────┘
```

这条管线的特点是：
- **全局中间件**在所有路由之前执行，适合做日志、鉴权、跨域等通用处理
- **路由级中间件**仅在匹配到特定路由时执行
- **响应插件链**对控制器返回值做后处理，适合统一包装响应格式

## 创建 Http 实例

```typescript
import { Http } from '@hile/http';

// 最简单的创建方式
const http = new Http({ port: 3000 });
```

### 配置参数

`Http` 构造函数接收一个 `HttpProps` 配置对象：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `port` | `number` | **必填** | 服务监听端口 |
| `keys` | `string[]` | 自动生成 | Koa 签名 cookie 密钥。不传时自动生成两个随机密钥 |
| `ignoreDuplicateSlashes` | `boolean` | `true` | 是否忽略重复斜杠（`//api//users` → `/api/users`） |
| `ignoreTrailingSlash` | `boolean` | `true` | 是否忽略结尾斜杠（`/users/` → `/users`） |
| `maxParamLength` | `number` | `Infinity` | 路径参数最大长度限制 |
| `allowUnsafeRegex` | `boolean` | `false` | 是否允许不安全的正则表达式（生产环境建议保持 `false`） |
| `caseSensitive` | `boolean` | `true` | 路由匹配是否区分大小写 |

```typescript
// 完整配置示例
const http = new Http({
  port: 3000,
  keys: ['my-secret-key-1', 'my-secret-key-2'],
  ignoreDuplicateSlashes: true,
  ignoreTrailingSlash: true,
  maxParamLength: 100,
  allowUnsafeRegex: false,
  caseSensitive: true,
});
```

### 获取端口

```typescript
console.log(http.port); // 3000
```

## Koa 中间件注册（use 方法）

`http.use(middleware)` 用于注册全局中间件，按注册顺序构成中间件链。中间件是标准的 Koa 中间件，接收 `(ctx, next)` 两个参数。

```typescript
// 请求耗时日志
http.use(async (ctx, next) => {
  const start = Date.now();
  await next(); // 执行后续中间件和路由
  const ms = Date.now() - start;
  console.log(`${ctx.method} ${ctx.url} - ${ms}ms`);
});

// CORS
http.use(async (ctx, next) => {
  ctx.set('Access-Control-Allow-Origin', '*');
  ctx.set('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
  ctx.set('Access-Control-Allow-Headers', 'Content-Type, Authorization');
  if (ctx.method === 'OPTIONS') {
    ctx.status = 204;
    return;
  }
  await next();
});

// use 返回 this，支持链式调用
http
  .use(middleware1)
  .use(middleware2)
  .use(middleware3);
```

**中间件的执行顺序**：想像一个洋葱，请求从外到内穿过所有中间件，响应从内到外穿回来。

```typescript
http.use(async (ctx, next) => {
  console.log('1. 进入中间件 A');
  await next();
  console.log('5. 离开中间件 A');
});

http.use(async (ctx, next) => {
  console.log('2. 进入中间件 B');
  await next();
  console.log('4. 离开中间件 B');
});

// 路由
http.get('/hello', async (ctx) => {
  console.log('3. 执行控制器');
  ctx.body = 'Hello';
});

// 收到 GET /hello 请求时输出：
// 1. 进入中间件 A
// 2. 进入中间件 B
// 3. 执行控制器
// 4. 离开中间件 B
// 5. 离开中间件 A
```

## 手动路由注册

`@hile/http` 提供了一组便捷方法用于注册 HTTP 路由。每个方法都返回一个**注销路由的函数**。

### 按 HTTP 方法注册

```typescript
// GET 请求
const offGet = http.get('/users', async (ctx) => {
  ctx.body = { users: [] };
});

// POST 请求
const offPost = http.post('/users', async (ctx) => {
  const body = ctx.request.body;
  ctx.body = { id: 1, ...body };
});

// PUT 请求
const offPut = http.put('/users/:id', async (ctx) => {
  ctx.body = { updated: ctx.params.id };
});

// DELETE 请求
const offDelete = http.delete('/users/:id', async (ctx) => {
  ctx.status = 204;
});

// TRACE 请求
http.trace('/debug', async (ctx) => {
  ctx.body = ctx.request;
});

// PATCH 请求
http.patch('/users/:id', async (ctx) => {
  ctx.body = { patched: ctx.params.id };
});
```

### 通用 route 方法

如果你想自定义 HTTP 方法（如 `OPTIONS`、`HEAD` 等），可以使用通用的 `route` 方法：

```typescript
const off = http.route('OPTIONS', '/users', async (ctx) => {
  ctx.status = 204;
});
```

### 路由级中间件

路由可以注册多个中间件，在到达控制器之前依次执行：

```typescript
// 验证用户身份
const authenticate = async (ctx, next) => {
  const token = ctx.headers.authorization;
  if (!token) {
    ctx.throw(401, '未提供认证令牌');
  }
  ctx.state.user = { id: 1, name: 'Admin' };
  await next();
};

// 验证请求体
const validateBody = async (ctx, next) => {
  if (!ctx.request.body || !ctx.request.body.name) {
    ctx.throw(400, '缺少必填字段: name');
  }
  await next();
};

http.post(
  '/users',
  authenticate,   // 先鉴权
  validateBody,   // 然后校验
  async (ctx) => { // 最后执行业务逻辑
    ctx.body = { message: `Hello, ${ctx.state.user.name}!` };
  }
);
```

### 路径参数

使用 `:paramName` 语法定义路径参数，通过 `ctx.params` 获取：

```typescript
http.get('/users/:userId/posts/:postId', async (ctx) => {
  const { userId, postId } = ctx.params;
  ctx.body = { userId, postId };
});

// GET /users/42/posts/7
// → { "userId": "42", "postId": "7" }
```

### 注销路由

每个注册方法都返回一个函数，调用后移除该路由：

```typescript
const off = http.get('/temporary', async (ctx) => {
  ctx.body = '临时路由';
});

// 移除路由
off();

// 此时再访问 /temporary 会返回 404
```

## find-my-way 路由器特性

`@hile/http` 内部使用 find-my-way 作为路由器。除了基本的路径匹配，它还支持：

### 多方法同路径

```typescript
http.get('/api/resource', async (ctx) => { ctx.body = 'GET' });
http.post('/api/resource', async (ctx) => { ctx.body = 'POST' });
http.put('/api/resource', async (ctx) => { ctx.body = 'PUT' });
```

### 通配符

```typescript
// 匹配 /files/ 下的所有路径
http.get('/files/*', async (ctx) => {
  // ctx.params['*'] -> 通配符匹配的部分
  ctx.body = { path: ctx.params['*'] };
});
```

### 正则表达式参数

```typescript
// 只匹配数字 ID
http.get('/users/:id(\\d+)', async (ctx) => {
  ctx.body = { id: ctx.params.id };
});

// GET /users/123  → 匹配
// GET /users/abc  → 不匹配，继续检查其他路由
```

## 控制器（defineController）

控制器是将路由注册和业务逻辑组织在一起的高级抽象。`defineController` 有三种重载形式。

### 重载 1：仅 method + 处理函数

最简洁的形式，适用于不需要校验和前置中间件的简单路由：

```typescript
import { defineController } from '@hile/http';

export default defineController('GET', async (ctx) => {
  return { message: 'Hello, World!' };
});
// 等价于：
// http.get('/path', handler)
```

### 重载 2：method + 前置中间件 + 处理函数

当路由需要前置中间件时使用：

```typescript
import { defineController } from '@hile/http';

const auth = async (ctx, next) => {
  if (!ctx.headers.authorization) {
    ctx.throw(401);
  }
  await next();
};

export default defineController(
  'POST',
  [auth], // 前置中间件数组
  async (ctx) => {
    return { success: true };
  }
);
```

### 重载 3：metadata + 处理函数（推荐）

最完整的形式，支持 Zod 校验：

```typescript
import { z } from 'zod';
import { defineController, createControllerMetadata } from '@hile/http';

const getUsersMeta = createControllerMetadata({
  method: 'GET',
  middlewares: [], // 可选的前置中间件
  schema: {
    query: z.object({
      page: z.coerce.number().default(1),
      limit: z.coerce.number().max(100).default(20),
    }),
  },
});

export default defineController(getUsersMeta, async (ctx) => {
  // ctx.query 已经是经过校验的（但类型不变，仍是原始字符串）
  return await getUsers();
});
```

## Zod 校验（query, params, body）

Zod 校验是 `defineController` 的第三重载的核心特性。当你在 `createControllerMetadata` 中提供 `schema` 时，控制器中间件会在调用处理函数前自动校验。

### 校验 query 参数

```typescript
const meta = createControllerMetadata({
  method: 'GET',
  schema: {
    query: z.object({
      page: z.coerce.number().min(1).default(1),
      limit: z.coerce.number().min(1).max(100).default(20),
      sort: z.enum(['asc', 'desc']).default('asc'),
      search: z.string().optional(),
    }),
  },
});

export default defineController(meta, async (ctx) => {
  // 校验失败自动 400，不会执行到这里
  return { page: ctx.query.page, limit: ctx.query.limit };
});

// GET /users?page=abc → 400 Bad Request
// GET /users?page=1&limit=200 → 400（limit 超过 100）
// GET /users?page=1&limit=20 → 200
```

### 校验路径参数

```typescript
const meta = createControllerMetadata({
  method: 'GET',
  schema: {
    params: z.object({
      id: z.coerce.number().positive(),
    }),
  },
});

export default defineController(meta, async (ctx) => {
  // ctx.params.id 是字符串，但经过校验确保是正整数格式
  return { id: ctx.params.id };
});

// GET /users/-1 → 400
// GET /users/abc → 400
// GET /users/42 → 200
```

### 校验请求体

```typescript
import { z } from 'zod';

const createUserSchema = z.object({
  name: z.string().min(1).max(50),
  email: z.string().email(),
  age: z.number().int().positive().optional(),
});

const meta = createControllerMetadata({
  method: 'POST',
  schema: {
    body: createUserSchema,
  },
});

export default defineController(meta, async (ctx) => {
  // body 已通过校验
  return { received: ctx.request.body };
});
```

### 同时校验多个

你可以同时校验 query、params 和 body：

```typescript
const meta = createControllerMetadata({
  method: 'PUT',
  schema: {
    params: z.object({
      id: z.coerce.number(),
    }),
    body: z.object({
      name: z.string().optional(),
      email: z.string().email().optional(),
    }),
    query: z.object({
      validate: z.coerce.boolean().optional(),
    }),
  },
});
```

### 校验行为说明

- 校验失败时，中间件调用 `ctx.throw(400, error.message)`，不会执行控制器
- 校验**不会改写** `ctx.query` 或 `ctx.params` 或 `ctx.request.body` 的值
- 这意味着在控制器中获取到的 query 值仍是原始字符串类型（而非 Zod 转换后的类型）
- 校验的目的是保证值的合法性，而不是转换类型

## 响应插件链（defineResponsePlugin）

响应插件链是 `@hile/http` 的一个独特特性。它允许你在控制器返回值写入 `ctx.body` 之前，对返回值进行一系列变换。

### 全局注册

插件通过 `defineResponsePlugin` **全局注册**。这意味着所有插件对所有 `defineController` 定义的控制器生效。

```typescript
import { defineResponsePlugin } from '@hile/http';

// 插件 1：统一响应格式
defineResponsePlugin(async (ctx, result, next) => {
  // 将结果包装为统一格式
  return await next({
    code: 0,
    data: result,
    timestamp: Date.now(),
  });
});

// 插件 2：错误格式包装
defineResponsePlugin(async (ctx, result, next) => {
  // 如果结果中有 error 字段，转为错误格式
  if (result && result.error) {
    return await next({
      code: -1,
      message: result.error,
      timestamp: Date.now(),
    });
  }
  return await next(result);
});
```

### 插件签名

```typescript
type ResponsePluginFunction = (
  ctx: Context,      // Koa 上下文
  result: any,       // 上一个插件传来的值（第一个插件收到的是控制器返回值）
  next: (r: any) => Promise<void>  // 调用下一个插件
) => Promise<any>;
```

### 执行流程

```
控制器返回值
  → 插件 1（传入 result = 控制器返回值）
    → 插件 1 调用 await next(transformed1)
      → 插件 2（传入 result = transformed1）
        → 插件 2 调用 await next(transformed2)
          → ...（后续插件）
            → 最终值写入 ctx.body
```

### 实际应用：统一响应格式

```typescript
// response-plugin.ts
import { defineResponsePlugin } from '@hile/http';

defineResponsePlugin(async (ctx, result, next) => {
  // 跳过已经设置了 body 的情况
  if (ctx.body !== undefined) return await next(result);

  // 跳过流式响应
  if (result instanceof Buffer || result instanceof require('stream').Readable) {
    return await next(result);
  }

  return await next({
    success: true,
    data: result,
  });
});
```

这样所有控制器的返回值都会自动被包装：

```typescript
// 控制器只返回数据
const meta = createControllerMetadata({
  method: 'GET',
  schema: { /* ... */ },
});

export default defineController(meta, async (ctx) => {
  return { id: 1, name: 'Alice' };
});

// 实际响应：
// {
//   "success": true,
//   "data": { "id": 1, "name": "Alice" }
// }
```

### 注意事项

- 插件是**全局**的，不区分 Http 实例
- 插件按注册顺序执行
- 插件必须在控制器注册之前注册，否则无法生效
- 如果控制器返回 `undefined`，不会触发插件链（也不会写入 `ctx.body`）

## 文件系统路由加载

文件系统路由是 `@hile/http` 的另一种路由组织方式。你可以将路由定义分散到多个文件中，然后通过目录加载。

### Loader 的 from 方法

```typescript
const http = new Http({ port: 3000 });

// 加载 controllers 目录下的所有路由文件
const unload = await http.load('./controllers', {
  suffix: 'controller',    // 文件后缀：*.controller.ts
  defaultSuffix: '/index', // 默认文件后缀
  prefix: '',              // 路由前缀
  conflict: 'error',       // 冲突策略
});

// 移除所有通过 load 注册的路由
unload();
```

### 文件命名转换为路由路径

`loader.ts` 中的 `from` 方法通过 glob 扫描目录，找到所有符合 `**.{suffix}.{ts,js,tsx,jsx}` 模式的文件。然后将文件名转换为路由路径：

```
controllers/
├── users.controller.ts       → /users
├── users/
│   ├── [id].controller.ts    → /users/:id
│   ├── [id]/
│   │   └── posts.controller.ts  → /users/:id/posts
│   └── index.controller.ts   → /users （因为 defaultSuffix: '/index'）
```

转换规则：
1. 去掉 `.{suffix}.ts` 后缀（如 `.controller.ts`）
2. 路径中的 `[param]` 转换为 `:param`（find-my-way 兼容）
3. 文件名后缀为 `defaultSuffix`（默认 `/index`）时，去掉该段
4. 反斜杠转正斜杠，合并连续斜杠
5. 可选添加 `prefix` 前缀

### 文件内容约定

每个控制器文件必须 `export default` 一个 `defineController(...)` 的返回值（单个或数组）：

```typescript
// controllers/users.controller.ts
import { defineController } from '@hile/http';

export default defineController('GET', async (ctx) => {
  return [{ id: 1, name: 'Alice' }];
});
```

```typescript
// controllers/users/[id].controller.ts
import { defineController } from '@hile/http';

export default defineController('GET', async (ctx) => {
  return { id: ctx.params.id, name: 'Bob' };
});
```

也可以导出数组：

```typescript
// controllers/users.controller.ts
import { defineController } from '@hile/http';

export default [
  defineController('GET', async (ctx) => {
    return { method: 'GET', users: [] };
  }),
  defineController('POST', async (ctx) => {
    return { method: 'POST', created: true };
  }),
];
```

### 路由冲突策略

当多个文件解析到同一个 HTTP 方法 + 路径时，会发生路由冲突。冲突策略由 `conflict` 选项控制：

| 策略 | 行为 |
|------|------|
| `'error'`（默认） | 抛出 `route conflict` 错误，阻止启动 |
| `'warn'` | 打印警告并保留先注册的路由 |
| `'override'` | 用新路由覆盖旧路由 |

```typescript
const http = new Http({ port: 3000 });

// 使用 warn 策略
await http.load('./controllers', {
  conflict: 'warn',
  onConflict: (ctx) => {
    console.warn(`路由冲突: ${ctx.method} ${ctx.url} (${ctx.resolution})`);
  },
});
```

### Loader 的 compile 方法

除了目录扫描，你也可以手动编译单个文件的路由：

```typescript
const http = new Http({ port: 3000 });

const controller = defineController('GET', async (ctx) => {
  return { hello: 'world' };
});

// 手动编译
const off = http.loader.compile('/custom-path', controller, {
  defaultSuffix: '/index',
  conflict: 'error',
});

// 注销
off();
```

## 启动服务器和关闭

### listen 方法

```typescript
const http = new Http({ port: 3000 });
http.get('/hello', async (ctx) => { ctx.body = 'world' });

// 启动服务
const close = await http.listen();

// 或者带回调
const close = await http.listen((server) => {
  console.log(`服务器启动在端口 ${http.port}`);
});

console.log('服务已启动');
```

`listen` 方法内部做了三件事：
1. 将路由中间件注入为最后一道 Koa 中间件
2. 创建 HTTP Server
3. 调用 `server.listen(port)`

**`listen` 方法必须在所有路由注册完成后再调用。** 因为 `listen` 时才会将路由中间件注入到 Koa 中间件链。

### 关闭服务器

```typescript
const close = await http.listen();

// 关闭
close();
```

在 Hile 框架中，通常不需要手动关闭。容器会自动在 `shutdown` 时处理关闭逻辑。

### 完整生命周期示例

```typescript
import { Http } from '@hile/http';
import { defineService, loadService, container } from '@hile/core';

// 将 HTTP 服务注册为容器服务
const httpService = defineService('http-server', async (shutdown) => {
  const http = new Http({ port: 3000 });

  // 注册中间件
  http.use(async (ctx, next) => {
    const start = Date.now();
    await next();
    console.log(`${ctx.status} ${ctx.method} ${ctx.url} - ${Date.now() - start}ms`);
  });

  // 注册路由
  http.get('/ping', async (ctx) => {
    ctx.body = 'pong';
  });

  // 启动
  const close = await http.listen();
  console.log(`HTTP 服务器启动在端口 ${http.port}`);

  // 注册清理
  shutdown(() => {
    console.log('关闭 HTTP 服务器');
    close();
  });

  return http;
});

await loadService(httpService);
// ... 运行中 ...
await container.shutdown();
// 输出：关闭 HTTP 服务器
```

## 完整示例：CRUD API

```typescript
import { Http, defineController, createControllerMetadata, defineResponsePlugin } from '@hile/http';
import { z } from 'zod';

// ---- 1. 响应插件 ----
defineResponsePlugin(async (ctx, result, next) => {
  return await next({ success: true, data: result });
});

// ---- 2. 创建 Http 实例 ----
const http = new Http({ port: 3000 });

// ---- 3. 全局中间件 ----
http.use(async (ctx, next) => {
  try {
    await next();
  } catch (err) {
    ctx.status = err.status || 500;
    ctx.body = { success: false, message: err.message };
  }
});

http.use(async (ctx, next) => {
  ctx.set('X-Powered-By', 'Hile');
  await next();
});

// ---- 4. 手动路由 ----
http.get('/ping', async (ctx) => {
  ctx.body = 'pong';
});

// ---- 5. 文件路由加载 ----
await http.load('./controllers', {
  suffix: 'controller',
  conflict: 'error',
});

// ---- 6. 启动 ----
const close = await http.listen();
console.log(`API 服务运行在 http://localhost:${http.port}`);

// 在 Hile CLI 环境下，close 会自动在退出时调用
```

## 常见问题

<AccordionGroup>
  <Accordion title="全局中间件和路由级中间件的区别是什么？">
    全局中间件通过 `http.use()` 注册，对所有请求生效。路由级中间件通过路由方法（如 `http.get('/path', mw1, mw2, handler)`）的第二个参数传入，仅当匹配到该路由时执行。全局中间件先于路由匹配执行。
  </Accordion>
  <Accordion title="响应插件和 Koa 中间件有什么区别？">
    响应插件专门用于处理控制器返回值，Koa 中间件可以修改整个请求/响应生命周期。响应插件有更明确的职责：将控制器的返回值转换为最终的 `ctx.body`。
  </Accordion>
  <Accordion title="文件路由加载时不希望使用默认的后缀名怎么办？">
    通过 `suffix` 选项自定义：
    ```typescript
    await http.load('./handlers', {
      suffix: 'handler', // 改为 *.handler.ts
    });
    ```
    然后在 handlers 目录下命名文件如 `users.handler.ts`。
  </Accordion>
  <Accordion title="如何给文件路由添加全局前缀？">
    使用 `prefix` 选项：
    ```typescript
    await http.load('./controllers', {
      prefix: '/api/v1', // 所有路由前缀变为 /api/v1/...
    });
    ```
    `users.controller.ts` 原本匹配 `/users`，带前缀后匹配 `/api/v1/users`。
  </Accordion>
</AccordionGroup>
