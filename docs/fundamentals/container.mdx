## 什么是 IoC 容器？

IoC（Inversion of Control，控制反转）容器帮你管理所有依赖的创建和销毁。在传统 Node.js 应用中，你这样组织代码：

```typescript
// 没有容器的写法：手动管理依赖
const db = await createConnection({ /* ... */ })
const redis = new Redis({ /* ... */ })
const server = new HttpServer({ port: 3000, db, redis })
```

问题：
1. **初始化顺序靠人脑记** —— 必须先创建 db，再创建 redis，最后创建 server
2. **全局状态难以管理** —— 测试时想 mock 某个依赖，得把整个初始化流程重写
3. **没有优雅关闭** —— 进程退出时需要按依赖逆序释放资源

Hile 的容器（`@hile/core` 中的 `Container` 类）是一个**异步容器**：服务的工厂函数可以是异步的，容器会等待异步初始化完成。

## 全局默认容器

当你 `import` 任何 `@hile/core` 的 API 时，Hile 自动创建一个全局默认容器，挂载到 `globalThis.HILE_GLOBAL_CONTAINER`：

```typescript
import { container } from '@hile/core'

// container 是全局默认容器
// 等价于：globalThis.HILE_GLOBAL_CONTAINER ??= new Container()
```

所有 `defineService` 和 `loadService` 快捷函数都操作这个全局容器。无论你在哪个模块 `import { container }`，拿到的都是同一个实例。

## Container 类——核心 API

`Container` 类提供以下公开方法：

| 方法 | 说明 |
|------|------|
| `register(key, fn)` | 注册服务（不执行工厂函数） |
| `resolve(props)` | 解析服务（执行工厂函数并缓存结果） |
| `shutdown()` | 优雅关闭所有已注册 teardown 的服务 |
| `on(listener)` | 订阅容器事件，返回取消订阅函数 |
| `off(listener)` | 取消订阅 |
| `hasService(key)` | 检查服务是否已 register |
| `hasMeta(key)` | 检查服务是否已有运行状态（已 resolve 过） |
| `getMetaByKey(key)` | 获取服务的 Paddings（status、lifecycle、value 等） |
| `getLifecycle(key)` | 获取服务生命周期阶段 |
| `getDependencyGraph()` | 返回 `{ nodes, edges }` 依赖图 |
| `getStartupOrder()` | 返回服务启动顺序数组 |

## defineService(key, fn) —— 注册服务

`defineService` 将工厂函数注册到容器。**注册时不会执行工厂函数**。

```typescript
import { defineService } from '@hile/core'

const greeting = defineService('greeting', async (shutdown) => {
  console.log('只在 loadService 时执行')
  shutdown(() => console.log('关闭时执行'))
  return '你好，世界！'
})
```

### 参数说明

| 参数 | 类型 | 说明 |
|------|------|------|
| `key` | `string \| symbol` | 服务唯一标识。字符串可读性好，Symbol 可避免命名冲突 |
| `fn` | `(shutdown) => R \| Promise<R>` | 工厂函数。`shutdown` 参数用于注册清理回调 |

### key 的选择策略

- **应用内的服务**用字符串：`'database'`、`'redis'`、`'http-server'`
- **集成包**用 `Symbol.for('包名')`：`Symbol.for('@hile/typeorm')`

```typescript
// 集成包通常这样做：
const SERVICE_KEY = Symbol.for('@hile/typeorm')
export default defineService(SERVICE_KEY, async (shutdown) => {
  // ...
})
```

### shutdown 回调

工厂函数接收 `shutdown` 参数，用于注册清理函数：

```typescript
const db = defineService('database', async (shutdown) => {
  const conn = await createConnection()
  shutdown(() => conn.close())          // 注册清理
  shutdown(() => console.log('已关闭'))  // 可以注册多个
  return conn
})
```

特性：
- 支持同步和异步函数
- 同一个函数重复注册只会执行一次（去重）
- 按 LIFO（后注册先执行）顺序执行
- 服务初始化失败时会**立即**执行已注册的清理回调

## loadService(props) —— 获取服务实例

```typescript
import { defineService, loadService } from '@hile/core'

const greeter = defineService('hello', async (shutdown) => {
  return '你好！'
})

// 第一次调用：执行工厂函数
const result1 = await loadService(greeter)  // '你好！'

// 第二次调用：直接返回缓存
const result2 = await loadService(greeter)  // '你好！'
console.log(result1 === result2) // true
```

### 并发合并

同时有多个调用者 `loadService` 同一个服务时，容器只执行一次工厂函数，其他调用者自动加入等待队列：

```typescript
const db = defineService('database', async (shutdown) => {
  console.log('只会打印一次')
  return await createConnection()
})

const results = await Promise.all([
  loadService(db),  // 真正执行
  loadService(db),  // 等待
  loadService(db),  // 等待
])
// 控制台只打印一次
```

## 服务间依赖

在服务 A 的工厂函数里 `loadService` 服务 B，容器自动记录依赖关系：**A 依赖 B**。

```typescript
const config = defineService('config', async (shutdown) => ({
  dbHost: 'localhost', dbPort: 3306,
}))

const database = defineService('database', async (shutdown) => {
  // 在 database 工厂里 load config → 自动记录 database → config
  const cfg = await loadService(config)
  const conn = await createConnection({ host: cfg.dbHost, port: cfg.dbPort })
  shutdown(() => conn.close())
  return conn
})
```

## 循环依赖检测

容器在运行时检测循环依赖。当服务 A 初始化中请求服务 B，容器检查是否存在 B → ... → A 的路径：

```typescript
// 错误示例：循环依赖
const serviceA = defineService('a', async (shutdown) => {
  await loadService(serviceB)  // A 依赖 B
  return 'a'
})
const serviceB = defineService('b', async (shutdown) => {
  await loadService(serviceA)  // B 依赖 A —— 循环！
  return 'b'
})
// 运行时抛出：circular dependency detected: a -> b
```

自循环也会被检测：

```typescript
const self = defineService('self', async (shutdown) => {
  await loadService(self)  // 自己依赖自己
  return 'self'
})
// 抛出错误
```

钻石依赖（A → B → C 且 A → C）是安全的。

## 服务状态

每个服务的内部状态通过 `getMetaByKey(key)` 查看：

| 状态码 | 含义 |
|--------|------|
| `0` | 运行中——工厂函数正在执行 |
| `1` | 已完成——工厂函数成功，结果已缓存 |
| `-1` | 已失败——工厂函数抛错 |

生命周期阶段（`getLifecycle(key)` 返回）：

| 阶段 | 说明 |
|------|------|
| `undefined` | 尚未被 loadService |
| `'init'` | 工厂函数正在执行 |
| `'ready'` | 服务就绪 |
| `'stopping'` | 正在执行清理回调 |
| `'stopped'` | 清理已完成 |

## AsyncLocalStorage 依赖追踪

容器使用 Node.js `AsyncLocalStorage` 追踪调用链。当工厂函数执行时，容器将当前服务 key 存入 AsyncLocalStorage 栈中。当工厂内部调用 `loadService` 时，容器知道"当前是谁在请求"，从而正确记录依赖边。这个机制对开发者完全透明。

## 查询 API

```typescript
import { container, defineService, loadService } from '@hile/core'

const mySvc = defineService('my-service', async (shutdown) => 'hello')

// 检查是否已 register
container.hasService('my-service')  // true

// 检查是否已 resolve（有运行状态）
container.hasMeta('my-service')      // false

await loadService(mySvc)

container.hasMeta('my-service')      // true

// 获取元数据
const meta = container.getMetaByKey('my-service')
meta.status       // 1（已完成）
meta.value        // 'hello'
meta.lifecycle    // 'ready'
meta.startedAt    // 启动时间戳
meta.endedAt      // 完成时间戳

// 获取生命周期
container.getLifecycle('my-service') // 'ready'

// 获取依赖图
const graph = container.getDependencyGraph()
// { nodes: ['my-service'], edges: [] }

// 获取启动顺序
container.getStartupOrder()
// ['my-service']
```

## 事件订阅

容器是一个事件发射器。`on()` 返回取消订阅函数：

```typescript
import { container, formatServiceKey } from '@hile/core'

const unsubscribe = container.on((event) => {
  switch (event.type) {
    case 'service:init':
      console.log(`服务 ${formatServiceKey(event.key)} 开始初始化`)
      break
    case 'service:ready':
      console.log(`服务 ${formatServiceKey(event.key)} 就绪（${event.durationMs}ms）`)
      break
    case 'service:error':
      console.error(`服务 ${formatServiceKey(event.key)} 失败:`, event.error)
      break
    case 'service:shutdown:start':
      console.log(`服务 ${formatServiceKey(event.key)} 开始关闭`)
      break
    case 'service:shutdown:done':
      console.log(`服务 ${formatServiceKey(event.key)} 关闭完成（${event.durationMs}ms）`)
      break
    case 'service:shutdown:error':
      console.error(`服务 ${formatServiceKey(event.key)} 关闭出错:`, event.error)
      break
    case 'container:shutdown:start':
      console.log('容器开始关闭')
      break
    case 'container:shutdown:done':
      console.log(`容器关闭完成（${event.durationMs}ms）`)
      break
    case 'container:error':
      console.error('容器级错误:', event.error)
      break
  }
})

// 取消订阅
unsubscribe()
```

完整事件类型：

| 事件 | 触发时机 | 携带数据 |
|------|----------|----------|
| `service:init` | 工厂函数开始执行 | `key` |
| `service:ready` | 初始化成功 | `key`, `durationMs` |
| `service:error` | 初始化失败 | `key`, `error`, `durationMs` |
| `service:shutdown:start` | 开始关闭 | `key` |
| `service:shutdown:done` | 关闭完成 | `key`, `durationMs` |
| `service:shutdown:error` | 关闭出错 | `key`, `error` |
| `container:shutdown:start` | 容器开始关闭 | — |
| `container:shutdown:done` | 容器关闭完成 | `durationMs` |
| `container:error` | 容器级错误（如循环依赖） | `error` |

## ContainerOptions

创建隔离容器时可传入配置：

```typescript
import { Container } from '@hile/core'

const container = new Container({
  startTimeoutMs: 5000,      // 启动超时（ms），超时后 reject
  shutdownTimeoutMs: 3000,   // 关闭超时（ms），超时后跳过该回调
})
```

超时不会强制终止函数执行，只让 Promise reject。

## container.shutdown() —— 优雅关闭

`shutdown()` 按 **LIFO**（后注册先关闭）顺序执行所有服务的清理回调：

```typescript
const http = defineService('http-server', async (shutdown) => {
  const server = createServer()
  shutdown(() => new Promise(r => server.close(r)))
  return server
})

const db = defineService('database', async (shutdown) => {
  const conn = await createConnection()
  shutdown(() => conn.close())
  return conn
})

// db 先注册，http 后注册
// shutdown 时：先关 http（停止接请求），再关 db（释放连接）
await container.shutdown()
```

同一服务内的多个清理回调也按 LIFO 执行：

```typescript
const svc = defineService('my-service', async (shutdown) => {
  shutdown(() => console.log('清理 1'))
  shutdown(() => console.log('清理 2'))
  shutdown(() => console.log('清理 3'))
  return 'ok'
})
await loadService(svc)
await container.shutdown()
// 输出：清理 3 → 清理 2 → 清理 1
```

### 晚注册 Teardown

关闭过程中，如果有服务在 shutdown 开始后才完成初始化并注册 teardown，容器通过 `setImmediate` 让出事件循环来捕获这种情况。

`shutdown()` 可以安全地多次调用。

## formatServiceKey / isService

```typescript
import { formatServiceKey, isService } from '@hile/core'

formatServiceKey('hello')          // 'hello'
formatServiceKey(Symbol('test'))   // 'Symbol(test)'

const props = defineService('test', async (shutdown) => {})
isService(props)  // true
isService({ key: 'x', fn: () => {} })  // false
```

## 隔离容器：new Container()

在测试或多租户场景中，可以创建独立容器：

```typescript
import { Container } from '@hile/core'

const container = new Container({ startTimeoutMs: 5000 })

// 使用方式与全局容器一致
const svc = container.register('my-service', async (shutdown) => 'hello')
const value = await container.resolve(svc)
await container.shutdown()
```

`defineService` 和 `loadService` 是全局容器的快捷函数，等价于 `container.register()` 和 `container.resolve()`。

## 最佳实践

### 1. 用 defineService + loadService 而非直接操作容器

```typescript
// ✅ 推荐
const db = defineService('db', async (shutdown) => { /* ... */ })
const instance = await loadService(db)

// ❌ 不必要
const props = container.register('db', async (shutdown) => { /* ... */ })
const instance = await container.resolve(props)
```

### 2. 在服务工厂内部声明依赖

```typescript
// ✅ 推荐：在工厂函数内部 loadService
const svcA = defineService('a', async (shutdown) => {
  const b = await loadService(svcB)
  return { b }
})

// ❌ 不推荐：在模块顶层 loadService（导致副作用）
const b = await loadService(svcB)
```

### 3. 总是注册清理回调

```typescript
const svc = defineService('my-service', async (shutdown) => {
  const resource = await acquire()
  shutdown(() => resource.release())  // 总是注册清理
  return resource
})
```

### 4. 合理命名 key

- 用 `kebab-case` 字符串：`'http-server'`、`'user-database'`
- 集成包用 `Symbol.for(...)`：`Symbol.for('@hile/typeorm')`

## 反模式

### 1. 在服务间传递容器引用

```typescript
// ❌ 反模式
const svc = defineService('bad', async (shutdown) => {
  return { container }
})

// ✅ 正确：在服务内按需 loadService
const svc = defineService('good', async (shutdown) => {
  const db = await loadService(databaseService)
  return { db }
})
```

### 2. 用同一个 key 注册多个服务

后注册的不会覆盖前注册的结果。第一个被 `loadService` 的优先。

## 完整示例

```typescript
import { defineService, loadService, container } from '@hile/core'

// 1. 配置服务
const config = defineService('config', async (shutdown) => ({
  port: 3000,
  db: { host: 'localhost', port: 5432 },
}))

// 2. 数据库服务（依赖 config）
const database = defineService('database', async (shutdown) => {
  const cfg = await loadService(config)
  console.log('数据库连接已建立')
  shutdown(async () => console.log('数据库连接已关闭'))
  return { id: 'db-conn' }
})

// 3. HTTP 服务（依赖 config 和 database）
const httpServer = defineService('http-server', async (shutdown) => {
  const cfg = await loadService(config)
  const db = await loadService(database)
  console.log(`HTTP 服务器启动在 ${cfg.port}`)
  shutdown(async () => console.log('HTTP 服务器已关闭'))
  return { port: cfg.port }
})

// 4. 启动：只需 load 最上层的服务
await loadService(httpServer)

// 5. 查看依赖图
console.log(container.getDependencyGraph())
// nodes: ['config', 'database', 'http-server']
// edges: database→config, http-server→config, http-server→database

// 6. 优雅关闭
await container.shutdown()
// 输出：HTTP 服务器已关闭 → 数据库连接已关闭
```
