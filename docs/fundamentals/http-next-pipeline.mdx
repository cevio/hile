title: HttpNext 与全栈分流
description: "同一端口下静态资源、API 与 Next.js 页面的请求顺序与约定"
---

**`@hile/http-next`** 将 **Koa + `@hile/http`** 与 **Next.js** 绑定在同一 HTTP Server：先尝试静态与 API，最后交给 Next 做 SSR/RSC。

## 构建与启动时序

```
HttpNext 构造函数
  1. new Http(httpOptions)
  2. koa-static(publicPath)         ← 用户静态资源（可配置，支持多目录）

HttpNext.start()
  3. koa-static(<nextArtifactsDir>/static)   ← Next 静态构建产物
  4. http.load(controllerDirectory, {
       prefix: controllerPrefix,    ← 默认 /-
       suffix: controllerSuffix,    ← 默认 controller
       conflict: "error"
     })
  5. http.load(specialControllers)          ← 额外控制器目录
  6. http.listen(onListen):
     a. 注入 router.routes() 为最后一道 Koa 中间件
     b. 创建 HTTP Server
     c. 调用 onListen(server):
        i.   创建 NextServer({ dev, httpServer, dir: cwd })
        ii.  await app.prepare()
        iii. this.http.use(Next.js handler)  ← 注册为最后一道 Koa 中间件
     d. server.listen(port)
```

最终 Koa 中间件执行顺序：

```
koa-static(publicPath)
    → koa-static(.next/static/)
    → router.routes()（find-my-way）
    → Next.js handler
```

## 请求顺序

```
客户端请求
    │
    ▼
koa-static(publicPath)        ← 配置项，多为 public/，可多目录
    │ 未命中
    ▼
koa-static(<nextArtifactsDir>/static)  ← 默认 .next/static/
    │ 未命中
    ▼
find-my-way 路由匹配          ← 控制器前缀默认 /-
    │ 未匹配（defaultRoute → next()）
    ▼
Next.js handler               ← SSR / RSC / Next 404
```

## 关键配置

- **`controllerPrefix`** — API 路由前缀，默认 **`/-`**（不含通配符），与 `/about` 等页面路由隔离
- **`controllerDirectory`** — 控制器目录名，开发时基于 `src/`，生产基于 `dist/`，默认 **`controllers`**
- **`controllerSuffix`** — 控制器文件后缀，默认 **`controller`**（即 `*.controller.ts`）
- **`publicPath`** — 用户静态资源目录，相对于 `cwd`，支持 `string | string[]`
- **`nextArtifactsDir`** — Next 构建产物目录，默认 `cwd/.next`
- **`specialControllers`** — 额外控制器配置数组 `{ directory: string, prefix: string }[]`，在默认控制器加载后依次 `http.load`

## 模型（Model）

Model 定义与消费由独立包 **`@hile/model`** 提供。**`defineModel`** 用于封装业务逻辑，**`loadModel`** 执行模型并返回结果。

**与 `defineService` 的区别**：Model **无容器 key、不参与容器生命周期、不缓存结果**——每次 `loadModel` 都会重新执行 `main`。适合在 controllers 与 pages 中按需构造数据。

在 `page.tsx` 中使用 `loadModel` 时，须 `export const dynamic = "force-dynamic"` 以保持响应性。

详见 [@hile/model](/packages/model)。

## 关于下一跳

Next handler 作为最后一道 Koa 中间件，通过 **`ctx.respond = false`** 与 **`ctx.status = 200`** 将请求交还给原生 `req`/`res`。handler 在 **`app.prepare()`** 完成后才注册，避免未就绪时接流。

完整构造参数与示例见 [@hile/http-next](/packages/http-next)。
