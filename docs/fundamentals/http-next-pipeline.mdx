## @hile/http-next 解决的问题

`@hile/http-next` 将 API 服务（Koa）和 Next.js SSR 绑定在**同一个端口**上：

```
同一端口 3000：
  /logo.png      → 静态文件（public/）
  /_next/static/* → Next.js 构建产物
  /-/users       → API 控制器（JSON）
  /about         → Next.js 页面（SSR HTML）
```

## 与 @hile/http 的关系

`HttpNext` 内部创建了一个 `Http` 实例，在它之上添加 Next.js 集成：

| 特性 | @hile/http | @hile/http-next |
|------|------------|-----------------|
| API 路由 | 支持 | 支持 |
| 中间件 | `http.use()` | `app.use()`（转发给内部 Http） |
| 文件路由 | `http.load()` 手动调用 | `start()` 时自动加载 |
| 静态文件 | 手动配置 | 内置 koa-static |
| Next.js | 不支持 | 完整集成 |
| 启动方式 | `http.listen()` | `app.start()` |

## HttpNext 类

### 构造参数

```typescript
import HttpNext from '@hile/http-next'

const app = new HttpNext({
  // ---- 继承自 HttpProps ----
  port: 3000,
  keys: ['my-cookie-key'],

  // ---- HttpNext 新增 ----
  cwd: '/path/to/project',          // 项目根目录，默认 process.cwd()
  publicPath: 'public',              // 静态资源目录（支持数组）
  controllerDirectory: 'controllers', // 控制器目录名，默认 'controllers'
  controllerPrefix: '/-',            // API 路由前缀，默认 '/-'
  controllerSuffix: 'controller',    // 控制器文件后缀，默认 'controller'
  specialControllers: [              // 额外控制器
    { directory: 'admin/controllers', prefix: '/admin' },
  ],
  nextArtifactsDir: '.next',        // Next.js 构建产物目录
})
```

### 选项详解

**`cwd`**：项目根目录。所有相对路径基于此。默认 `process.cwd()`。

**`controllerDirectory` + `controllerPrefix`**：控制器目录和路由前缀。

- 开发时目录：`{cwd}/src/{controllerDirectory}/`
- 生产时目录：`{cwd}/dist/{controllerDirectory}/`
- 路由前缀默认 `/-`

**`controllerSuffix`**：控制器文件后缀（不含扩展名）。默认 `controller`，匹配 `*.controller.{ts,js,tsx,jsx}`。

**`publicPath`**：静态资源目录，相对于 `cwd`。支持单目录或数组：

```typescript
new HttpNext({ port: 3000, publicPath: ['public', 'uploads'] })
```

**`specialControllers`**：额外的控制器目录，使用独立前缀：

```typescript
new HttpNext({
  port: 3000,
  specialControllers: [
    { directory: 'admin/controllers', prefix: '/admin' },
  ],
})
// src/admin/controllers/dashboard.controller.ts → /admin/dashboard
```

### 方法

**`use(middleware)`**：注册 Koa 中间件（转发给内部 Http 实例），返回 this。

**`load(directory)`**：手动加载控制器目录：

```typescript
app.load('./extra-controllers')
```

**`start(onListen?)`**：启动服务。返回关闭函数。

## 4 层中间件链

`start()` 完成后的中间件顺序：

```
第 1 层：koa-static(publicPath/)     ← 用户静态文件
第 2 层：koa-static(.next/static/)   ← Next.js 构建产物
第 3 层：router.routes()            ← API 控制器（find-my-way）
第 4 层：Next.js handler            ← SSR / SSG / RSC（兜底）
```

请求处理流程：

```
请求到达
  → 1. public/ 有文件？ → 返回文件
  → 2. .next/static/ 有文件？ → 返回文件
  → 3. find-my-way 匹配到控制器？ → 执行控制器 → 响应
  → 4. 交给 Next.js → SSR / 404
```

Next.js handler 放在最后，确保静态文件和 API 路由优先处理。

## start 方法完整流程

```
app.start()
  → 1. http.use(koaStatic('.next/static'))
  → 2. http.load(controllerDirectory, { prefix: '/-', ... })
  → 3. 依次 load specialControllers
  → 4. http.listen(async (server) => {
       → onListen 回调（如果提供）
       → NextServer({ dev, httpServer, dir })
       → app.prepare()
       → http.use(forwardToNextMiddleware(handler))
     })
  → 返回 stop 函数
```

关键实现细节：

- `forwardToNextMiddleware` 设置 `ctx.respond = false`，让 Koa 不处理响应
- 设置 `ctx.status = 200`（Koa 默认 404）
- 将 `ctx.req`/`ctx.res` 直接交给 Next.js

## 开发模式 vs 生产模式

通过 `NODE_ENV` 自动切换：

| 特性 | development | production |
|------|-------------|------------|
| 控制器目录 | `src/controllers/` | `dist/controllers/` |
| Next.js | `dev: true`（HMR） | `dev: false` |
| 启动方式 | tsx 实时编译 | 预先编译的 JS |

```bash
# 开发
hile start --dev

# 生产
hile start
```

## 控制器目录约定

```
src/controllers/
├── index.controller.ts              → /-/
├── users.controller.ts              → /-/users
├── users/
│   ├── index.controller.ts          → /-/users
│   ├── [id].controller.ts           → /-/users/:id
│   └── [id]/posts.controller.ts     → /-/users/:id/posts
```

## 完整示例

### 项目结构

```
my-app/
├── package.json
├── tsconfig.json
├── src/
│   ├── controllers/
│   │   └── users.controller.ts
│   ├── pages/              ← Next.js 页面
│   │   └── index.tsx
│   └── services/
│       └── index.boot.ts
└── public/
    └── logo.png
```

### 启动文件

```typescript
// src/services/index.boot.ts
import HttpNext from '@hile/http-next'
import { defineService } from '@hile/core'

export default defineService('http-next', async (shutdown) => {
  const app = new HttpNext({
    port: 3000,
    publicPath: 'public',
    controllerPrefix: '/-',
  })

  app.use(async (ctx, next) => {
    const start = Date.now()
    await next()
    console.log(`${ctx.status} ${ctx.method} ${ctx.url} - ${Date.now() - start}ms`)
  })

  const stop = await app.start()
  shutdown(stop)
  return app
})
```

### 请求处理

```
GET /logo.png     → public/logo.png（200）
GET /-/users      → API 控制器返回 JSON（200）
GET /             → Next.js 首页渲染（200）
GET /nonexistent  → Next.js 404
```

  <Accordion title="为什么 Next.js handler 放在最后？">
