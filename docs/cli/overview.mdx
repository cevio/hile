## 概述

Hile 的命令行工具分为两类：

1. **`hile`** —— 运行时 CLI（`@hile/cli`），用于启动服务、管理注册中心
2. **`create-hile`** —— 项目脚手架，用于快速生成项目模板

## hile start —— 启动服务

### 基本用法

```bash
# 开发模式
hile start --dev

# 生产模式
hile start

# 指定包名或路径启动
hile start my-app-package
hile start ./path/to/my-app
```

### 选项

| 选项 | 简写 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--dev` | `-d` | boolean | `false` | 开发模式 |
| `--silent` | `-s` | boolean | `false` | 静默模式 |
| `--env-file` | `-e` | string[] | `[]` | 加载 env 文件，可多次指定 |

#### --dev（开发模式）

开发模式下 CLI 会：

1. 设置 `NODE_ENV=development`
2. 使用 `tsx` 的 `tsImport` 实时编译 TypeScript
3. 扫描 `src/` 目录下的 `**/*.boot.{ts,js}` 文件
4. 自动订阅容器事件并输出彩色日志

```bash
hile start --dev -e .env
```

输出示例：

```
[hile] service(http-server) init
[hile] service(http-server) ready (15ms)
```

#### --silent（静默模式）

抑制容器事件日志（开发模式下依然生效）：

```bash
hile start --dev --silent
```

#### --env-file（环境变量文件）

使用 Node.js 原生 `process.loadEnvFile()` 加载。可多次指定，**先加载的优先**（已存在的 key 不被覆盖）：

```bash
hile start --dev -e .env -e .env.local
```

### start 的完整执行流程

```
hile start --dev -e .env
  → 1. 加载 --env-file 文件（process.loadEnvFile）
  → 2. 设置 NODE_ENV（dev → development, 否则 production）
  → 3. 开发且非 silent → container.on(logContainerEvent)
  → 4. 读取 package.json 中的 hile.auto_load_packages
  → 5. 扫描 boot 文件（dev → src/**/*.boot.{ts,js}, prod → dist/**/*.boot.{ts,js}）
  → 6. 并行加载所有 auto_load_packages 和 boot 文件
       → auto_load_packages: import(包名) → loadService(mod.default)
       → boot 文件: import(文件) → loadService(mod.default)
  → 7. 注册退出钩子（async-exit-hook → container.shutdown()）
```

### name 参数

`hile start [name]` 查找逻辑：

1. 如果是文件路径且存在 → 使用
2. 当前 `node_modules` 中查找
3. CLI 自身 `node_modules` 中查找
4. 全局 `npm root -g` 中查找

## 自动扫描 .boot 文件

CLI 自动扫描 `*.boot.{ts,js}` 文件：

- **开发模式**：`src/**/*.boot.{ts,js}`
- **生产模式**：`dist/**/*.boot.{ts,js}`

每个 boot 文件必须 `export default` 一个 `defineService(...)` 的返回值。

boot 文件可以放在 `src/` 下的任何位置：

```
src/
├── services/
│   ├── http.boot.ts
│   └── database.boot.ts
└── app/
    └── boot.ts
```

## auto_load_packages

在 `package.json` 中配置：

```json
{
  "hile": {
    "auto_load_packages": ["@hile/typeorm", "@hile/ioredis"]
  }
}
```

CLI 对数组中每个包执行：`import(pkgName)` → `loadService(mod.default)`。

支持的包（default export 是 `defineService(...)` 返回值）：
- `@hile/typeorm`
- `@hile/ioredis`
- `@hile/logger`

## hile registry —— 注册中心

```bash
# 默认配置启动
hile registry

# 指定端口和地址
hile registry --port 9876 --host 127.0.0.1
```

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--port` | number | `9876`（或 `REGISTRY_PORT` 环境变量） | 监听端口 |
| `--host` | string | `127.0.0.1` | 宣告地址 |

启动后自动创建 `~/.registry/` 工作目录，监听 `~/.registry/configs/` 下的 YAML 配置文件。

## hile registry configs —— 配置管理

### 查看配置列表

```bash
hile registry configs
```

### 获取配置

```bash
# YAML 格式（默认）
hile registry configs get my-service

# JSON 格式
hile registry configs get my-service --json
```

### 设置配置

```bash
hile registry configs set my-service port=8080
hile registry configs set my-service debug=true
hile registry configs set my-service whitelist='["10.0.0.1","10.0.0.2"]'
```

值的类型自动推断：

| 输入 | 推断类型 |
|------|----------|
| `8080`、`3.14` | number |
| `true`、`false` | boolean |
| `null` | null |
| `hello` | string |
| `{...}` 或 `[...]` 开头 | JSON.parse |

### 删除配置

```bash
hile registry configs del my-service port
hile registry configs del my-service        # 删除整个 namespace
hile registry configs del my-service -y     # 跳过确认
```

## create-hile —— 项目脚手架

```bash
npx create-hile create my-project
npx create-hile create my-project --skip-install
```

### 内置 6 种模板

| 模板 | 说明 |
|------|------|
| `default` | 纯 HTTP API 服务 |
| `next` | Next.js 全栈应用 |
| `micro-http` | 微服务 + HTTP API |
| `micro` | 纯微服务 |
| `micro-http-next` | 全栈微服务 |
| `monorepo` | 多包仓库（Lerna + pnpm workspace） |

## 完整启动流程

结合所有知识点，`hile start --dev -e .env` 的完整流程：

1. 解析命令行参数
2. `process.loadEnvFile('.env')` 加载环境变量
3. 设置 `NODE_ENV='development'`
4. 订阅容器事件（`container.on(logContainerEvent)`）
5. 读取 `package.json` 的 `hile.auto_load_packages`
6. 扫描 `src/**/*.boot.{ts,js}`
7. 并行 `loadService` 所有包和 boot 文件
8. 容器自动解析服务依赖
9. 注册退出钩子
10. 服务就绪，等待请求
11. Ctrl+C → `container.shutdown()` → 进程退出

## 常见问题

<AccordionGroup>
  <Accordion title="hile start 和 node app.js 有什么区别？">
    `hile start` 封装了自动扫描 boot 文件、自动加载集成包、自动管理容器生命周期和优雅关闭。`node app.js` 需要手动处理所有。
  </Accordion>
  <Accordion title="--dev 和手动设 NODE_ENV 有什么区别？">
    `--dev` 做了三件事：设置 `NODE_ENV=development`、使用 tsx 实时编译、打印容器事件日志。手动设环境变量只能实现第一部分。
  </Accordion>
  <Accordion title="生产环境如何启动？">
    ```bash
    tsc -b                    # 先编译
    hile start -e .env.prod   # 生产模式启动
    ```
  </Accordion>
</AccordionGroup>
