# 什么是 Hile？

Hile 是一套面向 Node.js 的**轻量级服务化工具集**。它的核心理念是：用最简单的 API 管理复杂的服务依赖关系，让你专注于业务逻辑而不是基础设施。

Hile 提供**服务容器**、**HTTP / Next 集成**、**数据库与缓存**以及**消息传输**等模块化能力。其中 **`@hile/core` 系**（如 `cli`、`http`、`typeorm`）通过同一套服务容器协作生命周期；**消息类包**（`message-modem`、`message-ws`、`message-loader`、`micro` 等）可脱离容器独立使用，也可在 boot 中自行接入。

## 依赖关系

以下是各包之间的依赖关系。箭头方向表示"依赖于"：

```
@hile/core          ← 所有包的基础
  ├── @hile/cli     ← 启动器，依赖核心容器
  ├── @hile/typeorm  ← 数据库集成，依赖核心容器
  └── @hile/ioredis  ← Redis 集成，依赖核心容器

@hile/http          ← HTTP 框架
  └── @hile/http-next ← Next.js 桥接层，依赖 HTTP 框架

@hile/message-modem ← 消息通信抽象层（独立，无外部依赖）
  ├── @hile/message-ipc ← Node.js IPC 实现，依赖 message-modem
  ├── @hile/message-worker-thread ← Worker Threads 实现，依赖 message-modem
  └── @hile/message-ws ← WebSocket 实现，依赖 message-modem + ws

@hile/message-loader ← 文件系统消息路由（独立，可搭配各 message 实现）

@hile/micro ← 轻量服务发现（依赖 message-loader + message-ws + ws）

create-hile ← 脚手架工具
  └── 生成的项目依赖所选模板（default / next / micro-http / micro / micro-http-next 等）
```

## 典型技术栈组合

根据你的项目类型，选择不同的包组合：

<AccordionGroup>
  <Accordion title="消息 / WS 服务发现">
    ```bash
    pnpm add @hile/message-loader @hile/message-ws @hile/micro
    ```
    适合：多进程之间用 WebSocket 做请求/响应，并需要 **Registry** 按 namespace 发现实例。细节见 [@hile/message-loader](/packages/message-loader) 与 [@hile/micro](/packages/micro)。
  </Accordion>
  <Accordion title="纯 API 服务">
    ```bash
    pnpm add @hile/core @hile/http @hile/cli
    ```
    适合：REST API、微服务后端。使用 `@hile/http` 的文件系统路由和中间件能力。
  </Accordion>
  <Accordion title="全栈应用（API + SSR）">
    ```bash
    npx create-hile create my-app
    ```
    创建时在 CLI 中选择 **`next`** 或 **`micro-http-next`** 等含 Next.js 的模板，即可得到 Koa API 路由与 Next.js 页面共享同一端口的典型全栈应用。若选 **`default`** 等模板，则无 Next.js，请以生成项目说明为准。
  </Accordion>
  <Accordion title="API + 数据库 + 缓存">
    ```bash
    pnpm add @hile/core @hile/http @hile/cli @hile/typeorm @hile/ioredis
    ```
    适合：需要数据库和 Redis 的后端服务。所有资源通过容器统一管理生命周期。
  </Accordion>
</AccordionGroup>

## 设计哲学

1. **服务即单例（按 key）**：通过 `defineService(key, fn)` 定义的服务由容器按 **服务 key** 保证全局唯一，并发加载自动合并
2. **约定优于配置**：文件系统路由、`*.boot.ts` 自动加载、环境变量配置，减少样板代码
3. **优雅关闭**：每个服务注册清理回调，进程退出时容器按逆序执行，确保资源正确释放
4. **可观测性**：容器事件流覆盖服务全生命周期，CLI 自动订阅并输出日志
5. **渐进式采用**：可以只用 `@hile/core`，也可以组合所有包构建完整应用
