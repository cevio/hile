```bash
pnpm add @hile/core
```

<Note>纯 TypeScript 实现，零运行时依赖。</Note>

## 核心概念

`@hile/core` 提供一个**异步服务容器**，负责管理服务的注册、加载、缓存和销毁。默认容器挂在 `globalThis.HILE_GLOBAL_CONTAINER` 上，同一进程内各模块共享。它解决的核心问题是：

1. **全局单例（按 key）** — 同一 **服务 key** 无论在哪里加载，返回同一个实例；不同 key 彼此独立
2. **并发安全** — 多处同时加载同一服务时，只初始化一次
3. **资源管理** — 每个服务注册清理回调，进程退出时统一销毁
4. **依赖追踪** — 自动构建服务间依赖图，检测循环依赖

## 使用指南

### 第一步：定义服务

使用 `defineService` 将一个异步函数注册为服务。函数接收 `shutdown` 参数，用于注册资源清理回调。

```typescript
import { defineService } from '@hile/core'

export const databaseService = defineService('database', async (shutdown) => {
  // 创建资源
  const pool = await createPool({
    host: 'localhost',
    port: 5432,
    database: 'myapp',
  })

  // 注册清理回调 — 进程退出时会自动调用
  shutdown(() => pool.end())

  // 返回服务实例
  return pool
})
```

`defineService` 做了什么：

1. 使用你传入的 **服务 key**（`string` 或 `symbol`）在容器内标识该服务槽位；同一 key 多次 `defineService`/`register` 指向同一单例槽（可更新工厂函数）
2. 将服务函数注册到默认容器
3. 返回一个 `ServiceRegisterProps` 对象（包含 `key`、`fn`、`flag`）
4. **此时服务函数并未执行**，只有 `loadService` 时才会执行

集成包常用 `Symbol.for('包名')` 作为 key，避免与用户字符串冲突；应用内可用 `'http'`、`'database'` 等可读字符串。

### 第二步：加载服务

使用 `loadService` 获取服务实例。容器保证同一服务只执行一次。

```typescript
import { loadService } from '@hile/core'
import { databaseService } from './services/database'

// 第一次调用：执行服务函数，创建连接池
const db = await loadService(databaseService)

// 第二次调用：直接返回缓存的连接池（同一个引用）
const db2 = await loadService(databaseService)

console.log(db === db2) // true
```

### 第三步：并发请求合并

当多处代码同时 `loadService` 同一个服务时，容器只执行一次初始化，所有调用方共享结果：

```typescript
// 三个并发请求同时到达，都需要数据库连接
const [r1, r2, r3] = await Promise.all([
  loadService(databaseService),
  loadService(databaseService),
  loadService(databaseService),
])

// 服务函数只执行了一次
// r1 === r2 === r3
```

内部机制：
1. 第一个 `loadService` 发现服务未初始化，开始执行服务函数，状态设为 `运行中(0)`
2. 后续的 `loadService` 发现服务正在初始化，加入等待队列
3. 服务函数执行完成后，状态设为 `已成功(1)`，通知所有等待者

### 第四步：服务间依赖

服务内部可以通过 `loadService` 加载其他服务，容器会自动追踪依赖关系：

```typescript
import { defineService, loadService } from '@hile/core'
import { databaseService } from './database'
import { cacheService } from './cache'

export const userService = defineService('user', async (shutdown) => {
  // 加载依赖的服务 — 容器自动记录 userService → databaseService
  const db = await loadService(databaseService)
  // 容器自动记录 userService → cacheService
  const cache = await loadService(cacheService)

  return {
    async getById(id: number) {
      // 先查缓存
      const cached = await cache.get(`user:${id}`)
      if (cached) return JSON.parse(cached)

      // 缓存未命中，查数据库
      const user = await db.query('SELECT * FROM users WHERE id = $1', [id])
      await cache.set(`user:${id}`, JSON.stringify(user), 'EX', 300)
      return user
    },

    async create(data: { name: string; email: string }) {
      const result = await db.query(
        'INSERT INTO users (name, email) VALUES ($1, $2) RETURNING *',
        [data.name, data.email]
      )
      return result[0]
    }
  }
})
```

### 第五步：资源销毁（Shutdown）

每个服务通过 `shutdown(fn)` 注册清理回调。当容器关闭或服务初始化失败时，这些回调会被执行。

```typescript
export const connectionService = defineService('connection', async (shutdown) => {
  const primary = await connectPrimary()
  shutdown(() => primary.disconnect())

  const replica = await connectReplica()
  shutdown(() => replica.disconnect())

  const cache = await initCache()
  shutdown(() => cache.flush())

  return { primary, replica, cache }
})
```

Shutdown 回调的规则：

| 规则 | 说明 |
|------|------|
| 全部执行 | `container.shutdown()` 会循环执行 shutdown 队列，每次让出事件循环以捕获关闭期间新注册的回调，直到队列清空 |
| LIFO 顺序 | 后注册的回调先执行。上例中执行顺序：`cache.flush()` → `replica.disconnect()` → `primary.disconnect()` |
| 支持异步 | 回调可以是 `async` 函数，容器会 `await` 每个回调 |
| 去重 | 同一个函数引用多次注册只执行一次 |
| 错误隔离 | 某个回调抛错不会阻止其他回调执行 |
| 失败路径 | 即使服务初始化失败，已注册的回调仍会执行 |

## 高级功能

### 隔离容器

除了默认容器（`defineService`/`loadService` 使用的），你可以创建独立容器实现作用域隔离：

```typescript
import { Container } from '@hile/core'

const testContainer = new Container({
  startTimeoutMs: 2_000,
  shutdownTimeoutMs: 1_000,
})

// 在隔离容器中注册和加载服务
const service = testContainer.register('test', async (shutdown) => {
  const conn = await createConnection()
  shutdown(() => conn.close())
  return conn
})

const result = await testContainer.resolve(service)

// 独立关闭，不影响默认容器
await testContainer.shutdown()
```

适用场景：
- 单元测试中创建独立容器，测试结束后销毁
- 多租户场景下为每个租户创建独立容器

### 超时控制

```typescript
const container = new Container({
  startTimeoutMs: 5_000,    // 服务启动超时
  shutdownTimeoutMs: 3_000, // shutdown 回调超时
})
```

超时后会抛出类似 `service startup timeout: <key> exceeded 5000ms` 的错误（`<key>` 为 `formatServiceKey(key)` 的文本），进入错误处理流程（执行已注册的 shutdown 回调）。

### 事件订阅

```typescript
import container, { formatServiceKey } from '@hile/core'

const off = container.on((event) => {
  switch (event.type) {
    case 'service:init':
      console.log(`[init] 服务 ${formatServiceKey(event.key)} 开始初始化`)
      break
    case 'service:ready':
      console.log(`[ready] 服务 ${formatServiceKey(event.key)} 就绪，耗时 ${event.durationMs}ms`)
      break
    case 'service:error':
      console.error(`[error] 服务 ${formatServiceKey(event.key)} 失败 (${event.durationMs}ms):`, event.error)
      break
    case 'service:shutdown:start':
      console.log(`[shutdown] 服务 ${formatServiceKey(event.key)} 开始关闭`)
      break
    case 'service:shutdown:done':
      console.log(`[shutdown] 服务 ${formatServiceKey(event.key)} 已关闭 (${event.durationMs}ms)`)
      break
    case 'service:shutdown:error':
      console.error(`[shutdown] 服务 ${formatServiceKey(event.key)} 关闭失败:`, event.error)
      break
    case 'container:shutdown:start':
      console.log('[container] 容器开始关闭')
      break
    case 'container:shutdown:done':
      console.log(`[container] 容器关闭完成 (${event.durationMs}ms)`)
      break
    case 'container:error':
      console.error('[container] 容器错误:', event.error)
      break
  }
})

// 取消订阅
off()
// 或者
container.off(listener)
```

### 依赖图查询

```typescript
// 获取完整依赖图
const graph = container.getDependencyGraph()
console.log(graph.nodes)  // 所有已注册服务的 key（按首次 register 的序号排序）
console.log(graph.edges)  // [{ from: 'a', to: 'b' }, ...] — 依赖边（from/to 均为 ServiceKey）

// 获取启动顺序（按首次 resolve 启动的顺序）
const order = container.getStartupOrder()
console.log(order)  // 例如 ['database', 'cache', 'user']
```

### 服务校验

```typescript
import { defineService, isService } from '@hile/core'

const myService = defineService('demo', async () => 'hello')

isService(myService) // true
isService({ key: 'x', fn: () => {} } as any) // false — 缺少内部 flag
isService(null) // false
```

`isService` 检查：`flag` 为内部标记、`fn` 为函数、`key` 为 `string` 或 `symbol`。

### 手动关闭

```typescript
import container from '@hile/core'

// 在不使用 CLI 时，手动处理进程退出
process.on('SIGTERM', async () => {
  await container.shutdown()  // 执行所有已注册的 teardown（含晚注册的）
  process.exit(0)
})
```

<Note>shutdown() 会循环处理队列直到清空，每轮通过 setImmediate 让出事件循环，确保关闭过程中新注册的 teardown 也会被执行。</Note>

## API 参考

### 顶层导出

| 导出 | 类型 | 说明 |
|------|------|------|
| `container` | `Container` | 默认容器实例（也是 default export），进程内单例 |
| `defineService(key, fn)` | `function` | 向默认容器注册服务，返回 `ServiceRegisterProps` |
| `loadService(props)` | `function` | 从默认容器加载服务，返回 `Promise<R>` |
| `isService(props)` | `function` | 校验对象是否为合法服务注册信息 |
| `formatServiceKey(key)` | `function` | 将 `ServiceKey` 格式化为可读字符串（日志用） |
| `Container` | `class` | 容器类，用于创建隔离容器 |

### Container 实例方法

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `register(key, fn)` | `ServiceRegisterProps<R>` | 注册服务（同一 key 共享槽位） |
| `resolve(props)` | `Promise<R>` | 加载服务 |
| `shutdown()` | `Promise<void>` | 关闭所有服务，执行清理回调 |
| `on(listener)` | `() => void` | 订阅事件，返回取消订阅函数 |
| `off(listener)` | `void` | 取消订阅 |
| `getLifecycle(key)` | `ServiceLifecycleStage \| undefined` | 按服务 key 获取当前生命周期阶段 |
| `getDependencyGraph()` | `{ nodes, edges }` | `nodes` 为 `ServiceKey[]`，`edges` 为 `{ from, to }` |
| `getStartupOrder()` | `ServiceKey[]` | 获取服务启动顺序（首次启动顺序） |
| `hasService(key)` | `boolean` | 是否已对该 key 执行过 `register` |
| `hasMeta(key)` | `boolean` | 该 key 是否已有运行时元数据（已触发过 resolve） |
| `getMetaByKey(key)` | `object \| undefined` | 按 key 获取运行时元数据（status, lifecycle, value, error 等） |

### ContainerOptions

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `startTimeoutMs` | `number` | 无限制 | 单个服务启动超时（毫秒） |
| `shutdownTimeoutMs` | `number` | 无限制 | 单个 shutdown 回调超时（毫秒） |

### 服务状态

| 状态 | 内部值 | `resolve()` 行为 |
|------|--------|-----------------|
| 未运行 | — | 执行服务函数 |
| 运行中 | `0` | 加入等待队列 |
| 已成功 | `1` | 直接返回缓存值 |
| 已失败 | `-1` | 直接返回缓存错误 |

### 类型定义

```typescript
type ServiceKey = string | symbol;
type ServiceCutDownFunction = () => unknown | Promise<unknown>;
type ServiceCutDownHandler = (fn: ServiceCutDownFunction) => void;
type ServiceFunction<R> = (fn: ServiceCutDownHandler) => R | Promise<R>;
type ServiceLifecycleStage = 'init' | 'ready' | 'stopping' | 'stopped';

interface ServiceRegisterProps<R> {
  key: ServiceKey;
  fn: ServiceFunction<R>;
  flag: symbol; // 内部标记，勿手造
}

interface ContainerOptions {
  startTimeoutMs?: number;
  shutdownTimeoutMs?: number;
}

type ContainerEvent =
  | { type: 'service:init'; key: ServiceKey }
  | { type: 'service:ready'; key: ServiceKey; durationMs: number }
  | { type: 'service:error'; key: ServiceKey; error: any; durationMs: number }
  | { type: 'service:shutdown:start'; key: ServiceKey }
  | { type: 'service:shutdown:done'; key: ServiceKey; durationMs: number }
  | { type: 'service:shutdown:error'; key: ServiceKey; error: any }
  | { type: 'container:shutdown:start' }
  | { type: 'container:shutdown:done'; durationMs: number }
  | { type: 'container:error'; error: any };
```

## 常见错误与排查

<AccordionGroup>
  <Accordion title="circular dependency detected: X -> Y">
    服务 X 依赖服务 Y，而 Y 又直接或间接依赖 X。解决方案：
    - 拆分服务职责，将共同依赖提取为独立服务
    - 引入中间层服务，打破循环
  </Accordion>
  <Accordion title="service startup timeout: X exceeded Yms">
    服务 X 的初始化耗时超过了 `startTimeoutMs`。排查：
    - 检查服务函数内的异步操作是否有死锁或无限等待
    - 适当增加 `startTimeoutMs` 的值
    - 检查网络连接（数据库、Redis 等是否可达）
  </Accordion>
</AccordionGroup>

## 反模式

<Warning>以下用法会导致问题，请避免使用。</Warning>

### 模块顶层缓存实例

```typescript
// ❌ 错误：模块加载时就执行 loadService，可能在容器就绪前
const db = await loadService(dbService)

export function query(sql: string) {
  return db.query(sql)
}

// ✅ 正确：在需要时加载
export async function query(sql: string) {
  const db = await loadService(dbService)
  return db.query(sql)
}
```

### 手动伪造服务对象

```typescript
// ❌ 错误：绕过容器，isService 校验会失败
const fake = { key: 'x', fn: async () => 1 } as any

// ✅ 正确：通过 defineService 创建
const real = defineService('real', async () => 1)
```

### 不注册资源清理

```typescript
// ❌ 错误：连接池永远不会被关闭
export const bad = defineService('bad', async () => {
  return await createPool()
})

// ✅ 正确：注册 shutdown 回调
export const good = defineService('good', async (shutdown) => {
  const pool = await createPool()
  shutdown(() => pool.end())
  return pool
})
```
