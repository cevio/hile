## 概述

`@hile/micro-dynamic-configs` 提供**配置服务端**组件 `MicroDynamicConfigsServer`，基于 `@hile/micro` 的发布/订阅机制实现动态配置管理：

- 使用 Zod schema 定义配置结构
- 配置持久化到 Redis
- 每次配置变更通过 `@hile/micro` 主题推送发布到订阅方

### 架构

```
Publisher                  MicroDynamicConfigsServer
    │                              │
    │    save({ key: val })        │
    ├────────────────────────────► │
    │                              │── 校验 & 对比变更
    │                              │── redis.set (持久化全量)
    │                              │── update 主题值 (推送)
    │                              │── emit change:key 事件
```

- **Config Server** 为每个 schema 字段注册一个 `{namespace}:{key}` 主题
- 订阅方通过 `@hile/micro` 的 `Application.subscribe()` 接收变更推送
- 配置变更时，服务端通过 `app.publish()` 返回的 publisher 推送新值

## 快速开始

### 配置服务端

```typescript
import { Application } from '@hile/micro';
import { MicroDynamicConfigsServer } from '@hile/micro-dynamic-configs';
import { Redis } from 'ioredis';
import { z } from 'zod';

const app = new Application({
  namespace: 'config-svc',
  registry: { host: '127.0.0.1', port: 9000 },
});
await app.listen(9100);

const redis = new Redis({ host: '127.0.0.1', port: 6379 });

const server = new MicroDynamicConfigsServer({
  app,
  redis,
  schema: z.object({
    featureX: z.boolean().default(false),
    maxRetries: z.number().default(3),
  }),
  redis_key: 'config:my-service',
});

const teardown = await server.initialize();
// 服务端就绪，等待订阅和写入
```

### 修改配置

```typescript
// 通过 save() 写入变更
const updatedCount = await server.save({
  featureX: true,
  maxRetries: 5,
});
// Redis 持久化 → 推送 change 事件 → 订阅方获取更新
```

### 订阅配置变更

```typescript
// 在订阅方应用中使用 @hile/micro 的 Application.subscribe()
await app.subscribe('config-svc:featureX', (value) => {
  console.log('featureX 变更为:', value);
});
```

## 核心功能

### 初始化流程

`initialize()` 执行以下操作：

1. 检查 Redis 中是否存在 `redis_key`，若存在则加载并解析
2. 使用 schema 解析初始值（Redis 数据或 schema 默认值）
3. 为 schema 中每个字段调用 `app.publish(namespace:key, value)` 注册主题
4. 返回 teardown 函数，用于清理所有 publisher 和事件监听器

### 配置写入流程

`save()` 执行两阶段处理：

1. **第一轮（校验 & 对比）**：逐个字段用 Zod schema 校验输入值，与当前值做 deep diff，收集有变更的条目
2. **第二轮（持久化 & 推送）**：构建全量新快照 → `redis.set` 持久化 → 更新内存 → 逐个字段调用 publisher 推送新值，同时 `emit('change:' + key, newValue, oldValue)`

未变化的字段跳过写入和推送。校验失败的字段抛出错误，不污染当前配置。

### 断连与清理

| 场景 | 处理 |
|------|------|
| 主动清理 | `initialize()` 返回的 teardown 函数 unpublish 所有主题并清除事件监听器 |

## API 参考

### MicroDynamicConfigsServer

```typescript
class MicroDynamicConfigsServer<
  T extends Application,
  Z extends ZodObject<ZodRawShape>
> extends EventEmitter

// 构造
constructor(options: {
  app: T
  redis: Redis
  schema: Z
  redis_key: string
})

// 初始化：从 Redis 加载数据，注册主题，返回 teardown 函数
initialize(): Promise<() => void>

// 持久化配置并推送变更，返回实际变更的字段数
save(value: Partial<z.infer<Z>>): Promise<number>

// 当前配置快照（只读）
get value(): z.infer<Z>
```

### 事件

`MicroDynamicConfigsServer` 继承 `EventEmitter`，配置变更时触发 `change:{fieldName}` 事件：

```typescript
server.on('change:featureX', (newValue, oldValue) => {
  console.log('featureX:', oldValue, '->', newValue);
});
```

## 最佳实践

### schema 设计

构造 `MicroDynamicConfigsServer` 时会执行 `schema.parse({})`，因此必须确保所有字段有默认值或为 optional：

```typescript
// ✓ 正确：字段都有默认值
z.object({
  host: z.string().default('localhost'),
  port: z.number().default(8080),
})

// ✗ 可能失败：必填字段无默认值
z.object({
  host: z.string(),  // parse({}) 时报错
})
```
