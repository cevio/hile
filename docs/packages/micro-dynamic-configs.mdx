## 概述

`@hile/micro-dynamic-configs` 是基于 `@hile/micro` WebSocket 通信的动态配置服务。提供**配置服务端**组件：

| 角色 | 组件 | 职责 |
|------|------|------|
| **Config Server** | `MicroDynamicConfigsServer` | 持有配置数据，管理订阅者列表，推送变更 |
| **Publisher** | 直接调用 `server.save()` | 修改配置，触发持久化和推送 |

### 架构

```
Publisher                 Config Server
    │                            │
    │    save({ key: val })      │
    ├──────────────────────────► │
    │                            │── redis.set (持久化)
    │                            │── emit change (推送)
    │                            │
```

- **Config Server** 通过 WebSocket 主题推送变更、持久化到 Redis
- 订阅方通过 `@hile/micro` 的 `Application` 直连 Config Server，使用 `app.subscribe()` 接收变更推送
- 使用 `@hile/micro` 的 `Application` 做服务发现和通信，独立包，仅需 Redis

## 快速开始

### 配置服务端

```typescript
import { Application } from '@hile/micro';
import { MicroDynamicConfigsServer } from '@hile/micro-dynamic-configs';
import { Redis } from 'ioredis';
import { z } from 'zod';

const app = new Application({
  namespace: 'config-svc',
  registry: { host: '127.0.0.1', port: 9000 },
});
await app.listen(9100);

const redis = new Redis({ host: '127.0.0.1', port: 6379 });

const server = new MicroDynamicConfigsServer({
  app,
  redis,
  schema: z.object({
    featureX: z.boolean().default(false),
    maxRetries: z.number().default(3),
    db: z.object({
      host: z.string().default('localhost'),
      port: z.number().default(3306),
    }).default({ host: 'localhost', port: 3306 }),
  }),
  redis_key: 'config:my-service',
});

const teardown = await server.initialize();
// 服务端就绪，等待订阅和写入
```

### 修改配置

```typescript
// 发布者通过 save() 写入变更
const updated = await server.save({
  featureX: true,
  maxRetries: 5,
});
// Redis 持久化 → 推送 change 事件 → 订阅者缓存更新
```

## 核心功能

### 实时推送

服务端 `save()` 写入数据时的处理流程：

1. **第一轮（validate & diff）**：逐个字段校验 schema，对比新旧值，收集变更条目
2. **第二轮（apply）**：构建全量快照 → `redis.set` 持久化 → 更新内存 → 逐个字段 `emit('change:key', newValue, oldValue)`
3. 每个字段的 `change:key` 事件通过 `app.publish()` 推送变更到订阅方

### 断连与清理

| 场景 | 处理 |
|------|------|
| Server 端主动关闭 | `initialize()` 返回的 teardown 清理所有 publisher 和监听器 |

## API 参考

### MicroDynamicConfigsServer

```typescript
class MicroDynamicConfigsServer<
  T extends Application,
  Z extends ZodObject<ZodRawShape>
> extends EventEmitter

// 构造
constructor(options: {
  app: T
  redis: Redis
  schema: Z
  redis_key: string
})

// 初始化：从 Redis 加载数据，返回 teardown 函数
initialize(): Promise<() => void>

// 持久化配置并推送变更
save(value: Partial<z.infer<Z>>): Promise<number>

// 当前配置快照（只读）
get value(): z.infer<Z>
```

### 通信端点

| 端点 | 说明 |
|------|------|
| `/-/dynamic-configs/subscribe` | 订阅方发送字段名数组，返回字段值 |
| `/-/dynamic-configs/unsubscribe` | 取消订阅 |
| `/-/dynamic-configs/change` (push) | 服务端推送变更 `{ key, newValue, oldValue }` |

## 最佳实践

### schema 设计

确保所有字段都有默认值或为 optional，否则构造 `MicroDynamicConfigsServer` 时会因 `parse({})` 失败：

```typescript
// ✓ 正确：字段都有默认值
z.object({
  host: z.string().default('localhost'),
  port: z.number().default(8080),
})

// ✗ 可能失败：必填字段无默认值
z.object({
  host: z.string(),  // parse({}) 时报错
})
```
