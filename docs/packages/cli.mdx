## 安装

```bash
pnpm add @hile/cli

# 或全局安装
pnpm add -g @hile/cli
```

安装后可使用 `hile` 命令。

---

## 它做了什么？

`@hile/cli` 是 Hile 应用的启动入口。运行 `hile start` 时，它会：

1. 加载 `.env` 文件（如果指定了 `--env-file`）
2. 设置 `NODE_ENV`（`--dev` 时为 `development`，否则为 `production`）
3. 在开发模式下加载 `tsx`（直接运行 TypeScript，无需预编译）
4. 在开发模式下订阅容器事件并输出日志
5. 读取 `package.json` 的 `hile.auto_load_packages`，加载指定模块
6. 扫描运行时目录下的 `*.boot.{ts,js}` 文件
7. 加载所有找到的服务（`await loadService()`）
8. 注册进程退出钩子，确保优雅关闭

## 命令详解

### hile start

```bash
hile start [name] [options]
```

| 选项 | 缩写 | 说明 | 默认值 |
|------|------|------|--------|
| `--dev` | `-d` | 开发模式 | `false` |
| `--silent` | `-s` | 静默模式，关闭开发模式下的容器事件日志 | `false` |
| `--env-file <path>` | `-e` | 加载 env 文件（可多次指定） | — |

`name` 参数可选，指定要启动的包名或路径。不传时使用当前目录。

#### 开发模式 vs 生产模式

| 特性 | `--dev` | 生产模式 |
|------|---------|---------|
| `NODE_ENV` | `development` | `production` |
| TypeScript | 使用 tsx 直接运行 | 需要预编译 |
| 扫描目录 | `src/` | `dist/` |
| 容器事件日志 | 自动输出 | 不输出 |

#### 加载 env 文件

```bash
# 加载单个 env 文件
hile start --env-file .env

# 加载多个（先加载的优先，已存在的 key 不被覆盖）
hile start --env-file .env --env-file .env.local

# 开发模式 + env 文件
hile start --dev --env-file .env.development
```

<Note>env 文件加载依赖 Node.js 20.12+ 原生 `process.loadEnvFile()` API。</Note>

#### 启动日志示例

开发模式下的典型输出（在终端中会带颜色：成功绿、错误红、警告黄等）：

```
[hile] service(database) init
[hile] service(http) init
[hile] service(http) ready (45ms)
[hile] service(database) ready (1203ms)
```

（实际标签为 `service(<key>)`，`<key>` 来自各 boot / 集成包注册的 `ServiceKey`，开发模式下经 `formatServiceKey` 格式化。）

按 Ctrl+C 关闭时：

```
[hile] container shutdown start
[hile] service(http) stopping
[hile] service(http) stopped (12ms)
[hile] service(database) stopping
[hile] service(database) stopped (3ms)
[hile] container shutdown done (15ms)
```

<Note>非 TTY（如重定向到文件或管道）时自动禁用颜色，输出为纯文本便于日志采集。</Note>

### hile registry

启动注册中心（Registry），提供服务注册与发现、心跳检测、配置存储等功能：

```bash
# 使用默认配置（端口 9876）
hile registry

# 指定端口和宣告地址
hile registry --port 8888 --host 10.0.0.1
```

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `--port <port>` | 监听端口 | `9876` |
| `--host <host>` | 宣告地址（其他服务连接的地址） | 自动获取的 IPv4 |

Registry 启动后自动在 `~/.registry/configs/` 下按 namespace 管理 YAML 配置文件，支持热加载。

### hile registry configs

管理本机 Registry 的 YAML 配置文件，无需手动编辑文件：

```bash
# 列出所有 namespace
hile registry configs

# 查看配置（YAML 输出）
hile registry configs get my-service

# 查看配置（JSON 输出）
hile registry configs get my-service --json

# 设置配置项（值自动推断类型）
hile registry configs set my-service port=8080
hile registry configs set my-service debug=true

# 设置数组/对象（值以 { 或 [ 开头时自动 JSON 解析）
hile registry configs set my-service whitelist='["10.0.0.1","10.0.0.2"]'
hile registry configs set my-service db='{"host":"localhost","port":3306}'

# 删除整个 namespace（需确认）
hile registry configs del my-service

# 删除某个字段（需确认）
hile registry configs del my-service port

# 跳过确认
hile registry configs del my-service -y
```

创建或修改的配置文件会被运行中的 Registry 通过 `fs.watch` 自动感知，无需重启。详细说明见 [@hile/micro](/packages/micro)。

## Boot 文件

Boot 文件是 Hile 应用的服务入口点。CLI 会扫描运行时目录下的所有 `*.boot.{ts,js}` 文件并加载。

**约定**：**`src/services/`** 下 **`*.boot.*`** 与 **`*.service.*`** **同属 service 模块**（均 **`defineService`**）：**`.boot`** 由 CLI **自启动**；**`.service`** 由 **`loadService`** **依赖加载**。二者**必须**放在 **`src/services/`**，**禁止**放在 **`src/`** 根目录。

### 编写 Boot 文件

```typescript
// src/services/http.boot.ts
import { defineService } from '@hile/core'
import { Http } from '@hile/http'

export default defineService('http', async (shutdown) => {
  const http = new Http({ port: 3000 })

  await http.load('./src/controllers', {
    suffix: 'controller',
    prefix: '/api',
  })

  const close = await http.listen()
  shutdown(close)

  return http
})
```

### 规则

| 规则 | 说明 |
|------|------|
| **`*.boot.*`** | **自启动** service 模块；必须以 **`.boot.ts`** 或 **`.boot.js`** 结尾 |
| **`*.service.*`** | **依赖加载** service 模块；必须以 **`.service.ts`** 或 **`.service.js`** 结尾 |
| 导出 | Boot 必须有 `export default`（或 `module.exports`） |
| 导出类型 | 必须是 `defineService(key, fn)` 的返回值 |
| 校验 | CLI 使用 `isService()` 校验，不合法则抛出 `invalid service file` |

### 多个 Boot 文件

可以有多个 boot 文件，它们会被 `Promise.all` 并发加载：

```
src/
└── services/
    ├── http.boot.ts        # HTTP 服务
    ├── database.boot.ts    # 数据库连接
    └── scheduler.boot.ts   # 定时任务
```

每个 boot 文件是一个独立的服务入口。它们内部可以通过 `loadService` 相互依赖。

## package.json 配置

### auto_load_packages

在 boot 文件扫描**之前**，CLI 会先加载 `hile.auto_load_packages` 中指定的模块：

```json
{
  "name": "my-app",
  "hile": {
    "auto_load_packages": ["@hile/typeorm", "@hile/ioredis"]
  }
}
```

| 特性 | 说明 |
|------|------|
| 加载顺序 | 按数组顺序加载，早于 boot 文件 |
| 模块名 | 与 `import('module')` 语义一致 |
| 校验 | 模块默认导出必须通过 `isService()` 校验 |
| 用途 | 适合加载框架级服务（如数据库、缓存） |

完整加载顺序：

```
1. auto_load_packages[0]
2. auto_load_packages[1]
3. ...
4. *.boot.ts (并发加载)
```

## 运行时目录

CLI 按以下优先级确定扫描哪个目录：

| 优先级 | 来源 | 目录 |
|--------|------|------|
| 1 | `HILE_RUNTIME_DIR` 环境变量 | 环境变量值 |
| 2 | `--dev` 模式 | `src/` |
| 3 | 生产模式 | `dist/` |

```bash
# 自定义运行时目录
HILE_RUNTIME_DIR=./custom hile start
```

## 优雅关闭

CLI 通过 `registerExitHook(container, offEvent)` 注册进程退出钩子（内部使用 `async-exit-hook`）。当收到 `SIGTERM`、`SIGINT` 等信号时：

1. **await** `container.shutdown()`（容器按 LIFO 顺序执行所有在 defineService 中注册的 shutdown 回调，含晚注册回调）
2. **仅在其完成后**执行 `offEvent()` 取消容器事件订阅
3. 调用 `exit()` 退出进程

若 `shutdown()` 未完成，进程会挂起不退出；强制退出超时被设为极大值，等效于「等 shutdown 完成再退出」。

```
SIGTERM/SIGINT → exitHook → await container.shutdown() → 执行所有 shutdown 回调 → offEvent() → exit
```

<Warning>
  如果没有任何服务可加载（`auto_load_packages` 为空且无 boot 文件），CLI 会输出 `no services to load` 并直接退出。
</Warning>

## 完整项目示例

```
my-app/
├── src/
│   ├── controllers/
│   │   ├── users/
│   │   │   └── index.controller.ts
│   │   └── hello.controller.ts
│   └── services/
│       ├── http.boot.ts       # HTTP 服务入口（*.boot 须在此目录）
│       ├── database.boot.ts   # 数据库服务入口
│       ├── config.service.ts  # defineService（通过 loadService 按需加载）
│       └── cache.service.ts
├── .env                       # 环境变量
├── package.json
└── tsconfig.json
```

```json
// package.json
{
  "name": "my-app",
  "type": "module",
  "scripts": {
    "dev": "hile start --dev --env-file .env",
    "build": "tsc -b",
    "start": "hile start --env-file .env"
  },
  "hile": {
    "auto_load_packages": ["@hile/ioredis"]
  },
  "dependencies": {
    "@hile/core": "^1.1.2",
    "@hile/http": "^1.1.0",
    "@hile/cli": "^1.1.3",
    "@hile/ioredis": "^1.1.2"
  }
}
```
