## 它做了什么？

`@hile/message-worker-thread` 是 `@hile/message-modem` 的 **Node.js Worker Threads 抽象实现**。它封装了 `worker.postMessage()` / `worker.on('message')` 和 `parentPort.postMessage()` / `parentPort.on('message')` 的细节，你只需继承 `MessageWorkerThread` 并实现 `exec` 方法即可。

继承链：

```
MessageModem (abstract)              ← post + exec 均抽象
  └── MessageWorkerThread (abstract) ← 实现 post，exec 仍抽象
        └── 用户子类                  ← 实现 exec
```

核心能力：

- **双端支持** — 主线程传入 `Worker` 或 `MessagePort`，Worker 线程端自动使用 `parentPort`
- **继承模式** — 子类实现 `exec` 定义请求处理逻辑
- **请求/响应** — 继承 `MessageModem` 全部能力（超时、中止、错误传播）
- **资源清理** — `dispose()` 移除监听，避免内存泄漏

## 通信模型

```
主线程                            Worker 线程
  │                                 │
  │  wt.request(data)               │
  │───── REQUEST ──────────────────►│
  │                                 │ exec(data)
  │                                 │
  │◄───── RESPONSE ─────────────────│
  │  resolve(result)                │
  │                                 │
  │  wt.abort()                     │
  │───── ABORT ────────────────────►│
  │                                 │ 取消 exec
```

<Note>
  通信是双向对称的。Worker 线程也可以向主线程发请求，前提是主线程的子类也实现了 `exec`。
</Note>

## 快速开始

### 第一步：定义子类

`MessageWorkerThread` 是抽象类，必须继承并实现 `exec`：

```typescript
import { MessageWorkerThread } from '@hile/message-worker-thread';
import { Exception } from '@hile/message-modem';

class ComputeWorker extends MessageWorkerThread {
  protected async exec(data: any): Promise<any> {
    switch (data?.action) {
      case 'compute':
        return data.value * 2;
      case 'restricted':
        throw new Exception(403, 'not allowed');
      default:
        return data;
    }
  }

  public request<T = any>(data: T, timeout?: number) {
    return this._send(data, timeout);
  }
}
```

### 第二步：主线程

```typescript
import { Worker } from 'node:worker_threads';

class MainThread extends MessageWorkerThread {
  protected async exec(data: any): Promise<any> {
    return { reply: 'from main', query: data };
  }

  public request<T = any>(data: T, timeout?: number) {
    return this._send(data, timeout);
  }
}

const worker = new Worker('./worker.js');
const wt = new MainThread(worker);

const result = await wt.request({ action: 'compute', value: 42 }).response();
console.log(result); // 84

wt.dispose();
await worker.terminate();
```

### 第三步：Worker 线程（worker.js）

```typescript
const wt = new ComputeWorker(); // 无参数 → 自动使用 parentPort
```

## 也可以用 MessageChannel

`MessageChannel` 创建一对互相连接的 `MessagePort`，可以在同一进程内测试或建立任意两端的通信：

```typescript
import { MessageChannel } from 'node:worker_threads';

const { port1, port2 } = new MessageChannel();
const side1 = new MySide(port1);
const side2 = new MySide(port2);

const result = await side1.request('hello').response();
console.log(result);

side1.dispose();
side2.dispose();
port1.close();
port2.close();
```

## 超时与中止

### 设置超时

```typescript
try {
  const result = await wt.request(data, 5000).response();
} catch (e) {
  // 超时后触发 abort → AbortException
}
```

### 主动中止

```typescript
const req = wt.request(data);
const promise = req.response();

setTimeout(() => req.abort(), 3000);

try {
  await promise;
} catch (e) {
  // AbortException
}
```

## 错误处理

### exec 中抛出异常

```typescript
import { Exception } from '@hile/message-modem';

class MyWorker extends MessageWorkerThread {
  protected async exec(data: any): Promise<any> {
    if (!data.token) {
      throw new Exception(401, 'Unauthorized');
      // status 401 透传到对端
    }
    throw new Error('Something went wrong');
    // 普通 Error → status 500
  }

  public request<T = any>(data: T, timeout?: number) {
    return this._send(data, timeout);
  }
}
```

### 对端捕获异常

```typescript
import { Exception, AbortException } from '@hile/message-modem';

try {
  await wt.request(data).response();
} catch (e) {
  if (e instanceof AbortException) {
    console.log('请求被中止或超时');
  } else if (e instanceof Exception) {
    console.log(`远端错误 [${e.status}]: ${e.message}`);
  }
}
```

## API 参考

### `MessageWorkerThread`（抽象类）

继承自 `MessageModem`。

| 方法 | 签名 | 说明 |
|------|------|------|
| `constructor` | `new SubClass(port?: Worker \| MessagePort)` | 主线程传 Worker/MessagePort；Worker 线程不传参数 |
| `exec` | `protected abstract exec(data: any): Promise<any>` | 子类必须实现：处理对端请求 |
| `_send` | `protected _send<T>(data: T, timeout?: number)` | 发送双向请求（`twoway: true`），返回 `{ abort, response }`。子类自行暴露为 public |
| `_push` | `protected _push<T>(data: T, timeout?: number)` | 发送单向推送（`twoway: false`），接收方不回复 RESPONSE |
| `dispose` | `dispose(): void` | 移除消息监听，释放资源 |

### `_send` 返回值

| 属性 | 类型 | 说明 |
|------|------|------|
| `abort` | `() => void` | 中止本次请求 |
| `response` | `<U = any>() => Promise<U>` | 等待对端响应，支持泛型 |

## 与其他模块的关系

```
@hile/message-modem              ← 抽象基类（传输无关）
  ├── @hile/message-ipc          ← Node.js IPC 实现（fork 父子进程）
  └── @hile/message-worker-thread ← Worker Threads 实现（worker_threads）
```

三者均不依赖 `@hile/core` 容器，可以独立使用。

---

## 与 @hile/message-ipc 的对比

| 特性 | message-ipc | message-worker-thread |
|------|-------------|----------------------|
| 底层 API | `process.send` / `child.send` | `port.postMessage` |
| 进程模型 | 独立进程（`fork`） | 同进程多线程（`new Worker`） |
| 内存 | 独立堆，JSON 序列化 | 可共享 `SharedArrayBuffer` |
| 传输通道 | `ChildProcess` | `Worker` / `MessagePort` |
| 构造参数 | `ChildProcess \| 不传` | `Worker \| MessagePort \| 不传` |

## 注意事项

<Warning>
  `MessageWorkerThread` 是抽象类，不能直接实例化。必须继承并实现 `exec` 方法。
</Warning>

<Warning>
  Worker 线程端不传参数时，必须确保代码运行在 Worker 线程内（`parentPort` 可用）。在主线程中不传参数会抛出错误。
</Warning>

<Warning>
  使用完毕后务必调用 `dispose()` 移除消息监听器。主线程端还需要 `await worker.terminate()` 关闭 Worker 线程。
</Warning>

## 常见问题

<AccordionGroup>
  <Accordion title="报错 'parentPort is not available' 怎么办？">
    这表示代码在主线程中运行，不在 Worker 线程内。主线程端必须传入 `Worker` 或 `MessagePort` 实例：

    ```typescript
    // ✅ 主线程
    const worker = new Worker('./worker.js');
    const wt = new MyWT(worker);

    // ✅ Worker 线程内
    const wt = new MyWT(); // 自动使用 parentPort
    ```
  </Accordion>
  <Accordion title="Worker 线程可以主动向主线程发请求吗？">
    可以。通信是双向对称的。只要主线程端的子类也实现了 `exec`，Worker 线程就可以通过 `request()` 向主线程发请求。
  </Accordion>
  <Accordion title="如何管理多个 Worker 线程？">
    为每个 `new Worker()` 创建独立的子类实例：

    ```typescript
    const workers = Array.from({ length: 4 }, () => new Worker('./worker.js'));
    const wts = workers.map(w => new MyWT(w));

    await Promise.all(wts.map(wt => wt.request('ping').response()));
    ```
  </Accordion>
  <Accordion title="可以传递 SharedArrayBuffer 吗？">
    `postMessage` 支持 transferable objects，但当前 `MessageWorkerThread` 的 `post` 实现只调用 `postMessage(data)` 不传 transfer list。如需传递 SharedArrayBuffer 或 transferable objects，可在子类中覆写 `post` 方法。
  </Accordion>
  <Accordion title="和 MessageChannel 有什么区别？">
    `MessageChannel` 创建一对 `MessagePort`，可以在同进程内使用。`Worker` 则是独立线程。两者都可以作为 `MessageWorkerThread` 的通道参数，因为 `Worker` 和 `MessagePort` 都支持 `postMessage` + `on('message')` 接口。
  </Accordion>
</AccordionGroup>
