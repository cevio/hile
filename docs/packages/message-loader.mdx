## 安装

```bash
pnpm add @hile/message-loader
```

依赖 `glob` 和 `rou3`，安装时自动引入。

## 它做了什么？

`@hile/message-loader` 是一个 **基于文件系统的消息路由加载器**，与 `@hile/http` 的 `Loader` 思路一致，但面向消息通信场景。

它将目录中的 `*.msg.{ts,js,tsx,jsx}` 文件自动扫描并注册为路由，也可用 **`register(routePath, fn)`** 在运行时挂载单条路由；通过 **`dispatch(path, data, extras?)`** 分发消息到匹配的处理器，其中 **`extras`** 会展开合并到处理器入参（例如 `@hile/micro` 注入 `client`）。

```
文件系统                        路由表                       分发
  messages/                    ┌──────────────────────┐
  ├── index.msg.ts    ──────►  │ /                    │
  ├── hello.msg.ts    ──────►  │ /hello               │  ──► dispatch(url, data, extras?)
  ├── users/                   │                      │       找到路由 → 执行 fn
  │   ├── index.msg.ts ─────►  │ /users               │       未找到  → 抛出错误
  │   └── [id].msg.ts  ─────►  │ /users/:id           │
  └── ...                      └──────────────────────┘
```

也可用 `loader.register(...)` 向路由表追加 **编程式路由**（图中未画出）。

核心能力：

- **文件系统即路由** — 目录结构自动映射为路由表
- **index 折叠** — `users/index.msg.ts` 映射为 `/users`
- **动态参数** — `[id].msg.ts` 转换为 `:id`，通过处理器入参 **`params`** 访问
- **路径前缀** — 通过 `prefix` 配置统一前缀（如 `/-`）
- **编程式路由** — `register(path, fn)` 返回单条注销函数
- **`dispatch` 扩展** — 第三参 `extras` 会与 `{ params, data, url }` 合并后传入 `fn`
- **注销支持** — `load()` 的注销移除该次扫描注册的全部路由；`register()` 的注销仅移除对应一条
- **传输无关** — 可搭配任意 message 通信模块或 [@hile/micro](/packages/micro) 使用

## 快速开始

### 第一步：创建消息处理器

使用 `defineMessage` 工厂函数定义消息处理器，每个 `*.msg.ts` 文件导出一个处理器：

```typescript
// messages/hello.msg.ts
import { defineMessage } from '@hile/message-loader';

export default defineMessage(async ({ data, params, url }) => {
  return { greeting: `Hello, ${data.name}!` };
});
```

### 第二步：支持动态参数

文件名中的 `[param]` 会被转换为路由参数：

```typescript
// messages/users/[id].msg.ts
import { defineMessage } from '@hile/message-loader';

export default defineMessage(async ({ params }) => {
  const user = await findUserById(params!.id);
  return user;
});
```

### 第三步：加载并分发

```typescript
import { MessageLoader } from '@hile/message-loader';
import path from 'node:path';

const loader = new MessageLoader({
  suffix: 'msg',
  prefix: '/-',
});

await loader.load(path.resolve(__dirname, 'messages'));

const result = await loader.dispatch('/-/hello', { name: 'world' });
console.log(result); // { greeting: 'Hello, world!' }

const user = await loader.dispatch('/-/users/42', {});
console.log(user); // findUserById 返回值，通常包含 id 等字段
```

### 编程式注册（可选）

不通过文件，直接在内存里挂路由：

```typescript
const unload = loader.register('/-/health', async ({ data }) => ({ ok: true, data }));
await loader.dispatch('/-/health', { ping: 1 });
unload();
```

## 文件系统映射规则

| 文件路径 | 路由（无 prefix） | 路由（prefix: `/-`） |
|---------|-------------------|---------------------|
| `index.msg.ts` | `/` | `/-/` |
| `hello.msg.ts` | `/hello` | `/-/hello` |
| `users/index.msg.ts` | `/users` | `/-/users` |
| `users/[id].msg.ts` | `/users/:id` | `/-/users/:id` |
| `[category]/[id].msg.ts` | `/:category/:id` | `/-/:category/:id` |

<Note>
  `defaultSuffix` 默认为 `/index`，即文件名为 `index` 时会被折叠。可通过配置 `defaultSuffix` 自定义折叠行为。
</Note>

## 与 message 模块搭配

`@hile/message-loader` 天然与 `@hile/message-modem` 家族模块搭配使用。只需在 `exec` 方法中调用 `loader.dispatch` 即可。若你需要 **中心化注册表 + 多实例 namespace 查找**，可先阅读 [@hile/micro](/packages/micro)：它在 message-loader + message-ws 上封装 `Registry` 与 `Application`。

### 搭配 @hile/message-ws

```typescript
import { MessageWs } from '@hile/message-ws';
import { MessageLoader } from '@hile/message-loader';
import path from 'node:path';

const loader = new MessageLoader({ suffix: 'msg', prefix: '/-' });
await loader.load(path.resolve(__dirname, 'messages'));

class AppWs extends MessageWs {
  protected async exec(data: { url: string; data: any }): Promise<any> {
    return loader.dispatch(data.url, data.data);
  }

  public request(url: string, data: any, options?: { timeout?: number, signal?: AbortSignal }) {
    return this._send({ url, data }, options);
  }
}
```

使用：

```typescript
import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ port: 8080 });
wss.on('connection', (ws) => {
  const modem = new AppWs(ws);
  ws.on('close', () => modem.dispose());
});

// 客户端
const ws = new WebSocket('ws://localhost:8080');
ws.on('open', async () => {
  const modem = new AppWs(ws);
  const result = await modem.request('/-/hello', { name: 'world' });
  console.log(result); // { greeting: 'Hello, world!' }
  modem.dispose();
  ws.close();
});
```

### 搭配 @hile/message-worker-thread

```typescript
import { MessageWorkerThread } from '@hile/message-worker-thread';

class AppWorker extends MessageWorkerThread {
  protected async exec(data: { url: string; data: any }): Promise<any> {
    return loader.dispatch(data.url, data.data);
  }

  public request(url: string, data: any, options?: { timeout?: number, signal?: AbortSignal }) {
    return this._send({ url, data }, options);
  }
}

// 主线程
const worker = new Worker('./worker.js');
const wt = new AppWorker(worker);
const result = await wt.request('/-/hello', { name: 'world' });
wt.dispose();
await worker.terminate();
```

### 搭配 @hile/message-ipc

```typescript
import { MessageIpc } from '@hile/message-ipc';

class AppIpc extends MessageIpc {
  protected async exec(data: { url: string; data: any }): Promise<any> {
    return loader.dispatch(data.url, data.data);
  }

  public request(url: string, data: any, options?: { timeout?: number, signal?: AbortSignal }) {
    return this._send({ url, data }, options);
  }
}

const ipc = new AppIpc();
const result = await ipc.request('/-/hello', { name: 'world' });
ipc.dispose();
```

## API 参考

### `MessageLoader`

| 方法 | 签名 | 说明 |
|------|------|------|
| `constructor` | `new MessageLoader(props: MessageLoaderProps)` | 创建加载器实例 |
| `load` | `load(directory: string): Promise<() => void>` | 从目录批量注册，返回注销函数（移除本批路由） |
| `register` | `register(routePath: string, fn: MessageFunction): () => void` | 注册单条路由，返回注销函数 |
| `dispatch` | `dispatch(path: string, data: any, extras?: Record<string, any>): Promise<any>` | 分发消息；`extras` 合并进处理器入参 |

### `MessageLoaderProps`

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `suffix` | `string` | `'msg'` | 文件后缀标记，匹配 `*.{suffix}.{ts,js,tsx,jsx}` |
| `defaultSuffix` | `string` | `'/index'` | 折叠后缀（index 文件映射为父级路径） |
| `prefix` | `string` | `''` | 路径前缀 |

### `defineMessage(fn)`

工厂函数，创建消息处理器注册信息，自动分配递增 ID。

```typescript
function defineMessage<T = any>(fn: MessageFunction<T>): MessageRegisterProps<T>;

type MessageFunction<T = any, E extends Record<string, any> = {}> = (data: {
  params?: Record<string, string>;
  data: T;
  url: string;
} & E) => any;

interface MessageRegisterProps<T = any> {
  id: number;
  fn: MessageFunction<T>;
}
```

### `dispatch` 处理器参数

| 属性 | 类型 | 说明 |
|------|------|------|
| `params` | `Record<string, string>` | 路由匹配提取的动态参数 |
| `data` | `any` | 调用方传入的消息数据 |
| `url` | `string` | 原始请求路径（包含 prefix） |
| （其它） | `extras` 中的键 | `dispatch` **第三参** 会展开并入同一对象，例如 `client` |

<Warning>`extras` 展开在 `params`、`data`、`url` 之后，如果用了同名字段会覆盖前者。避免使用 `data`、`params`、`url` 作为 `extras` 的键名。</Warning>

<Note>`load()` 注册的 **文件路由** 与 `register()` 注册的 **编程式路由** 共用同一张 `rou3` 路由表，`dispatch` 语义完全一致。</Note>

## 与 @hile/http Loader 的对比

| 特性 | @hile/http Loader | @hile/message-loader |
|------|-------------------|---------------------|
| 面向场景 | HTTP 请求 | 消息通信（WS/IPC/Worker） |
| 路由引擎 | find-my-way | rou3 |
| 文件后缀 | `*.controller.{ts,js}` | `*.msg.{ts,js,tsx,jsx}` |
| HTTP 方法 | 支持 GET/POST/PUT 等 | 仅 GET（内部路由键） |
| 冲突处理 | error/warn/override | 无（后注册覆盖） |
| 中间件 | 支持 | 不支持 |
| 依赖 HTTP 框架 | 是（`@hile/http`） | 否（独立使用） |

## 注意事项

<Warning>
  消息处理器文件必须有 `export default`。缺少默认导出的文件会被静默跳过，不会抛出错误。
</Warning>

<Warning>
  `dispatch` 在路径未匹配时抛出 `NotFoundException`（包含 `status: 'NOT_FOUND'`）。调用方应做好 try-catch 处理。
</Warning>

<Warning>
  `dispatch` 路径需要包含 `prefix`。如果 `prefix` 为 `/-`，那么调用 `dispatch('/hello', data)` 将找不到路由，应使用 `dispatch('/-/hello', data)`。
</Warning>

<Note>
  `load()` 返回注销函数，调用后所有已注册的路由会被移除。适合热更新场景：先注销旧路由，再重新加载。
</Note>

## 常见问题

<AccordionGroup>
  <Accordion title="dispatch 抛出 NotFoundException 怎么办？">
    检查以下几点：
    1. 文件是否放在正确的目录下，且命名符合 `*.msg.{ts,js,tsx,jsx}` 格式
    2. 文件是否有 `export default`
    3. dispatch 路径是否包含了 `prefix`
    4. 是否已调用 `loader.load()` 加载目录
  </Accordion>
  <Accordion title="如何实现热更新？">
    `load()` 返回注销函数，可以先注销旧路由再重新加载：

    ```typescript
    let off = await loader.load(directory);

    // 文件变更后
    off(); // 移除旧路由
    off = await loader.load(directory); // 重新加载
    ```
  </Accordion>
  <Accordion title="可以同时加载多个目录吗？">
    可以。每次 `load()` 调用独立注册路由，各自返回独立的注销函数：

    ```typescript
    const off1 = await loader.load(dir1);
    const off2 = await loader.load(dir2);

    // 独立注销
    off1();
    off2();
    ```
  </Accordion>
  <Accordion title="支持 TypeScript 消息处理器吗？">
    支持。`load()` 使用 `import()` 动态导入文件，只要运行环境支持 `.ts` 文件（如通过 `tsx`、`ts-node` 或编译后运行），就可以正常加载 `.msg.ts` 文件。
  </Accordion>
  <Accordion title="`register` 和 `load()` 能一起用吗？">
    可以。二者共用同一张 `rou3` 路由表；`load()` 返回的注销只撤销**该次目录扫描**注册的路由，`register()` 返回的注销只撤销**那一条**。
  </Accordion>
  <Accordion title="`dispatch` 第三参 `extras` 是什么？">
    可选对象，会展开合并进处理器入参（与 `params`、`data`、`url` 同级）。`@hile/micro` 在向 Registry 查询等场景下会传入 `{ client }`，handler 可读取 `client`。避免使用 `data`、`params`、`url` 作为 `extras` 的键名以免语义混淆。
  </Accordion>
  <Accordion title="与 @hile/http 的 Loader 有什么区别？">
    两者设计理念相同（文件系统即路由），但 `@hile/http` Loader 面向 HTTP 请求，支持多种 HTTP 方法和中间件；`@hile/message-loader` 面向消息通信，更轻量，不依赖 `@hile/core` 容器。
  </Accordion>
</AccordionGroup>
