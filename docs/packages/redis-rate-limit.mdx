## 安装

```bash
pnpm add @hile/redis-rate-limit @hile/ioredis
```

`@hile/redis-rate-limit` 不创建 Redis 连接。它接收任何满足 `RedisRateLimitLike` 的客户端；Hile 应用里通常来自 `@hile/ioredis`：

```typescript
import { loadService } from '@hile/core'
import redisService from '@hile/ioredis'
import { RedisRateLimiter } from '@hile/redis-rate-limit'

const redis = await loadService(redisService)
const limiter = new RedisRateLimiter(redis, { prefix: 'myapp:' })
```

## 快速开始

```typescript
import {
  RateLimitExceededError,
  RedisRateLimiter,
  defineLimit,
} from '@hile/redis-rate-limit'

const loginLimit = defineLimit('rl:login:{ip:string}', {
  algorithm: 'sliding-window',
  limit: 5,
  window: 60_000,
})

const result = await limiter.consume(loginLimit, { ip })

if (!result.allowed) {
  throw new RateLimitExceededError(result)
}
```

`defineLimit()` 的 key 支持和 `@hile/cache` 类似的模板参数：`{id:string}`、`{n:number}`、`{flag:boolean}`。

## 算法

| algorithm | Redis 结构 | 适合场景 |
|---|---|---|
| `fixed-window` | integer counter + TTL | 简单接口配额、成本低、允许窗口边界突刺 |
| `sliding-window` | sorted set accepted timestamps | 登录、验证码、昂贵查询，避免固定窗口边界突刺 |
| `token-bucket` | hash `{ tokens, updatedAt }` | 允许短突刺但需要平滑长期速率，例如邮件/短信发送 |

`fixed-window` 和 `sliding-window` 中，`limit` 表示每个 `window` 毫秒最多允许多少次。

`token-bucket` 中，`limit` 表示桶容量，`window` 表示空桶补满所需时间。例如 `limit: 4, window: 4000` 表示桶最多存 4 个 token，平均每秒补 1 个 token。每次 `consume()` 消耗 1 个 token。

## 返回值

```typescript
type RateLimitResult = {
  allowed: boolean
  algorithm: 'fixed-window' | 'sliding-window' | 'token-bucket'
  key: string
  limit: number
  remaining: number
  resetAt: number
  retryAfter: number
  dryRun: boolean
}
```

`retryAfter` 单位是毫秒。HTTP adapter 会把 `Retry-After` 转成秒。

## 状态机

### fixed-window

| 状态 | Redis value | TTL | 说明 |
|---|---|---:|---|
| key 不存在 | - | - | 当前窗口还没有请求 |
| active | integer counter | `window` | 第一次非 dry-run consume 创建窗口 |
| exceeded | integer counter | 剩余窗口 TTL | 超额请求仍会递增 counter，但不延长窗口 |
| reset | key 过期 | - | 下一次 consume 开启新窗口 |

### sliding-window

| 状态 | Redis value | TTL | 说明 |
|---|---|---:|---|
| key 不存在 | - | - | 滚动窗口内没有已接受 hit |
| active | sorted set | 最后 accepted hit 后 `window` | score 是 accepted hit 的时间戳 |
| exceeded | sorted set | 不变 | 超额请求不会写入 sorted set |
| reset | key 过期或旧 score 被 Lua 清理 | - | hit 按各自时间戳逐个离开窗口 |

Lua 会原子执行：清理过期 score、计数、判断、写入新 hit、刷新 TTL、返回 `remaining/resetAt/retryAfter`。

### token-bucket

| 状态 | Redis value | TTL | 说明 |
|---|---|---:|---|
| full | key 不存在或 token 已补满 | - | 新 key 视为满桶 |
| partial | hash `{ tokens, updatedAt }` | 到满桶为止 | 保存可为小数的 token 数 |
| empty | hash `{ tokens < 1, updatedAt }` | 到满桶为止 | 请求被拒绝，直到补够 1 个 token |
| reset | key 过期 | - | 下一次 consume 视为满桶 |

当调用方传入的 `now` 倒退时，Lua 不会把桶的 `updatedAt` 写回过去，避免提前补 token。

## HTTP adapter

```typescript
http.use(rateLimitHttp(loginLimit, {
  limiter,
  key: ctx => ({ ip: ctx.ip }),
}))
```

middleware 会设置 `X-RateLimit-*` 和 `RateLimit-*` 响应头。超额时返回 `429`，设置 `Retry-After`，并且不调用 `next()`。

## Model adapter

```typescript
pipeline.use(rateLimitModel(tenantLimit, {
  limiter,
  key: input => ({ tenantId: input.tenantId }),
}))
```

middleware 会把结果写入 `ctx.state.rateLimit`。超额时抛出 `RateLimitExceededError`。

## Dry run

```typescript
const result = await limiter.consume(limit, params, { dryRun: true })
```

`dryRun` 用于上线前观察。它会返回“如果真的 consume 会发生什么”，但不修改 Redis。

## 边界

<Warning>
限流不是认证、幂等、队列或审计系统。它只能限制尝试速率，不能替代权限检查、唯一约束、outbox、幂等 key 或业务额度账本。
</Warning>

- fixed window 成本最低，但允许窗口边界突刺。
- sliding window 更平滑，但每个 key 要保存 accepted hit 时间戳。
- token bucket 允许桶容量内的短突刺，并按长期速率补 token。
- `resetAt` 和 `retryAfter` 基于调用方提供的时钟和 Redis 状态计算；多实例部署时应保持机器时间基本同步。
