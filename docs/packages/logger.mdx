## 安装

```bash
pnpm add @hile/logger
```

同时确保安装了 peer 依赖（可选，用于开发环境美化输出）：

```bash
pnpm add pino-pretty
```

<Note>`pino-pretty` 是可选依赖。仅在开发环境（`NODE_ENV !== 'production'`）或显式设置 `pretty: true` 时需要。生产环境建议使用 JSON 格式输出，不需要此依赖。</Note>

## 核心概念

### 什么是结构化日志？

传统日志是纯文本字符串：

```
[INFO] user logged in
```

结构化日志是 JSON 格式的键值对：

```json
{"level":30,"time":1700000000000,"msg":"user logged in","userId":"u-001","module":"auth"}
```

结构化日志的优势：

| 优势 | 说明 |
|------|------|
| **机器可读** | 日志收集系统（ELK、Datadog、Splunk）可以直接解析和搜索 |
| **丰富的上下文** | 每条日志携带结构化字段，方便过滤和聚合 |
| **低解析开销** | 不需要正则表达式解析文本日志 |
| **Pino 性能** | Pino 是最快的 Node.js 日志库之一，比 Winston 快 5-10 倍 |

### `@hile/logger` 做了什么？

`@hile/logger` 是对 Pino 的轻量封装：

1. 提供更友好的默认配置（自动检测开发/生产环境）
2. 内置敏感字段过滤（credentials、tokens 等不会被写入日志）
3. 默认导出 Hile 服务定义，可直接与 `@hile/core` 容器集成
4. 服务退出时自动调用 `flush()` 确保日志完全写入

## 快速开始

### 直接使用

```typescript
import { createLogger } from '@hile/logger'

const logger = createLogger()

logger.info('application started')
logger.error({ err: new Error('connection failed') }, 'database error')
logger.warn({ cpu: 0.9 }, 'high CPU usage')
```

### 作为容器服务使用

```typescript
import { loadService } from '@hile/core'
import loggerService from '@hile/logger'

const logger = await loadService(loggerService)
logger.info('service container ready')
```

## 配置

### LoggerOptions

```typescript
interface LoggerOptions {
  level?: 'trace' | 'debug' | 'info' | 'warn' | 'error' | 'fatal'
  pretty?: boolean
  redact?: string[]
}
```

#### 配置项详解

| 选项 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `level` | `'trace' \| 'debug' \| 'info' \| 'warn' \| 'error' \| 'fatal'` | `LOG_LEVEL` 环境变量 或 `'info'` | 日志级别。低于此级别的日志不会输出 |
| `pretty` | `boolean` | `NODE_ENV !== 'production'` 时 `true` | 是否启用 pino-pretty 美化输出（终端用户友好） |
| `redact` | `string[]` | 无 | 敏感字段路径列表。匹配的字段在输出时会被替换为 `[Redacted]` |

#### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LOG_LEVEL` | `'info'` | 全局默认日志级别 |
| `NODE_ENV` | — | 控制 `pretty` 默认值：`'production'` 时输出 JSON，其他值或未设置时输出美化格式 |

#### 优先级规则

```
createLogger({ level }) > LOG_LEVEL 环境变量 > 'info' (默认值)
createLogger({ pretty }) > (NODE_ENV === 'production' ? false : true)
```

## API 参考

### 顶层导出

| 导出 | 类型 | 说明 |
|------|------|------|
| `createLogger(options?)` | `function` | 创建 Pino Logger 实例 |
| `Logger` | `type` | PinoLogger 的类型别名（`import type { Logger } from '@hile/logger'`） |
| `LoggerOptions` | `type` | `createLogger` 的参数类型 |
| **默认导出** | `ServiceRegisterProps<Logger>` | 作为 `@hile/core` 服务的 Logger。使用 `loadService` 加载 |

---

### createLogger(options?)

创建一个 Pino Logger 实例。

```typescript
function createLogger(options?: LoggerOptions): PinoLogger
```

#### 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `options` | `LoggerOptions` | 否 | Logger 配置选项 |

#### 返回值

返回 `PinoLogger` 实例（即 `pino` 包的 Logger 类型）。完整的 API 方法如下。

---

### Logger 实例方法

Pino Logger 提供了以下核心方法：

| 方法 | 签名 | 说明 |
|------|------|------|
| `logger.trace()` | `(obj?: object, msg?: string, ...args: any[]) => void` | TRACE 级别日志 |
| `logger.debug()` | `(obj?: object, msg?: string, ...args: any[]) => void` | DEBUG 级别日志 |
| `logger.info()` | `(obj?: object, msg?: string, ...args: any[]) => void` | INFO 级别日志 |
| `logger.warn()` | `(obj?: object, msg?: string, ...args: any[]) => void` | WARN 级别日志 |
| `logger.error()` | `(obj?: object, msg?: string, ...args: any[]) => void` | ERROR 级别日志 |
| `logger.fatal()` | `(obj?: object, msg?: string, ...args: any[]) => void` | FATAL 级别日志 |
| `logger.child()` | `(context: object) => Logger` | 创建带固定上下文的子 Logger |
| `logger.flush()` | `() => void` | 刷新待写入日志（退出前调用确保日志写入） |
| `logger.level` | `string` (getter/setter) | 获取或设置当前日志级别 |

<Note>`logger.trace()` 是 Pino 最详细的级别，默认不输出。需要在 `createLogger({ level: 'trace' })` 配置后可用。</Note>

#### 调用格式

每个级别的方法支持多种传参方式：

```typescript
// 仅有消息
logger.info('server started')

// 有结构化对象 + 消息
logger.info({ userId: 'u-001' }, 'user logged in')

// 有错误对象 + 消息
logger.error({ err }, 'operation failed')

// 多个参数（会使用 util.format 风格）
logger.info('user %s logged in', userId)

// 仅有结构化对象（消息可选）
logger.info({ event: 'page_view', path: '/home' })
```

### 默认导出（容器服务）

```typescript
export default defineService(Symbol.for('@hile/logger'), async (shutdown) => {
  const logger = createLogger()
  shutdown(() => { logger.flush() })
  return logger
})
```

作为 `@hile/core` 容器服务的行为：

| 行为 | 说明 |
|------|------|
| 服务 key | `Symbol.for('@hile/logger')` |
| 初始化 | 首次 `loadService` 时调用 `createLogger()` |
| Shutdown | 容器关闭时自动调用 `logger.flush()`，确保所有日志写入 |
| 单例 | 同一进程内只创建一个 logger 实例 |

## 完整使用示例

### 基础用法

```typescript
import { createLogger } from '@hile/logger'

// 创建一个生产环境 Logger
const logger = createLogger({
  level: 'info',
  pretty: false,       // 生产环境输出 JSON
})

// 简单日志
logger.info('应用程序启动')

// 带上下文的结构化日志
logger.info({ pid: process.pid, nodeVersion: process.version }, 'worker started')

// 错误日志
try {
  throw new Error('数据库连接失败')
} catch (err) {
  logger.error({ err }, 'database error')
}

// 退出前刷新
process.on('beforeExit', () => {
  logger.flush()
})
```

### 使用 Child Logger

```typescript
import { createLogger } from '@hile/logger'

const logger = createLogger({ level: 'info' })

// 创建模块级子 Logger
const httpLogger = logger.child({ module: 'http' })
const dbLogger = logger.child({ module: 'database' })

httpLogger.info({ method: 'GET', path: '/api/users' }, 'incoming request')
dbLogger.info({ query: 'SELECT ...', duration: 42 }, 'query executed')

// 多层继承
const orderLogger = logger.child({ module: 'order' })
const specificOrderLogger = orderLogger.child({ orderId: 'ord-001' })
specificOrderLogger.info('order created')
// 输出包含: { module: 'order', orderId: 'ord-001' }
```

### 敏感字段过滤

```typescript
import { createLogger } from '@hile/logger'

const logger = createLogger({
  level: 'info',
  pretty: false,
  redact: ['password', 'token', 'authorization', 'headers.authorization'],
})

// 敏感字段会被自动替换
logger.info({
  password: 'secret123',
  token: 'eyJhbG...',
  email: 'user@example.com',
}, 'user auth')
// 输出: {"password":"[Redacted]","token":"[Redacted]","email":"user@example.com"}
```

### 容器服务集成

```typescript
import { loadService } from '@hile/core'
import loggerService from '@hile/logger'

async function startApp() {
  // 从容器加载 Logger 服务
  const logger = await loadService(loggerService)

  logger.info('application started')

  // 使用 child logger 区分模块
  const httpLogger = logger.child({ module: 'http' })

  // 模拟请求
  httpLogger.info({ method: 'POST', path: '/api/orders' }, 'request received')

  // 当容器 shutdown 时，logger.flush() 会自动调用
}

startApp().catch(console.error)
```

### 开发和生产的差异

```typescript
// 开发环境 (NODE_ENV 未设置 或 NODE_ENV=development)
const devLogger = createLogger()
// pretty=true → 使用 pino-pretty 输出彩色、易读的格式

// 生产环境 (NODE_ENV=production)
const prodLogger = createLogger()
// pretty=false → 输出 JSON Lines, 每行一个 JSON 对象
```

开发环境输出示例（pino-pretty）：

```
[10:00:00.000] INFO  (12345): 应用程序启动
[10:00:00.001] ERROR (12345): 数据库连接失败
    err: {
      "type": "Error",
      "message": "数据库连接失败",
      "stack": "Error: ..."
    }
```

生产环境输出示例（JSON Lines）：

```json
{"level":30,"time":1700000000000,"pid":12345,"hostname":"server-1","msg":"应用程序启动"}
{"level":50,"time":1700000000001,"pid":12345,"hostname":"server-1","msg":"数据库连接失败","err":{"message":"数据库连接失败","stack":"..."}}
```

## 最佳实践

### 使用 Child Logger 区分模块

不要在整个应用中使用同一个 logger 实例，应该为每个模块创建 child logger：

```typescript
// ✅ 推荐：模块级 child logger
const logger = createLogger()
const httpLogger = logger.child({ module: 'http' })
const dbLogger = logger.child({ module: 'database' })
const paymentLogger = logger.child({ module: 'payment' })

// ❌ 不推荐：所有地方用同一个 logger
logger.info({ module: 'http' }, '...') // 冗余
```

### 始终携带错误对象

记录错误时，传递 `Error` 对象而不是仅记录消息：

```typescript
// ✅ 推荐：传递 error 对象
try {
  await doSomething()
} catch (err) {
  logger.error({ err }, 'operation failed')
}

// ❌ 不推荐：只记录消息
try {
  await doSomething()
} catch (err) {
  logger.error('operation failed: ' + err.message)
}
```

Pino 会自动将 `Error` 对象的 `stack`、`message` 等属性序列化。

### 生产环境不要用 pretty

```typescript
// ✅ 生产环境
const logger = createLogger({ pretty: false })

// ✅ 或者利用自动检测，设置环境变量
// NODE_ENV=production node app.js
```

### 在进程退出前 flush

```typescript
// 确保退出前所有日志写入
process.on('beforeExit', () => {
  logger.flush()
})

// 如果是容器服务，shutdown 会自动 flush
```

## 常见问题

<AccordionGroup>
  <Accordion title="如何将日志写入文件？">
    `@hile/logger` 不提供文件输出功能，因为生产环境中日志收集有更好的方式：

    **方式一：stdout 重定向（推荐）**
    ```bash
    node app.js > app.log 2>&1
    ```

    **方式二：PM2 日志管理**
    ```bash
    pm2 start app.js --output app.log --error err.log
    ```

    **方式三：日志收集 Agent**
    使用 Filebeat、Fluentd 等工具读取 stdout 发送到 ELK 或 Datadog。
  </Accordion>
  <Accordion title="如何使用高级 Pino 配置？">
    `createLogger` 封装了最常用的 pino 配置。如果需要自定义 levels、formatters、serializers 等，直接使用 `pino()` 原生 API 导出：

    ```typescript
    import pino from 'pino'

    const logger = pino({
      level: 'info',
      formatters: {
        level(label) { return { severity: label } },
      },
    })
    ```

    `@hile/logger` 保持精简，目的是覆盖 90% 的场景。
  </Accordion>
  <Accordion title="如何在不同模块间共享 Logger 实例？">
    推荐通过 `@hile/core` 容器加载 Logger 服务：

    ```typescript
    // 模块 A
    const logger = await loadService(loggerService)

    // 模块 B — 同一实例
    const logger = await loadService(loggerService)
    ```

    或者使用 createLogger 创建一次后导出为模块级单例。
  </Accordion>
  <Accordion title="redact 的路径语法支持哪些格式？">
    Pino 的 `redact` 支持 `path` 语法：

    ```typescript
    redact: ['password',              // 顶层字段
             'user.password',         // 嵌套字段
             'headers.*',             // 通配符
             'req.headers.cookie']    // 深层路径
    ```

    完整语法参考 [Pino Redact 文档](https://getpino.io/#/docs/redaction)。
  </Accordion>
  <Accordion title="容器服务的 shutdown 做了什么？">
    默认导出的服务在容器关闭时会调用 `logger.flush()`。

    ```typescript
    // @hile/logger 内部实现
    shutdown(() => { logger.flush() })
    ```

    `flush()` 确保所有待写入的日志缓冲区被刷新到输出流。这是防止进程退出时丢失日志的关键操作。
  </Accordion>
</AccordionGroup>
