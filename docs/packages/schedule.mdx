```bash
pnpm add @hile/schedule
```

从 3.0.0 开始，新增或重构的 Hile 架构包统一进入 3.x 版本线，2.x 时代结束。

<Note>依赖 `@hile/loader`（扫描文件系统）和 `node-schedule`（任务调度引擎），安装时会自动安装。</Note>

## 核心概念

### 什么是任务调度？

任务调度（Task Scheduling）是指在特定的时间点或时间间隔执行预定义的代码逻辑。常见的场景包括：

| 场景 | 示例 |
|------|------|
| 定时任务 | 每天早上 8 点生成日报 |
| 周期性任务 | 每 5 分钟检查系统健康状态 |
| 延迟任务 | 用户注册后 30 分钟发送欢迎邮件 |
| 定时清理 | 每天凌晨清理过期数据 |

### `@hile/schedule` 的设计

`@hile/schedule` 提供了两种使用方式：

1. **代码定义** — 通过 `Scheduler` 类的 `add()` 方法直接注册任务
2. **文件系统自动加载** — 通过约定文件命名规则编写任务文件，`scheduler.load()` 自动发现和注册

**两种表达式格式：**

| 格式 | 类型 | 说明 |
|------|------|------|
| `string` | cron 表达式 | 周期性执行，如 `'0 8 * * *'` 每天早上 8 点 |
| `{ delay: number }` | 延迟毫秒数 | 一次性延迟执行，如 `{ delay: 5000 }` 5 秒后执行 |

**错误隔离：** 所有任务的同步错误和异步 rejection 都被安全捕获，单个任务的失败不会影响调度器和其他任务的执行。

**分布式执行：** `Scheduler.add()` 和 `defineJob()` 支持 `distributed` 选项，底层使用 `@hile/redis-lock`，多实例部署时同一个 job 同一时间只会有一个实例执行。

## 快速开始

### 代码定义

```typescript
import { Scheduler } from '@hile/schedule'

const scheduler = new Scheduler()

// 每天 8:00 执行
scheduler.add('daily-report', '0 8 * * *', () => {
  console.log('Generating daily report...')
})

// 延迟 5 秒执行一次
scheduler.add('delayed-task', { delay: 5000 }, () => {
  console.log('Ran after 5 seconds')
})

// 查看所有任务
console.log(scheduler.getJobs())
// [
//   { id: 'daily-report', type: 'cron', expression: '0 8 * * *' },
//   { id: 'delayed-task', type: 'delay', expression: 'delay:5000' },
// ]

// 取消所有任务
scheduler.stop()
```

### 分布式任务

```typescript
scheduler.add('daily-report', '0 8 * * *', async () => {
  await generateDailyReport()
}, {
  distributed: {
    redis,
    ttl: 60_000,
  },
  onSkip(info) {
    console.log('skip locked job', info.id)
  },
})
```

默认策略是 `skip-if-locked`。如果希望短暂等待锁释放，可以配置 `policy: 'wait'` 和 `wait`。

默认锁 key 是 `schedule:{namespace}:{jobId}`，未配置 `namespace` 时使用 `default`。如果多个应用共享同一个 Redis，但允许相同 job id 各自执行，可以设置 `distributed.namespace` 隔离默认锁 key。

### 文件系统自动加载

```typescript
// tasks/report.schedule.ts
import { defineJob } from '@hile/schedule'

export default defineJob('daily-report', '0 8 * * *', () => {
  console.log('Daily report generated')
})
```

分布式任务建议显式传入稳定 id：

```typescript
export default defineJob('daily-report', '0 8 * * *', async () => {
  await generateDailyReport()
}, {
  distributed: { redis, ttl: 60_000 },
})
```

```typescript
// app.ts
import { Scheduler } from '@hile/schedule'
import { resolve } from 'node:path'

const scheduler = new Scheduler()

// 自动加载 tasks/ 目录下所有 *.schedule.ts 文件
const off = await scheduler.load(resolve(__dirname, 'tasks'))

// 需要时注销所有
off()
```

### defineJob(id, expression, handler, options?)

创建带稳定 id 的任务定义对象。推荐用于分布式任务、日志追踪和长期维护的任务文件。

```typescript
function defineJob(
  id: string | number,
  expression: string | { delay: number },
  handler: (info: JobRunInfo) => Promise<void> | void,
  options?: JobOptions,
): JobDefinition
```

### defineJob(expression, handler, options?)

创建一个标准化的任务定义对象。专为文件系统自动加载场景设计。

```typescript
function defineJob(
  expression: string | { delay: number },
  handler: (info: JobRunInfo) => Promise<void> | void,
  options?: JobOptions,
): JobDefinition
```

#### 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `expression` | `string \| { delay: number }` | 执行表达式。`string` = cron 表达式，`{ delay }` = 延迟毫秒数 |
| `handler` | `(info: JobRunInfo) => Promise<void> \| void` | 任务执行函数，可以是同步或异步 |

#### 返回值

```typescript
interface JobDefinition {
  id: string | number      // 显式 id，或 defineJob 自动生成的数字 id
  idAutoGenerated?: boolean // 未显式传 id 时为 true
  type: 'job'              // 固定为 'job'，用于文件加载时的类型判断
  expression: string | { delay: number }  // 原始表达式
  handler: (info: JobRunInfo) => Promise<void> | void // 执行函数
  options?: JobOptions                   // 分布式、错误、skip 配置
}
```

| 属性 | 类型 | 说明 |
|------|------|------|
| `id` | `string \| number` | 显式传入时为稳定 id；未传入时为自动递增数字 |
| `idAutoGenerated` | `boolean \| undefined` | 未显式传 id 时为 `true`，`scheduler.load()` 会用文件 routePath 作为实际注册 id |
| `type` | `'job'` | 固定为 `'job'`，用于 `scheduler.load()` 时校验文件内容 |
| `expression` | `string \| { delay: number }` | 原始传入的 cron 字符串或延迟配置 |
| `handler` | `(info: JobRunInfo) => Promise<void> \| void` | 任务执行函数 |

<Note>未显式传 id 时，`defineJob` 仍会生成进程级自增 id；但通过 `scheduler.load()` 加载时会使用文件路径派生出的 routePath 作为实际注册 id，避免多文件或多进程场景都落到 `1`。</Note>

#### Cron 表达式格式

支持标准的 5 字段格式以及带秒的 6 字段格式：

```
字段: 秒(可选) 分 时 日 月 周
格式: [秒] 分 时 日 月 周
```

| 表达式 | 说明 |
|--------|------|
| `'0 8 * * *'` | 每天早上 8:00 |
| `'*/5 * * * *'` | 每 5 分钟 |
| `'0 0 * * *'` | 每小时（整点） |
| `'0 0 * * 0'` | 每周日午夜 |
| `'0 9-17 * * 1-5'` | 工作日（周一至周五）9-17 点每小时 |
| `'*/10 * * * * *'` | 每 10 秒（6 字段格式） |
| `'0 0 1 * *'` | 每月 1 日午夜 |
| `'0 0 1 1 *'` | 每年 1 月 1 日午夜 |

#### 延迟任务表达式

```typescript
// 5 秒后执行一次
{ delay: 5000 }

// 1 分钟后执行一次
{ delay: 60000 }

// 1 小时后执行一次
{ delay: 3600000 }
```

### Scheduler 类

任务调度器，管理任务的注册、执行和取消。

```typescript
class Scheduler {
  // 方法
  add(id: string | number, expression: string, handler: JobHandler, options?: JobOptions): void
  add(id: string | number, options: { delay: number }, handler: JobHandler, jobOptions?: JobOptions): void
  remove(id: string | number): void
  stop(): void
  getJobs(): JobInfo[]
  load(directory: string, options?: { suffix?: string }): Promise<() => void>
}
```

#### new Scheduler()

创建一个调度器实例。

```typescript
const scheduler = new Scheduler()
```

#### add(id, expression, handler, options?)

注册一个 cron 任务或延迟任务。

```typescript
add(id: string | number, expression: string, handler: JobHandler, options?: JobOptions): void
add(id: string | number, options: { delay: number }, handler: JobHandler, jobOptions?: JobOptions): void
```

##### 参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | `string \| number` | 任务唯一标识。数字和字符串视为同一 key（`add(42, ...)` 和 `add('42', ...)` 冲突） |
| `expression` | `string` | cron 表达式（仅第一种重载） |
| `options.delay` | `number` | 延迟执行的毫秒数（仅第二种重载） |
| `handler` | `(info: JobRunInfo) => Promise<void> \| void` | 任务执行函数 |

##### 行为

| 场景 | 行为 |
|------|------|
| 正常注册 | 创建任务并添加到调度器 |
| 重复 ID | 抛出 `Error('Job "<key>" already exists')` |
| handler 抛同步错误 | 被 `try-catch` 捕获，不影响调度器 |
| handler 返回 rejected promise | 用 `.catch(() => {})` 静默处理 |

##### 示例

```typescript
const s = new Scheduler()

// cron 任务
s.add('health-check', '*/5 * * * *', async () => {
  const ok = await checkHealth()
  if (!ok) await notifyAdmin()
})

// 延迟任务
s.add('delayed-notification', { delay: 30000 }, () => {
  sendNotification()
})

// 数字 ID
s.add(1, '0 0 * * *', () => cleanup())
```

#### remove(id)

取消并删除指定任务。

```typescript
remove(id: string | number): void
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | `string \| number` | 要取消的任务 ID |

```typescript
s.add('task', '0 * * * *', handler)
s.remove('task')   // 取消任务
s.remove('noop')   // 不存在的 ID，不做任何操作

s.add(42, { delay: 100 }, handler)
s.remove(42)       // 等价于 s.remove('42')
```

#### stop()

取消所有已注册的任务，清空内部状态。

```typescript
stop(): void
```

```typescript
const s = new Scheduler()
s.add('a', '0 8 * * *', handlerA)
s.add('b', '0 0 * * *', handlerB)

s.stop()  // 取消 a 和 b

// stop 后可以继续添加新任务
s.add('c', '*/10 * * * *', handlerC)
```

#### getJobs()

获取所有已注册任务的信息快照。

```typescript
getJobs(): JobInfo[]
```

##### 返回值

```typescript
type JobInfo = {
  id: string         // 任务 ID（字符串形式）
  type: 'cron' | 'delay'  // 任务类型
  expression: string // 表达式：cron 字符串 或 'delay:<毫秒数>'
}
```

##### 示例

```typescript
const s = new Scheduler()
s.add('a', { delay: 1000 }, handlerA)
s.add('b', '0 8 * * *', handlerB)
s.add(3, '0 0 * * *', handlerC)

console.log(s.getJobs())
// [
//   { id: 'a', type: 'delay', expression: 'delay:1000' },
//   { id: 'b', type: 'cron', expression: '0 8 * * *' },
//   { id: '3', type: 'cron', expression: '0 0 * * *' },
// ]
```

#### load(directory, options?)

从目录自动扫描并加载任务文件。

```typescript
async load(
  directory: string,
  options?: { suffix?: string },
): Promise<() => void>
```

##### 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `directory` | `string` | 是 | — | 要扫描的目录路径 |
| `options.suffix` | `string` | 否 | `'schedule'` | 文件后缀标记 |

##### 文件命名规则

```
{任意名称}.{suffix}.{ts,js,tsx,jsx,mjs}
```

默认 suffix 为 `'schedule'`，即匹配 `*.schedule.ts`、`*.schedule.js`、`*.schedule.mjs`、`*.schedule.tsx`、`*.schedule.jsx`。

##### 内部流程

1. 使用 `@hile/loader` 的 `scanDirectory` 扫描匹配的文件
2. 动态 `import()` 每个文件
3. 检查 `mod.default` 是否存在且 `type === 'job'`
4. 如果任务 id 是 `defineJob()` 自动生成的，则使用文件 routePath 作为实际注册 id
5. 调用 `this.add(id, expression, handler, options)` 注册任务
6. 收集每个任务的注销函数

##### 返回值

返回一个批量注销函数。调用后取消所有通过本次 `load()` 注册的任务。

```typescript
const off = await scheduler.load('./tasks')
// ... 一段时间后
off()  // 取消所有通过 load 加载的任务
```

##### 示例

```typescript
// 扫描 ./tasks 下所有 *.schedule.ts 文件
const off = await scheduler.load('./tasks')

// 自定义 suffix
const off2 = await scheduler.load('./jobs', { suffix: 'job' })
```

### 类型参考

#### JobHandler

```typescript
type JobHandler = (info: JobRunInfo) => Promise<void> | void
```

任务处理函数类型。可以是同步或异步函数，参数是当前任务的运行信息。

#### JobDefinition

```typescript
type JobDefinition = {
  id: string | number
  idAutoGenerated?: boolean
  type: 'job'
  expression: string | { delay: number }
  handler: JobHandler
  options?: JobOptions
}
```

`defineJob` 的返回值类型。其中 `type` 固定为 `'job'`。

#### JobInfo

```typescript
type JobInfo = {
  id: string
  type: 'cron' | 'delay'
  expression: string
}
```

`getJobs()` 的返回值类型。`type` 区分任务类型，`expression` 是原始表达式的字符串形式。

## 完整示例

### 应用中的调度管理

```typescript
import { Scheduler, defineJob } from '@hile/schedule'
import { resolve } from 'node:path'

// 1. 创建调度器
const scheduler = new Scheduler()

// 2. 代码定义任务
scheduler.add('health-check', '*/5 * * * *', async () => {
  const isHealthy = await checkSystemHealth()
  if (!isHealthy) {
    console.error('[HEALTH] System unhealthy!')
    await notifyOps()
  }
})

scheduler.add('cleanup-temp', '0 3 * * *', async () => {
  await cleanupTempFiles()
  console.log('[CLEANUP] Temporary files cleaned')
})

scheduler.add('startup-notify', { delay: 5000 }, () => {
  console.log('[STARTUP] Application fully initialized')
})

// 3. 文件系统加载任务
const off = await scheduler.load(resolve(__dirname, 'schedules'))

// 4. 查看已注册的任务
const jobs = scheduler.getJobs()
console.log(`已注册 ${jobs.length} 个任务:`)
for (const job of jobs) {
  console.log(`  [${job.type}] ${job.id}: ${job.expression}`)
}

// 5. 优雅关闭
process.on('SIGTERM', async () => {
  console.log('Shutting down scheduler...')
  off()
  scheduler.stop()
  console.log('All jobs cancelled')
  process.exit(0)
})
```

## 最佳实践

### 使用文件系统加载管理任务

将每个任务写在单独的文件中，便于管理和维护：

```
schedules/
  daily-report.schedule.ts    # 日报生成
  health-check.schedule.ts    # 健康检查
  cleanup-temp.schedule.ts    # 临时文件清理
  data-sync.schedule.ts       # 数据同步
```

### 为每个任务赋予有意义的 ID

```typescript
// ✅ 语义化 ID，方便后续查看和管理
scheduler.add('daily-report', '0 8 * * *', handler)

// ❌ 无意义 ID
scheduler.add('job-1', '0 8 * * *', handler)
```

### 异步 handler 始终处理错误

虽然 `@hile/schedule` 会静默处理 handler 内部的错误，但仍然建议在 handler 内部自行处理，以便记录和告警：

```typescript
scheduler.add('data-sync', '0 */2 * * *', async () => {
  try {
    await syncData()
  } catch (err) {
    // 记录错误，通知运维
    console.error('[SYNC] Data sync failed:', err)
    await notifyOps(err)
  }
})
```

### 延迟任务的资源清理

延迟任务执行后，`node-schedule` 会自动失效。但 `Scheduler` 的元数据不会自动清理。如果不再需要保留记录，可以手动 `remove()`：

```typescript
scheduler.add('one-time', { delay: 5000 }, async () => {
  await doSomething()
  // 延迟任务执行后，可以手动清理元数据
  scheduler.remove('one-time')
})
```

### 组合使用 load() 和 add()

`load()` 和 `add()` 可以混合使用，它们管理的是同一个内部任务列表：

```typescript
const s = new Scheduler()
s.add('manual-task', '0 8 * * *', handler)       // 手动注册
await s.load('./tasks', { suffix: 'schedule' })   // 文件加载

s.stop()  // 取消所有手动注册 + 文件加载的任务
```

## 常见错误与排查

<AccordionGroup>
  <Accordion title="Job 'xxx' already exists">
    **原因**：调用了 `add()` 但指定的 `id` 已经被注册。

    **排查步骤：**
    1. 检查是否有重复调用 `add()` 的情况
    2. 检查 `load()` 加载的文件中是否有显式 ID 冲突；未传 id 的 `defineJob()` 会使用文件 routePath 作为实际注册 id
    3. 数字 ID 和字符串 ID 冲突：`add(42, ...)` 和 `add('42', ...)` 冲突
    4. 如果需要覆盖，先调用 `remove()` 再 `add()`
  </Accordion>
  <Accordion title="load() 加载后没有任务执行">
    **原因**：文件扫描或加载过程中可能有问题。

    **排查步骤：**
    1. 检查文件名是否符合约定：`*.schedule.ts`（默认 suffix）
    2. 确认文件有 `export default defineJob(...)`
    3. 调用 `getJobs()` 查看是否已注册
    4. 确认 cron 表达式是否正确
    5. 确认目录路径正确（使用绝对路径）
  </Accordion>
  <Accordion title="scheduler.load() 扫描不到文件">
    **原因**：glob 模式不匹配或目录路径错误。

    **排查步骤：**
    1. 确认文件扩展名在列表中：`.ts`、`.js`、`.tsx`、`.jsx`、`.mjs`
    2. 确认文件命名包含 `.schedule.`（或自定义 suffix）
    3. 尝试使用绝对路径
    4. 确认目录存在
  </Accordion>
  <Accordion title="延迟任务执行后 getJobs() 仍显示该任务">
    **原因**：延迟任务执行后 `Scheduler` 的元数据不会自动清理。

    **解决方案：**
    - 在 handler 中手动调用 `remove(id)` 清理
    - 或者忽略，因为 `node-schedule` 层面的任务已自动失效
  </Accordion>
  <Accordion title="cron 表达式不生效">
    **原因**：cron 表达式格式错误。

    **解决方案：**
    1. 检查是否使用正确的字段数（5 字段或 6 字段）
    2. 常见错误：`'* * * * *'` 表示每分钟，`'0 * * * *'` 表示每小时
    3. 使用 [crontab.guru](https://crontab.guru/) 在线验证表达式
  </Accordion>
</AccordionGroup>
