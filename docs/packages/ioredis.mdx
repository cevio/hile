## 核心概念

### 它做了什么？

`@hile/ioredis` 将 ioredis 客户端封装为 Hile 服务，提供两种使用方式：

1. **容器模式**（默认导出）：作为 Hile 服务，自动从环境变量读取配置、等待连接就绪、注册进程退出时的断连逻辑
2. **手动模式**（`createRedis`）：不依赖 Hile 容器，直接创建 Redis 客户端

### 为什么需要等待连接就绪？

`createRedis` 函数在创建 Redis 客户端后，会等待 `connect` 事件触发才 resolve。这意味着：

- 你拿到的一定是一个**已连接就绪**的客户端
- 如果连接失败（如 Redis 服务器未启动），Promise 会 reject，让你能及时捕获错误
- 避免出现"客户端创建成功但连接还没建立"的竞态条件

### RedisOptions

`RedisOptions` 是 ioredis 客户端的标准配置类型。`@hile/ioredis` 将其重新导出，方便你在需要时使用。

## 快速开始

### 第一步：配置环境变量

创建 `.env` 文件：

```env
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_USERNAME=
REDIS_PASSWORD=
REDIS_DB=0
```

### 第二步：加载服务

```typescript
import { loadService } from '@hile/core'
import ioredisService from '@hile/ioredis'

const redis = await loadService(ioredisService)

// 现在可以使用 ioredis 的全部 API
await redis.set('key', 'value')
const value = await redis.get('key')
console.log(value) // 'value'
```

### 手动创建

```typescript
import { createRedis } from '@hile/ioredis'

const redis = await createRedis({
  host: 'localhost',
  port: 6379,
  db: 0,
})

await redis.set('foo', 'bar')
const val = await redis.get('foo')

// 使用完毕断开连接
redis.disconnect()
```

## API 参考

### 默认导出（容器模式）

```typescript
export default defineService(Symbol.for(pkg.name), async (shutdown) => {
  const client = await createRedis()
  shutdown(() => client.disconnect())
  return client
})
```

默认导出的服务会自动执行以下操作：
1. 调用 `createRedis()` 从环境变量读取配置，创建并等待连接就绪
2. 注册 `shutdown` 回调，进程退出时自动调用 `client.disconnect()`
3. 返回已就绪的 `Redis` 实例（ioredis 的原生实例）

**使用方式**：

```typescript
import { loadService } from '@hile/core'
import ioredisService from '@hile/ioredis'

const redis: Redis = await loadService(ioredisService)
```

返回的 `Redis` 实例是标准的 ioredis `Redis` 对象，支持所有 ioredis API。

### createRedis(options?)

手动创建 Redis 客户端并等待连接就绪。

```typescript
async function createRedis(options?: RedisOptions): Promise<Redis>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `options` | `RedisOptions` | 否 | ioredis 的 Redis 配置。不传时从环境变量读取配置 |

**返回值**：`Promise<Redis>` — 连接就绪后的 ioredis `Redis` 实例。

**不传参数时**，从以下环境变量读取配置：

| 环境变量 | 映射到 RedisOptions | 默认值 | 说明 |
|---------|-------------------|--------|------|
| `REDIS_HOST` | `host` | `'localhost'` | Redis 服务器地址 |
| `REDIS_PORT` | `port` | `6379` | Redis 服务端口（自动转为 number） |
| `REDIS_USERNAME` | `username` | — | Redis 用户名（Redis 6+ ACL 功能） |
| `REDIS_PASSWORD` | `password` | — | Redis 密码 |
| `REDIS_DB` | `db` | `0` | Redis 数据库编号（0-15，自动转为 number） |

#### 连接等待机制

```typescript
async function createRedis(options?: RedisOptions): Promise<Redis> {
  const client = new Redis(options ?? envOptions())

  // 等待 connect 或 error 事件
  await new Promise<void>((resolve, reject) => {
    const onerror = (e: any) => reject(e)

    // 监听 error 事件：如果连接失败则 reject
    client.on('error', onerror)

    // 监听 connect 事件：连接成功后移除 error 监听并 resolve
    client.on('connect', () => {
      client.off('error', onerror)  // 连接成功后不再将 error 视为初始化失败
      resolve()
    })
  })

  return client
}
```

这意味着：
- 连接成功前发生错误 → Promise reject，创建失败
- 连接成功后发生错误 → 不触发 reject（由 ioredis 自动重连）

### RedisOptions 重新导出

```typescript
export type { RedisOptions } from 'ioredis'
```

`@hile/ioredis` 重新导出了 ioredis 的 `RedisOptions` 类型，方便在自定义配置时使用：

```typescript
import type { RedisOptions } from '@hile/ioredis'

const config: RedisOptions = {
  host: 'redis-cluster.example.com',
  port: 6379,
  retryStrategy: (times) => Math.min(times * 50, 2000),  // 自定义重试策略
  enableReadyCheck: true,
  maxRetriesPerRequest: 3,
}
```

## 完整示例

### 基本操作

```typescript
import { loadService } from '@hile/core'
import ioredisService from '@hile/ioredis'

async function main() {
  const redis = await loadService(ioredisService)

  // String
  await redis.set('name', 'Alice')
  const name = await redis.get('name')

  // Hash
  await redis.hmset('user:1', { name: 'Bob', age: '30' })
  const user = await redis.hgetall('user:1')

  // List
  await redis.lpush('queue', 'task1', 'task2')
  const task = await redis.rpop('queue')

  // Set
  await redis.sadd('tags', 'typescript', 'redis')
  const members = await redis.smembers('tags')

  // 带过期的 key
  await redis.setex('temp', 60, '将在 60 秒后过期')
}
```

### 缓存函数

```typescript
import { loadService } from '@hile/core'
import ioredisService from '@hile/ioredis'

async function getWithCache<T>(
  key: string,
  ttl: number,
  fetcher: () => Promise<T>
): Promise<T> {
  const redis = await loadService(ioredisService)

  // 尝试从缓存读取
  const cached = await redis.get(key)
  if (cached) return JSON.parse(cached)

  // 缓存未命中，调用回源函数
  const data = await fetcher()

  // 写入缓存
  await redis.set(key, JSON.stringify(data), 'EX', ttl)
  return data
}

// 使用
const user = await getWithCache('user:1', 300, async () => {
  return await db.query('SELECT * FROM users WHERE id = 1')
})
```

### Pub/Sub（发布/订阅）

```typescript
import { loadService } from '@hile/core'
import ioredisService from '@hile/ioredis'

async function main() {
  const redis = await loadService(ioredisService)

  // 订阅需要独立的连接（pub/sub 专用）
  const subscriber = redis.duplicate()

  // 订阅频道
  await subscriber.subscribe('events', (err) => {
    if (err) console.error('订阅失败:', err)
  })

  // 监听消息
  subscriber.on('message', (channel, message) => {
    console.log(`[${channel}] ${message}`)
  })

  // 发布消息
  await redis.publish('events', JSON.stringify({ type: 'user_created', id: 1 }))
}
```

### 分布式锁

```typescript
import { loadService } from '@hile/core'
import ioredisService from '@hile/ioredis'

async function acquireLock(
  lockKey: string,
  ttl: number = 10
): Promise<boolean> {
  const redis = await loadService(ioredisService)
  const result = await redis.set(lockKey, 'locked', 'NX', 'EX', ttl)
  return result === 'OK'
}

async function releaseLock(lockKey: string) {
  const redis = await loadService(ioredisService)
  await redis.del(lockKey)
}

// 使用
if (await acquireLock('order:1:lock')) {
  try {
    // 处理订单...
  } finally {
    await releaseLock('order:1:lock')
  }
}
```

## 连接行为详解

### 初始化流程

```
createRedis() 调用
    │
    ├── new Redis(options) — 创建客户端
    │    （ioredis 开始尝试连接）
    │
    ├── client.on('error', reject)    ← 监听错误
    ├── client.on('connect', resolve) ← 监听连接就绪
    │
    ▼
Promise pending...
     │
     ├── connect 事件触发 → 移除 error 监听 → resolve → 返回客户端
     │
     └── error 事件触发  → reject → 抛出异常
```

### 连接成功后 ioredis 的行为

- **自动重连**：如果连接断开，ioredis 会自动重试连接
- **error 事件**：连接成功后发生的错误不会再 reject Promise，而是触发 error 事件
- **ready 事件**：除了 `connect`，ioredis 还会触发 `ready` 事件表示可以发送命令。`createRedis` 在 `connect` 后即 resolve

### 断连行为

进程退出时，容器调用 `client.disconnect()`：
1. 停止自动重连
2. 关闭当前连接
3. 清理内部状态

## 最佳实践

### 1. 缓存 Key 的命名规范

```typescript
// 建议使用冒号分隔的层级结构
await redis.set('user:1:profile', data)
await redis.set('order:2024:01:count', data)
```

### 2. 为不同业务使用不同 Redis 实例

默认导出是单例。如需多个 Redis 实例，自定义额外的服务：

```typescript
import { defineService } from '@hile/core'
import Redis from 'ioredis'

export const cacheRedis = defineService('redis.cache', async (shutdown) => {
  const client = new Redis({ host: 'cache-host', port: 6379 })
  // 注意：手动创建的 Redis 实例最好也等待连接就绪
  shutdown(() => client.disconnect())
  return client
})

export const sessionRedis = defineService('redis.session', async (shutdown) => {
  const client = new Redis({ host: 'session-host', port: 6380 })
  shutdown(() => client.disconnect())
  return client
})
```

### 3. 合理设置过期时间

```typescript
// 使用 setex 一次性设置值和过期时间（原子操作）
await redis.setex('temp-key', 3600, 'value')

// 不要先 set 后 expire（非原子操作，可能漏掉 expire）
// await redis.set('temp-key', 'value')
// await redis.expire('temp-key', 3600)  // 不推荐
```

### 4. 不要在循环中使用 loadService

`loadService` 返回的是同一个单例，但每次调用都有轻微开销。建议将实例保存为变量：

```typescript
// 好：只 load 一次
const redis = await loadService(ioredisService)
for (const key of keys) {
  await redis.get(key)
}

// 不好：每次循环都 load
// for (const key of keys) {
//   const redis = await loadService(ioredisService)  // 不必要
//   await redis.get(key)
// }
```

## 常见错误排查

<AccordionGroup>
  <Accordion title="连接超时或拒绝连接">
    错误信息：`connect ETIMEOUT` 或 `connect ECONNREFUSED`。

    **解决方法**：
    - 确认 Redis 服务是否正在运行：`redis-cli ping` 应返回 `PONG`
    - 检查 `REDIS_HOST` 和 `REDIS_PORT` 是否正确
    - 检查防火墙是否阻止了连接
    - 检查 Redis 配置中 `bind` 和 `protected-mode` 设置
  </Accordion>

  <Accordion title="认证失败">
    错误信息：`ERR AUTH failed` 或 `NOAUTH Authentication required`。

    **解决方法**：
    - 检查 `REDIS_PASSWORD` 是否正确
    - 如果 Redis 启用了 ACL，需要同时设置 `REDIS_USERNAME` 和 `REDIS_PASSWORD`
    - 用 `redis-cli AUTH <username> <password>` 验证凭据
  </Accordion>

  <Accordion title="Redis 服务器配置了密码但环境变量未设置">
    错误信息：`NOAUTH Authentication required`。

    **解决方法**：在 `.env` 文件中添加 `REDIS_PASSWORD=你的密码`。
  </Accordion>

  <Accordion title="数据库编号错误">
    如果设置了 `REDIS_DB=1` 但操作似乎没有生效。

    **解决方法**：确认 Redis 配置中 `databases` 选项的值 >= 你设置的编号。
  </Accordion>

  <Accordion title="如何使用 Redis Cluster？">
    默认导出只支持单节点模式。如需 Cluster 模式，需要自定义服务：

    ```typescript
    import { defineService } from '@hile/core'
    import Redis from 'ioredis'

    export const clusterService = defineService('redis.cluster', async (shutdown) => {
      const cluster = new Redis.Cluster([
        { host: 'node1', port: 6379 },
        { host: 'node2', port: 6379 },
        { host: 'node3', port: 6379 },
      ])
      shutdown(() => cluster.disconnect())
      return cluster
    })
    ```
  </Accordion>

  <Accordion title="ioredis 自动重连导致难以调试">
    **解决方法**：可以在开发环境中限制重试次数：

    ```typescript
    const redis = await createRedis({
      host: 'localhost',
      retryStrategy: (times) => {
        if (times > 3) return null  // 超过 3 次不再重试
        return Math.min(times * 100, 1000)
      },
    })
    ```
  </Accordion>
</AccordionGroup>
