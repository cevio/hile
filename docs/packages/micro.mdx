## 安装

```bash
pnpm add @hile/micro
```

`@hile/micro` 自动引入以下依赖：

- `@hile/message-loader` - 路由注册与分发引擎（`register` / `dispatch` / `load`）
- `@hile/message-ws` - WebSocket 请求/响应传输层
- `@hile/message-modem` - 底层请求/响应/流式协议抽象
- `ws` - Node.js WebSocket 实现

---

## 核心概念

### 类层次结构

```
MessageModem                      请求/响应/流式协议抽象
  └── MessageWs                   WebSocket 传输层
        └── Client                远端连接代理（心跳 + request/push/stream）

Loader                            文件扫描抽象
  └── MessageLoader               消息路由注册与分发
        └── Server                WebSocket 服务端基类
              ├── Registry        注册中心（服务发现 + 发布订阅）
              └── Application     应用服务（服务发现 + 熔断 + 重试）
```

因此 `Application` 拥有以下**所有父类方法**：

| 来源 | 方法 | 用途 |
|------|------|------|
| `MessageLoader` | `register(url, fn)` | 编程式注册路由 |
| `MessageLoader` | `dispatch(url, data, extras?)` | 同进程内分发消息 |
| `MessageLoader` | `load(directory)` | 从目录加载 `.msg.ts` 文件作为路由表 |
| `Server` | `listen(port)` | 启动 WebSocket 监听 |
| `Server` | `connect(host, port)` | 出站连接其他节点 |
| `Server` | `handleUpgrade(req, socket, head)` | 挂载到已有 HTTP 服务器 |
| `Application` | `get(ns)` | 服务发现（从 Registry 查找并缓存） |
| `Application` | `call(ns, url, data)` | 一站式远程调用（发现+请求+熔断+重试） |
| `Application` | `stream(ns, url, data)` | 流式远程调用（返回 Readable stream） |
| `Application` | `publish(topic, data)` | 发布 topic |
| `Application` | `subscribe(topic, cb)` | 订阅 topic |

### 四大角色

| 类 | 职责 | 典型用法 |
|-----|-------|---------|
| **Server** | WebSocket 监听、连接管理 | 创建自定义协议的服务器节点 |
| **Client** | 远端连接代理 | 通过 `request()` / `push()` / `stream()` 通信 |
| **Registry** | 注册中心，维护全局服务拓扑 | 充当「电话总机」：所有服务在此注册和发现 |
| **Application** | 完整微服务节点 | **日常开发主要使用的类** |

## Server 类

`Server` 是所有服务节点的基类，继承自 `MessageLoader`。它负责：

- 启动 WebSocket 服务器监听端口
- 接受来自其他节点的入站连接并创建 `Client` 实例
- 向其他节点发起出站连接
- 管理所有连接的生命周期

### 构造函数

```typescript
const server = new Server('my-service', {
  advertiseHost: '127.0.0.1',   // 宣告地址，缺省自动获取
  logger: myLogger,              // 可选，日志记录器（缺省 console）
  suffix: 'msg',                 // 可选，传给 MessageLoader 的配置
  prefix: '-',                   // 可选
  defaultSuffix: '/index',       // 可选
});
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---------|------|------|------|------|
| `namespace` | `string` | 是 | - | 服务标识。出站连接时附加到 WebSocket URL 路径，Registry 用它区分不同服务 |
| `props.advertiseHost` | `string` | 否 | `getLocalIPv4()` | 向其他节点宣告的本机地址。若获取不到且未显式传入，构造函数抛错 |
| `props.logger` | `Logger` | 否 | `console` | 日志记录器，需支持 `debug` / `info` / `warn` / `error` |
| `props.suffix` | `string` | 否 | `'msg'` | `load()` 扫描文件的后缀标记 |
| `props.prefix` | `string` | 否 | `''` | 路由前缀 |
| `props.defaultSuffix` | `string` | 否 | `'/index'` | index 文件的折叠后缀 |

<Note>
 `advertiseHost` 在生产环境中应设为其他节点能访问到的 IP（如内网 IP `10.0.0.1`），而不是 `127.0.0.1`（除非所有服务在同一台机器上）。
</Note>

### 实例属性

| 属性 | 类型 | 说明 |
|----------|------|------|
| `namespace` | `string` | 构造时传入的服务标识（只读） |
| `port` | `number \| undefined` | 当前监听的端口号，`listen()` 调用后可用 |
| `host` | `string`（getter） | 宣告地址的解析结果 |
| `clients` | `Map<string, Client>` | 已连接的客户端映射表，key 为 `"host:port"` |
| `events` | `EventEmitter` | 连接/断开事件。发射 `connect` 和 `disconnect`，回调参数 `(client, extras)` |

### listen(port?)

启动 WebSocket 服务器。

```typescript
const teardown = await server.listen(9100);
console.log(`Server listening on port ${server.port}`);
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|--------|------|------|------|------|
| `port` | `number` | 否 | `0` | 监听端口。传 `0` 时创建 `noServer` 模式的 WebSocketServer，适用于挂载到已有 HTTP 服务器 |

**返回值**：`() => Promise<void>` teardown 函数。调用后依次：关闭所有 Client → 清空 clients 映射 → 关闭 WebSocketServer → 重置 port/wss。

### connect(host, port, timeout?)

向其他节点发起 WebSocket 出站连接。

```typescript
server.setPort(9100);
const client = await server.connect('10.0.0.2', 9000, 3000);
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|--------|------|------|------|------|
| `host` | `string` | 是 | - | 目标主机地址 |
| `port` | `number` | 是 | - | 目标端口（1-65535） |
| `timeout` | `number` | 否 | `5000` | 连接超时（毫秒） |

连接 URL 格式：`ws://{targetHost}:{targetPort}/{本机host}/{本机port}/{本机namespace}`

- 如果已存在到同一 `host:port` 的连接，旧连接会被关闭并替换（客户端去重）
- 必须先调用 `setPort()` 设置本地端口，否则抛错
- 超时未连接成功时抛出 `Connection timeout`

### setPort(port)

设置本地端口号，返回 `this`（链式调用）。必须在 `connect()` 之前调用。

### handleUpgrade(req, socket, head)

将 WebSocket 升级逻辑挂载到已有 HTTP 服务器。

```typescript
import { createServer } from 'node:http';

const httpServer = createServer((req, res) => { res.end('Hello'); });
httpServer.on('upgrade', (req, socket, head) => {
  server.handleUpgrade(req, socket, head);
});
httpServer.listen(3000);
```

<Warning>
 调用 `handleUpgrade` 之前必须先调用 `listen(0)` 初始化 WebSocketServer。
</Warning>

### 事件

```typescript
server.events.on('connect', (client, extras) => {
  console.log(`新连接: ${client.host}:${client.port}`, extras);
});
server.events.on('disconnect', (client, extras) => {
  console.log(`连接断开: ${client.host}:${client.port}`, extras);
});
```

`extras` 是 URL 路径中 namespace 之后额外部分的数组（ `/` 分割）。同时事件也会转发到 `Client.events`。

### 从 MessageLoader 继承的方法

Server 继承自 `MessageLoader`，因此也拥有：

#### register(url, fn)

编程式注册消息处理器。

```typescript
const unregister = server.register('/charge', async ({ data, params, url, client }) => {
  // data: 请求体
  // params: 动态路由参数（如 /users/:id 中的 id）
  // url: 请求路径
  // client: 发起请求的 Client（由 Server/Application 通过 dispatch extras 注入）
  return { charged: true, amount: data.amount };
});

// 不需要时注销该路由
unregister();
```

**关键点**：注册的 handler 既可以返回普通值（ `call()` 消费），也可以返回 `async generator`（ `stream()` 消费）。

#### load(directory)

从目录批量加载 `.msg.ts` / `.msg.js` 文件。这是**推荐的消息定义方式**。

```typescript
const unload = await server.load(resolve(__dirname, 'messages'));
// 注销：unload()
```

文件示例：

```typescript
// src/messages/charge.msg.ts
import { defineMessage } from '@hile/message-loader';
export default defineMessage(async ({ data }) => {
  return { charged: true, amount: data.amount };
});
```

#### dispatch(url, data, extras?)

同进程内分发消息。`extras` 会合并进 handler 的入参。

```typescript
const result = await server.dispatch('/charge', { amount: 100 });
// 也可以传入 extras 给 handler
const result = await server.dispatch('/charge', { amount: 100 }, { client: myClient });
```

### 完整示例

```typescript
import { Server } from '@hile/micro';

const serverA = new Server('service-a', { advertiseHost: '127.0.0.1' });
const closeA = await serverA.listen(9100);

const serverB = new Server('service-b', { advertiseHost: '127.0.0.1' });
const closeB = await serverB.listen(9200);

serverB.setPort(9200);
const client = await serverB.connect('127.0.0.1', 9100);  // B → A

serverA.register('/hello', async ({ data }) => {
  return { message: `Hello, ${data.name}!` };
});

const result = await client.request('/hello', { name: 'World' });
console.log(result);  // { message: 'Hello, World!' }

await closeB(); await closeA();
```

## Client 类

`Client` 是远端连接的代理，继承自 `MessageWs`。**通常不直接创建**，由 `Server.connect()` 或内部自动实例化。

### 实例属性

| 属性 | 类型 | 说明 |
|----------|------|------|
| `host` | `string` | 远端主机地址（只读） |
| `port` | `number` | 远端端口（只读） |
| `events` | `EventEmitter` | 连接状态事件（`connect` / `disconnect`） |

### `request<T>(url, data, options?)`

发送请求并等待远端响应。类似 HTTP 请求-响应模式。

```typescript
const result = await client.request<{ balance: number }>(
  '/account/balance',
  { userId: '123' },
  { timeout: 5000 }
);
```

| 参数 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `url` | `string` | 是 | 请求路径 |
| `data` | `any` | 是 | 请求数据（JSON 可序列化） |
| `options.timeout` | `number` | 否 | 超时时间（毫秒），超时后抛出错误 |
| `options.signal` | `AbortSignal` | 否 | 手动取消 |

**返回值**：`Promise<T>` - 远端 handler 的返回值。

**可能抛出的错误**：`Client is not online`（断开状态调用）、超时错误、远端异常透传。

### push(url, data, options?)

发送单向消息，不等待响应。适用于日志、事件通知等不需要回复的场景。

```typescript
client.push('/log', { event: 'page_view' });
```

返回值 `Promise<void>` - 数据发送完成即 resolve，不等待远端处理结果。

### stream(url, data, options?)

发送流式请求，返回 `Readable` stream。适用于大数据集、实时事件、LLM token 流等场景。

```typescript
const readable = client.stream('/events', { query: 'recent' }, { signal: abortController.signal });
for await (const chunk of readable) {
  console.log(chunk);
}
```

| 参数 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `url` | `string` | 是 | 请求路径 |
| `data` | `any` | 是 | 请求数据 |
| `options.signal` | `AbortSignal` | 否 | 取消信号 |

**返回值**：`Readable` - Node.js 可读流（`objectMode: true`），可用 `for await` 逐块消费。

**原理**：底层 `_stream()` 标记 `stream: true`，远端收到后检测 handler 返回的是否 `AsyncIterable`，若是则逐 chunk 回传 `MessageStreamChunk`（含 `seq` 序号和 `final` 结束标记）。

<Note>
 如果远端 handler 返回普通值而不是 async generator，`stream()` 会收到 `"Invalid async iterable"` 错误。
</Note>

### dispose()

清理资源：停止心跳定时器、关闭 WebSocket 连接。

### 心跳机制

Client 启动后自动心跳保活，通过环境变量配置：

| 环境变量 | 默认值 | 说明 |
|-------------------|---------|------|
| `MICRO_HEARTBEAT_INTERVAL` | `10000` (10s) | 心跳发送间隔 |
| `MICRO_HEARTBEAT_TIMEOUT` | `20000` (20s) | 心跳超时判死阈值 |
| `MICRO_HEARTBEAT_CHECK_INTERVAL` | `5000` (5s) | 超时检查间隔 |

Client 定期发送 `/-/heartbeat` 消息，远端 `exec()` 更新 `lastHeartbeat` 时间戳。超时未收到回复则自动 `dispose()`。

### 消息处理（exec）

当 Client 收到远端发来的消息时，`exec` 被调用：

```typescript
protected async exec(data: { url: string; data: any }): Promise<any> {
  if (data.url === '/-/heartbeat') {
    this.lastHeartbeat = Date.now();
    return;
  }
  return this.server.dispatch(data.url, data.data, { client: this });
}
```

通信是**双向对称的**：两端都能给对方发请求，也都能处理对方发来的请求。

## Registry 类

`Registry` 是注册中心，继承自 `Server`。它的 `namespace` 固定为 `'registry'`。

### 为什么需要 Registry？

Registry 相当于微服务的「电话总机」：

```
服务启动 → 连接 Registry → Registry 记录: payments = {10.0.0.1:9100, 10.0.0.2:9100}

消费者: Registry，payments 在哪里？
Registry: 随机返回一个可用实例（如 10.0.0.2:9100）
消费者: 直连 10.0.0.2:9100 → 调用 /charge
```

### 构造函数

```typescript
const registry = new Registry({ advertiseHost: '127.0.0.1' });
```

构造函数中会创建 `~/.registry/` 工作目录。

### listen(port)

```typescript
const teardown = await registry.listen(9876);
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|--------|------|------|------|------|
| `port` | `number` | 否 | `REGISTRY_PORT` 环境变量或 0 | 监听端口 |

如果 port 和 `REGISTRY_PORT` 都未设置或 ≤ 0，抛出错误。

启动后自动调用 `watchEnvFile()` 开始监听配置文件变更。

### watchEnvFile()

监听 `~/.registry/configs/` 目录下的 `*.config.yaml` 文件，文件变更时自动加载并发布 topic。

```yaml
# ~/.registry/configs/my-service.config.yaml
database:
  host: localhost
  port: 5432
debug: true
```

配置项会自动作为 topic `registry:{namespace}/{key}` 发布。

### 内置处理程序

| 路径 | 调用方向 | 说明 |
|------|----------|------|
| `/-/find` | Application → Registry | 按 namespace 查找可用实例，随机返回一个地址 |
| `/-/declare` | Publisher → Registry | 声明 topic 并发布初始数据 |
| `/-/undeclare` | Publisher → Registry | 取消声明 topic |
| `/-/subscribe` | Subscriber → Registry | 订阅 topic，立即返回当前数据 |
| `/-/unsubscribe` | Subscriber → Registry | 取消订阅 |
| `/-/topic/update` | 任意 → Registry | 推送 topic 更新，Registry 转发给该 topic 的所有订阅者 |

#### /-/find

```typescript
// 请求
{ namespace: 'payments', exclude?: ['10.0.0.1:9100'] }
// 响应（随机负载均衡）
{ host: '10.0.0.2', port: 9100 }
```

### 连接自动注册与清理

Application 连接 Registry 时，URL 路径被解析为：

```
ws://registry:9876/{advertiseHost}/{port}/{namespace}
```

Registry 自动将 `host:port` 加入 `namespaces[namespace]` 集合。连接断开时自动清理。

## Application 类

`Application` 是日常开发主要使用的类，继承自 `Server`，集成了：

- **自动连接 Registry** - `listen()` 时自动连接，失败则整个 listen 抛错
- **服务发现** - `get()` 从 Registry 查找服务地址并缓存
- **熔断器** - 按 namespace + peer 在本地内存记录 `closed` / `open` / `half-open` 状态
- **自动重试** - `call()` 失败后可换 peer 重试，`stream()` 的同步建流失败也可重试
- **缓存降级** - Registry 不可用时使用最后一次成功的地址
- **自动重连** - Registry 断连后 3 秒间隔重试，重连后自动重新订阅所有 topic
- **发布订阅** - `publish()` / `subscribe()` 通过 Registry 实现

### 构造函数

```typescript
const app = new Application({
  namespace: 'my-service',
  registry: { host: '127.0.0.1', port: 9876 },
  advertiseHost: '127.0.0.1',
  registryLookupTimeoutMs: 10_000,   // 默认
  requestTimeoutMs: 30_000,           // 默认
  circuitBreaker: {
    failureThreshold: 3,
    failureWindowMs: 60_000,
    successThreshold: 2,
    cooldownMs: 10_000,
    maxCooldownMs: 120_000,
    halfOpenMaxProbes: 1,
  },
});
```

#### ApplicationProps

| 属性 | 类型 | 必填 | 默认 | 说明 |
|----------|------|------|------|------|
| `namespace` | `string` | 是 | - | 本服务的唯一标识 |
| `registry` | `{ host, port }` | 是 | - | Registry 地址（严格校验） |
| `advertiseHost` | `string` | 否 | `getLocalIPv4()` | 宣告地址 |
| `registryLookupTimeoutMs` | `number` | 否 | `10000` | `/-/find` 查询超时 |
| `requestTimeoutMs` | `number` | 否 | `30000` | 远程调用默认超时 |
| `circuitBreaker` | `CircuitBreakerOptions` | 否 | 见「熔断器详解」 | 本地内存熔断策略 |

<Warning>
 `registry.host` 和 `registry.port` 经过严格校验（host 不能为空/含空白符/IPv6 须加方括号/端口 1-65535）。通不过时构造函数抛错。
</Warning>

---

### 方法详解

#### listen(port?)

启动 WebSocket 监听并连接 Registry。

```typescript
const teardown = await app.listen(9100);
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|--------|------|------|------|------|
| `port` | `number` | 否 | `0` | 监听端口 |

**启动流程**：
1. 调用父类 `Server.listen()` 启动 WebSocketServer
2. 调用 `reconnectToRegistry()` 连接 Registry
3. 连接 Registry 失败则整个 listen 抛出错误

**返回值**：teardown 函数。调用后：清理 fallback 路由 → 停止重连 → 断开 Registry → 调用父类 teardown。

**何时调用**：服务启动时调用一次，返回的 teardown 在 SIGTERM/SIGINT 时调用。

---

#### get(namespace, exclude?)

从 Registry 获取指定 namespace 的一个 Client 连接，结果会被**缓存**。

```typescript
const client = await app.get('payments');
const result = await client.request('/charge', { amount: 100 });
```

| 参数 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `namespace` | `string` | 是 | 目标服务名称 |
| `exclude` | `string[]` | 否 | 排除的地址列表（熔断器使用） |

**发现流程**（完整状态机）：

```
IDLE ──首次 get()──→ PENDING ──Registry /-/find──→
  ↑                                                    │
  │                    成功                            │
  │                    ↓                               │
  │                  READY（缓存到 namespaces map）      │
  │                    │                               │
  └──client disconnect──                               │
                              Registry 不可用          │
                              ↓                        │
                              缓存降级：若之前有缓存的 Client 且仍在连接，返回缓存
                              若无缓存 → 抛出错误
```

**缓存降级**：若 Registry 宕机但内存中仍有先前已连接的 Client，`get()` 自动返回该 Client，不报错。这确保即使 Registry 短时不可用，已经连上的 peer 仍可通信。

**合并请求**：当多个 `get()` 同时请求同一个 namespace 时，只发一次 Registry 查询，所有调用者共享结果。

**何时用**：当你需要拿到 Client 对象做多次调用（如 `request()` + `push()` + `stream()` 混合使用），或者需要手动控制 abort 时。

**何时不用**：大多数场景直接用 `call()` 或 `stream()` 更方便，它们内部调用了 `get()`。

---

#### `call<T>(namespace, url, data, options?)`

一站式远程调用。**最常用的 consumer 方法**。封装了：服务发现 → 请求 → 熔断排除 → 失败重试。

```typescript
// 最简用法
const result = await app.call('payments', '/charge', { amount: 100 });

// 自定义超时和重试
const result = await app.call('payments', '/charge', { amount: 100 }, {
  timeout: 5000,       // 5 秒超时
  retries: 3,          // 失败后重试 3 次
});

// 使用 AbortController 取消
const ac = new AbortController();
setTimeout(() => ac.abort(), 2000);
const result = await app.call('payments', '/charge', { amount: 100 }, {
  signal: ac.signal,
});
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|--------|------|------|------|------|
| `namespace` | `string` | 是 | - | 目标服务名 |
| `url` | `string` | 是 | - | 请求路径 |
| `data` | `any` | 是 | - | 请求数据 |
| `options.timeout` | `number` | 否 | `requestTimeoutMs`（默认 30000） | 单次请求超时 |
| `options.retries` | `number` | 否 | `1` | 失败重试次数 |
| `options.signal` | `AbortSignal` | 否 | - | 取消信号 |

**完整执行流程**：

```
call(namespace, url, data)
  │
  ├─→ 计算 exclude                     // 排除 open 或探针名额已满的 half-open peer
  ├─→ get(namespace, exclude)          // 向 Registry 查找可用 peer
  │     └─→ 所有 open peer 被排除 → 重置该 namespace 熔断状态后重新选择（可沿用仍连接的缓存 Client）
  │
  ├─→ client.request(url, data, {timeout, signal})
  │     ├─ 成功 → recordSuccess → 必要时关闭 half-open 探测 → return
  │     └─ 失败 → recordFailure → 必要时打开或重新打开熔断
  │               └─→ retries > 0 且 shouldRetry(err) → 下一轮选择其他 peer
  │               └─→ retries = 0 → 抛出错误
```

**何时用**：绝大多数请求/响应场景。如查询用户信息、创建订单、验证支付等。

**何时不用**：需要流式返回时用 `stream()`；需要复用同一个 Client 多次调用时先用 `get()`。

**retries = 0 时不会重试**，失败直接抛出。适合幂等敏感的写操作。

---

#### stream(namespace, url, data, options?)

流式远程调用。与 `call()` 共享相同的发现和熔断选路，但返回 `Readable` stream 而不是单次 Promise。同步建流失败可以按 `retries` 重试；流已经返回后的异步错误会计入熔断，但不会自动重放这个流。

```typescript
const readable = await app.stream('data-svc', '/stream-logs', { startDate: '2024-01-01' });
for await (const chunk of readable) {
  console.log('收到 chunk:', chunk);
}
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|--------|------|------|------|------|
| `namespace` | `string` | 是 | - | 目标服务名 |
| `url` | `string` | 是 | - | 请求路径 |
| `data` | `any` | 是 | - | 请求数据 |
| `options.signal` | `AbortSignal` | 否 | - | 取消信号 |
| `options.retries` | `number` | 否 | `1` | 同步建流失败重试次数 |

<Warning>
  `stream()` 只会在 `client.stream()` 同步抛错时自动重试。一旦 `Readable` 已返回，后续 `error` 会更新熔断状态并由消费方处理；用户主动 `destroy()` 或只触发 `close` 的流不会被当作一次成功探测。
</Warning>

**Provider 侧要求**：handler 必须返回 async generator（`async function*`）。两种注册方式均可：

```typescript
// 方式一：register() 注册
app.register('/events', async function* () {
  for (let i = 0; i < 100; i++) {
    yield { seq: i, time: Date.now() };
    await new Promise(r => setTimeout(r, 100));
  }
});

// 方式二：.msg 文件定义（推荐）
// src/messages/events.msg.ts
import { defineMessage } from '@hile/message-loader';
export default defineMessage(async function* ({ data }) {
  for (const item of await fetchItems(data.query)) {
    yield item;
  }
});
```

**Consumer 侧**：`stream()` 返回 Node.js `Readable`（`objectMode: true`），可用 `for await` 逐 chunk 消费或 pipe 到其他流。

```typescript
const readable = await app.stream('data-svc', '/events', { query: 'recent' });
try {
  for await (const chunk of readable) {
    console.log(chunk);
  }
} catch (err) {
  console.error('Stream error:', err);
}
```

**SSE（Server-Sent Events）集成**：将 `stream()` 的结果 pipe 到 HTTP SSE 响应，浏览器端用 `EventSource` 实时消费：

```typescript
// Koa 中间件示例（配合 @hile/http）
http.get('/api/events', async (ctx) => {
  ctx.respond = false;
  ctx.res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
  });

  const readable = await app.stream('data-svc', '/events', {});
  try {
    for await (const chunk of readable) {
      ctx.res.write(`data: ${JSON.stringify(chunk)}\n\n`);
    }
    ctx.res.write('data: [DONE]\n\n');
  } catch (err: any) {
    ctx.res.write(`event: error\ndata: ${JSON.stringify({ message: err.message })}\n\n`);
  } finally {
    ctx.res.end();
  }
});
```

浏览器端：
```javascript
const es = new EventSource('/api/events');
es.onmessage = (e) => { console.log(JSON.parse(e.data)); };
```

**完整协议链路**：

```
Consumer                     Provider
  │                           │
  │ stream()                  │
  │ ──REQUEST(stream=true)──→ │ exec() → MessageLoader.dispatch()
  │                           │ handler 返回 async generator
  │ ←──RESPONSE(seq:0)─────── │ for await (chunk of gen)
  │ ←──RESPONSE(seq:1)─────── │
  │ ←──RESPONSE(seq:2)─────── │
  │        ...                │
  │ ←──RESPONSE(final=true)── │ 迭代结束
  │                           │
  │ abort()                   │
  │ ──ABORT──────────────────→ │ generator.return()
```

**何时用**：大数据集分页、实时事件流、LLM token 输出、文件传输进度、日志流推送。

**何时不用**：单次请求/响应用 `call()`；偶发性的一次性数据也无需 streaming，`call()` 足够。

**常见错误**：
- handler 返回普通值而非 async generator → 报错 `"Invalid async iterable"`
- 处理 async generator 的执行函数是同步的 → `isAsyncIterable` 检查会失败
- 不需要流式传输时用 `stream()` 取单次返回值 → 浪费资源，应用 `call()`

#### `publish<T>(topic, data)`

发布一个 topic，返回 `{ update, unpublish }` 引用对象。

```typescript
const ref = await app.publish('config/feature-flag', { enabled: true });
await ref.update({ enabled: false });  // 所有订阅者立即收到推送
await ref.unpublish();                  // 取消发布
```

| 参数 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `topic` | `string` | 是 | topic 名称 |
| `data` | `T` | 是 | 初始数据 |

**内部流程**：向 Registry 发送 `/-/declare` → Registry 存储 topic 和 publisher → 订阅者连接时自动推送 → `update()` 发送 `/-/topic/update` 实现广播。

**何时用**：配置下发、事件广播、状态同步。
**何时不用**：需要点对点通信时用 `call()` 或 `push()`。

---

#### `subscribe<T>(topic, callback, isReconnect?)`

订阅一个 topic，数据变更时自动收到回调。

```typescript
const unsubscribe = await app.subscribe<{ enabled: boolean }>('config/feature-flag', (data) => {
  console.log('feature flag 更新:', data);
});
await unsubscribe();
```

| 参数 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `topic` | `string` | 是 | topic 名称 |
| `callback` | `(data: T) => any` | 是 | 数据更新回调 |
| `isReconnect` | `boolean` | 否 | 内部参数，Registry 重连后重新订阅用 |

**行为**：
1. 向 Registry 发送 `/-/subscribe`
2. Registry 返回当前 topic 数据
3. **立即调用一次 callback**（传入当前值）
4. 注册 `topic:{topic}` 事件监听
5. 后续有 publish/update 时自动触发 callback

**幂等性**：对同一 topic 重复 `subscribe()` 是安全的，第二次只返回 `unsubscribe` 函数，不重复注册。

**自动重订阅**：Registry 重连后自动重新订阅所有之前订阅过的 topic（`isReconnect = true`）。

**何时用**：监听配置变更、接收业务事件推送。

#### register(url, handler)（继承自 MessageLoader）

编程式注册消息处理器。

```typescript
const unregister = app.register<{ amount: number }>('/charge', async ({ data }) => {
  return { charged: true, amount: data.amount };
});
// 不需要时：unregister()
```

handler 入参包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `params` | `Record<string, string>` | 动态路由参数 |
| `data` | `T` | 请求体数据 |
| `url` | `string` | 当前请求路径 |
| `client` | `Client`（由 Server dispatch extend 注入） | 发起请求的 Client |

**handler 可以返回**：
- 普通值 → consumer 用 `call()` 获取 `Promise<T>`
- async generator → consumer 用 `stream()` 获取 `Readable`

#### load(directory)（继承自 MessageLoader）

从目录批量加载 `.msg.{ts,js}` 文件作为路由。**推荐用于定义消息处理器**。

```typescript
const unload = await app.load(resolve(__dirname, 'messages'));
// 文件示例：messages/charge.msg.ts
// import { defineMessage } from '@hile/message-loader'
// export default defineMessage(async ({ data }) => ({ charged: true }))
```

文件路径自动映射为路由路径：`hello.msg.ts` → `/hello`，`users/[id].msg.ts` → `/users/:id`，`users/index.msg.ts` → `/users`。

**何时用**：项目中有多个消息处理器，希望用文件组织而非 `register()` 集中注册。
**何时用 `register()`**：少数几个 handler，或需要动态注册/注销的场景。

同进程内分发消息。通常用于 `/-/health` 等内置端点。

const health = await app.dispatch('/-/health', {});

### 熔断器详解

熔断器在每次 `call()` 和 `stream()` 调用中自动工作。状态只保存在当前调用方 `Application` 的内存中，不写入 Registry、Redis 或数据库。

```
closed
  ├─ 连续失败达到 failureThreshold → open
  └─ 成功 → 清空该 peer 的失败状态

open
  ├─ 冷却未结束 → 进入 Registry exclude
  └─ 冷却结束 → half-open

half-open
  ├─ 探针名额已满 → 进入 Registry exclude，不额外放行
  ├─ 探测成功达到 successThreshold → closed
  └─ 探测失败 → open，并按指数退避延长 cooldown
```

默认策略：

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `failureThreshold` | `3` | 连续失败达到阈值后打开熔断 |
| `failureWindowMs` | `60000` | 连续失败统计窗口。窗口外的旧失败会被遗忘 |
| `successThreshold` | `2` | half-open 连续探测成功达到阈值后恢复 |
| `cooldownMs` | `10000` | 首次打开后的冷却时间 |
| `maxCooldownMs` | `120000` | half-open 探测失败后的指数退避上限 |
| `halfOpenMaxProbes` | `1` | half-open 同时放行的探测请求数 |
| `shouldRecordFailure(err)` | `() => true` | 返回 `false` 的错误不会计入熔断 |
| `shouldRetry(err)` | `() => true` | 返回 `false` 的错误不会自动重试 |

所有 `open` peer 都被排除时，`Application` 会重置该 namespace 的本地熔断状态并重新选择，避免服务完全饿死。若 Registry 短暂不可用但重置前已经拿到仍连接的缓存 Client，会沿用该缓存连接发起探测。但如果 peer 处于 `half-open` 且探针名额已满，不会通过 reset 绕过 `halfOpenMaxProbes`。

---

### 缓存降级详解

当 Registry 不可用时，`get()` 的降级行为：

| 场景 | 行为 |
|------|------|
| Registry 可用 + 有缓存 | 验证缓存有效性，无效则重新查询 |
| Registry 可用 + 无缓存 | 查询并连接 |
| Registry 不可用 + 缓存有效（Client 仍在连接） | 返回缓存 Client；熔断 reset 时也可用该缓存发起探测 |
| Registry 不可用 + 缓存无效（Client 已断开） | 抛出错误 |
| Registry 恢复 | 下次 `get()` 恢复查询 |

---

### Registry 重连详解

Application 与 Registry 断连后的重连机制：

```
disconnect 事件触发
  → this.registry = undefined
  → reconnectToRegistry()
      ├─ 成功 → this.registry = 新连接 → 重新订阅所有 topic → 注册下一次 disconnect 监听
      └─ 失败 → scheduleRegistryRetry()
                └─ 3 秒后再次尝试
```

- `listen()` teardown 被调用后（`stopped = true`），停止所有重连
- 重连成功后自动重新订阅所有之前订阅的 topic

## 完整场景示例

```typescript
import { Application, Registry } from '@hile/micro';
import { resolve, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = dirname(fileURLToPath(import.meta.url));

// ====== 启动 Registry ======
const registry = new Registry({ advertiseHost: '127.0.0.1' });
const closeRegistry = await registry.listen(9876);

// ====== 启动 Provider（支付服务） ======
const provider = new Application({
  namespace: 'payments',
  registry: { host: '127.0.0.1', port: 9876 },
  advertiseHost: '127.0.0.1',
});
const closeProvider = await provider.listen(0);

// 方式一：register() 注册 handler
provider.register('/charge', async ({ data }) => {
  return { transactionId: 'txn_001', amount: data.amount };
});

// 方式二：load() 从目录加载（推荐）
// 目录下放置 *.msg.ts 文件，export default defineMessage(...)
await provider.load(resolve(__dirname, 'messages'));

// 流式 handler
provider.register('/stream-data', async function* () {
  for (let i = 0; i < 10; i++) {
    yield { chunk: i };
    await new Promise(r => setTimeout(r, 100));
  }
});

// 发布配置
const configRef = await provider.publish('payments/config', {
  maxAmount: 10000, currency: 'CNY'
});

// ====== 启动 Consumer（订单服务） ======
const consumer = new Application({
  namespace: 'orders',
  registry: { host: '127.0.0.1', port: 9876 },
  advertiseHost: '127.0.0.1',
});
const closeConsumer = await consumer.listen(0);

// 请求/响应
const result = await consumer.call('payments', '/charge', { amount: 500 });
console.log(result);  // { transactionId: 'txn_001', amount: 500 }

// 流式调用
const stream = await consumer.stream('payments', '/stream-data', {});
for await (const chunk of stream) { console.log('stream chunk:', chunk); }

// 订阅配置
const unsubscribe = await consumer.subscribe('payments/config', (config) => {
  console.log('配置更新:', config);
});

// 更新配置（广播给所有订阅者）
await configRef.update({ maxAmount: 20000, currency: 'CNY' });

// 清理
await unsubscribe();
await configRef.unpublish();
await closeConsumer();
await closeProvider();
await closeRegistry();
```

## 决策指南：何时用什么

| 场景 | 方法 | 原因 |
|------|------|------|
| 单次请求/响应 | `app.call()` | 一站式：发现+请求+熔断+重试 |
| 需要复用同一个 Client | `app.get()` | 返回 Client 可多次 request/push/stream |
| 大数据流 / 实时事件 | `app.stream()` | 返回 Readable，逐 chunk 消费 |
| 单向通知（不关心响应） | `client.push()` | 无返回值，不等待 |
| 定义消息处理器（文件） | `app.load()` | 自动扫描 .msg 文件，推荐 |
| 动态注册/注销路由 | `app.register()` | 如运行时改变路由表 |
| 同进程内自调用 | `app.dispatch()` | 如调用 /-/health |
| 广播配置 / 事件 | `app.publish()` + `app.subscribe()` | Registry 中转的 pub/sub |

## 常见错误排查

### "Unable to resolve advertise host"

`getLocalIPv4()` 返回了 `undefined`。解决：显式传入 `advertiseHost: '127.0.0.1'`。

### "You can not connect to a server without a local port"

调用 `connect()` 或 `listen(0)` 前未调用 `setPort()`。解决：使用 `Application` 而非裸 `Server`，或先 `listen(port > 0)`。

### "Client is not online"

Client 已断开，但仍尝试发送请求。解决：监听 disconnect 事件及时清理引用，或重新调用 `app.get()`。

### "Namespace not found"

目标服务未启动或未连接到 Registry。检查 namespace 拼写和目标服务状态。

### "Invalid async iterable"（stream 调用）

Provider handler 返回了普通值而非 async generator。解决：handler 改为 `async function*` 并 `yield` 每个 chunk。

### "Registry not found"

1. 确保 `listen()` 已成功完成（`await app.listen(...)`)
2. 确保 Registry 正在运行且地址正确
3. 确保网络可达
