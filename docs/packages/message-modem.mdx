## 它做了什么？

`@hile/message-modem` 提供了一个 **抽象基类 `MessageModem`**，将底层传输机制（WebSocket、postMessage、IPC、child_process 等）与业务逻辑完全解耦。

你只需实现两个方法：

1. **`post(data)`** — 怎么把消息发出去
2. **`exec(data)`** — 收到请求后怎么处理

框架帮你搞定：

- 请求/响应自动配对（自增 ID + Promise 栈）
- 超时控制（默认 30 秒，可覆盖）
- 主动中止（发送方 abort → 接收方取消执行）
- 错误传播（`Exception` 携带 status 码透传，普通 Error 映射为 500）
- ID 溢出保护（超过 `Number.MAX_SAFE_INTEGER` 时自动归零）

## 消息流转

### 双向模式（`_send`）

```
发送方                        接收方
  │                             │
  │  _send(data)                │
  │──── REQUEST (twoway) ──────►│
  │                             │ exec(data)
  │                             │
  │◄──── RESPONSE ──────────────│
  │  resolve(data)              │
  │                             │
  │  abort()                    │
  │──── ABORT ─────────────────►│
  │                             │ 取消 exec
```

### 单向模式（`_push`）

```
发送方                        接收方
  │                             │
  │  _push(data)                │
  │──── REQUEST (!twoway) ─────►│
  │                             │ exec(data)
  │                             │ （不回复 RESPONSE）
```

<Steps>
  <Step title="发送方调用 _send(data)">
    框架生成自增 ID，构造 `REQUEST` 消息，通过 `post()` 发出。返回 `Promise<T>`。
  </Step>
  <Step title="接收方 receive 分发">
    接收方通过 `receive(msg)` 入口收到消息，根据 `mode` 分发到 `onRequest` / `onResponse` / `onAbort`。
  </Step>
  <Step title="接收方执行 exec">
    `onRequest` 调用子类实现的 `exec(data)` 方法处理业务逻辑。使用 `Promise.race` 同时监听 abort 信号。
  </Step>
  <Step title="结果返回">
    执行成功：发送 `RESPONSE`（status=200 + data）。
    执行失败：发送 `RESPONSE`（status=错误码 + message）。
    被中止：不发送响应。
  </Step>
  <Step title="发送方收到响应">
    `onResponse` 根据 ID 匹配 Promise 栈，status=200 时 resolve，否则 reject。
  </Step>
</Steps>

## 快速开始

### 场景一：WebSocket 通信

```typescript
import { MessageModem, type MessageTransferFormat } from '@hile/message-modem';

class WebSocketModem extends MessageModem {
  constructor(private ws: WebSocket) {
    super();
    // 绑定 receive 入口
    ws.addEventListener('message', (e) => {
      this.receive(JSON.parse(e.data));
    });
  }

  // 如何发送消息
  protected post<T>(data: MessageTransferFormat<T>): void {
    this.ws.send(JSON.stringify(data));
  }

  // 如何处理收到的请求
  protected async exec(data: any): Promise<any> {
    return handleRequest(data);
  }

  // 对外暴露发送方法
  public request<T>(data: T, options?: { timeout?: number, signal?: AbortSignal }) {
    return this._send(data, options);
  }
}
```

使用：

```typescript
const modem = new WebSocketModem(ws);

// 发送请求并等待响应
const user = await modem.request({ action: 'getUser', id: 1 });

// 发送请求并设置超时
const result = await modem.request(data, { timeout: 5000 });

// 发送请求并支持中止
const ac = new AbortController();
setTimeout(() => ac.abort(), 3000); // 3 秒后中止
const res = await modem.request(data, { signal: ac.signal });
```

### 场景二：iframe postMessage

```typescript
class IframeModem extends MessageModem {
  constructor(private target: Window, private origin: string) {
    super();
    window.addEventListener('message', (e) => {
      if (e.origin === origin) this.receive(e.data);
    });
  }

  protected post<T>(data: MessageTransferFormat<T>): void {
    this.target.postMessage(data, this.origin);
  }

  protected async exec(data: any): Promise<any> {
    return handleIframeRequest(data);
  }
}
```

### 场景三：Node.js Worker Threads

```typescript
import { parentPort, Worker } from 'node:worker_threads';

// 主线程
class WorkerModem extends MessageModem {
  constructor(private worker: Worker) {
    super();
    worker.on('message', (msg) => this.receive(msg));
  }

  protected post<T>(data: MessageTransferFormat<T>): void {
    this.worker.postMessage(data);
  }

  protected async exec(data: any): Promise<any> {
    return handleInWorkerThread(data);
  }
}

// Worker 线程
class ParentModem extends MessageModem {

    super();

  }

  protected post<T>(data: MessageTransferFormat<T>): void {
    parentPort!.postMessage(data);
  }

    return heavyComputation(data);
  }
```

## 异常处理

### 异常类型

| 类 | `status` | 默认 `message` | 触发时机 |
|------|----------|------|------|
| `Exception` | 自定义 | 自定义 | `exec` 中主动抛出 |
| `TimeoutException` | `ETIMEDOUT` | `Timeout` | 超过指定超时时间 |
| `AbortException` | `ECONNABORTED` | `Abort` | 调用 `abort()` 或被远端中止 |

### exec 中抛出异常

```typescript
import { Exception } from '@hile/message-modem';

protected async exec(data: any): Promise<any> {
  if (!data.token) {
    // status 码会透传到发送方
    throw new Exception(401, 'Unauthorized');
  }

  // 普通 Error 会被映射为 status 500
  throw new Error('Something went wrong');
}
```

### 发送方捕获异常

```typescript
import { Exception, AbortException } from '@hile/message-modem';

try {
  const result = await modem.request(data, { timeout: 5000 });
} catch (e) {
  if (e instanceof AbortException) {
    console.log('请求被中止或超时');
  } else if (e instanceof Exception) {
    console.log(`远端返回错误 [${e.status}]: ${e.message}`);
  }
}
```

## API 参考

### `MessageModem`（抽象类）

| 方法 | 可见性 | 签名 | 说明 |
|------|--------|------|------|
| `post` | `protected abstract` | `post<T>(data: MessageTransferFormat<T>): void` | 子类实现：如何将消息发送到远端 |
| `exec` | `protected abstract` | `exec(data: any, signal?: AbortSignal): Promise<any>` | 子类实现：如何处理收到的请求，可选接收中止信号 |
| `_send` | `protected` | `_send<T>(data: T, options?: { timeout?: number, signal?: AbortSignal }): Promise<T>` | 发送双向请求（`twoway: true`），返回 Promise。timeout 默认 30000ms |
| `_push` | `protected` | `_push<T>(data: T, options?: { timeout?: number, signal?: AbortSignal }): void` | 发送单向推送（`twoway: false`），无返回值，接收方不回复 RESPONSE |
| `_stream` | `protected` | `_stream<T>(data: T, options?: { signal?: AbortSignal }): Readable` | 发送流式请求，返回 `Readable` 流（objectMode），逐块消费远端 `AsyncIterable` |
| `receive` | `public` | `receive(msg: MessageTransferFormat): void` | 接收消息入口，根据 mode 分发处理 |

### 消息类型枚举 `MESSAGE_MODEM_TYPE`

| 值 | 说明 |
|------|------|
| `REQUEST` | 请求消息。`_send` 时 `twoway: true`（期待回复），`_push` 时 `twoway: false`（不期待回复） |
| `RESPONSE` | 响应消息。`twoway: false` |
| `ABORT` | 中止消息。`twoway: false`，data 为要中止的请求 ID |

### 消息格式

```typescript
interface MessageTransferFormat<T = any> {
  id: number;               // 自增消息 ID
  mode: MESSAGE_MODEM_TYPE; // 消息类型
  twoway: boolean;          // 是否需要响应
  stream?: boolean;          // 是否为流式消息
  data?: T;                 // 消息数据
}

interface MessageReturnFormat<T = any> {
  status: string | number;  // 200 成功，其他为错误码
  data: T;                  // 响应数据
  message: string;          // 错误消息（成功时可能为空）
}

interface MessageStreamChunk<T = any> {
  status: string | number;  // 200 成功，其他为错误码
  seq: number;              // 块序号
  payload: T;               // 块数据
  final: boolean;           // 是否为最后一个块
}
```

## 注意事项

<Warning>
  `post` 方法应保持同步。如果底层传输是异步的（如需要 await），应在 `post` 内部缓冲，不要将 `post` 声明为 `async`。
</Warning>

<Warning>
  `_send` 和 `_push` 方法均是 `protected` 的。子类应自行决定如何暴露（方法名、参数签名），而不是直接改为 public。
</Warning>

<Note>
  消息 ID 在同一实例内自增。两端各自维护独立的 ID 序列，不会冲突，因为 ID 只在 `stacks`（本地发出的请求追踪）和 `aborts`（本地收到的请求取消追踪）中各自使用。
</Note>

## 常见问题

<AccordionGroup>
  <Accordion title="如何处理大量并发请求？">
    每个请求通过唯一 ID 追踪，并发请求互不影响。ID 超过 `Number.MAX_SAFE_INTEGER` 时自动归零。在极端场景下，如果旧请求的 ID 仍未清理而新 ID 重复，可能导致冲突，但在实际使用中几乎不会发生。
  </Accordion>
  <Accordion title="远端无响应会怎样？">
    默认 30 秒后触发超时。超时会先触发 abort（发送 ABORT 消息到远端），然后 reject AbortException。你可以通过 `_send(data, { timeout: ms })` 自定义超时时间。
  </Accordion>
  <Accordion title="可以发送单向消息吗？">
    可以。使用 `_push` 方法发送单向消息（`twoway: false`），接收方执行 `exec` 后不会回复 RESPONSE。适用于通知、日志上报等 fire-and-forget 场景。`_send` 仍用于需要响应的双向请求。
  </Accordion>
  <Accordion title="支持 TypeScript 类型推导吗？">
    `_send` 返回 `Promise<T>`，泛型由 `_send<T>(data)` 传入，你可以这样使用：
    ```typescript
    const user = await modem.request<User>(data);
    ```
  </Accordion>
</AccordionGroup>
