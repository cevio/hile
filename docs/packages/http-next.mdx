## 安装

```bash
pnpm add @hile/http-next
```

---

## 它解决什么问题？

当你的项目同时需要 **API 接口**（由 Koa 处理）和 **SSR 页面渲染**（由 Next.js 处理）时，通常有两个选择：

1. 分别启动两个服务，用反向代理分流 — 部署复杂，无法共享中间件
2. 在同一个服务中运行两者 — `@hile/http-next` 的方案

`@hile/http-next` 将 Next.js 嵌入 Koa 服务，共享同一个 HTTP Server 和端口。API 路由默认使用 **`/-` 前缀**（可通过 `controllerPrefix` 配置），与 Next.js 页面路由隔离；控制器默认从 **`src/controllers/`**（开发）或 **`dist/controllers/`**（生产）加载，与 **`src/app/`** 下的页面文件分开存放。

## 快速开始

```typescript
import HttpNext from "@hile/http-next";

const httpNext = new HttpNext({
  port: 3000,
  cwd: __dirname,        // 项目根目录
  publicPath: "public",   // 或 string[] 挂载多个静态根（相对 cwd）
});

const close = await httpNext.start();
// close() 可关闭服务
```

### 与 @hile/core 集成（推荐用法）

```typescript
// src/services/index.boot.ts
import HttpNext from "@hile/http-next";
import { defineService } from "@hile/core";
import { fileURLToPath } from "node:url";
import { dirname, resolve } from "node:path";

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

export default defineService('http.next', async (shutdown) => {
  const httpNext = new HttpNext({
    port: 3000,
    cwd: resolve(__dirname, "../.."),
    publicPath: "public",
  });

  shutdown(await httpNext.start());
  return httpNext;
});
```

然后用 `hile start --dev` 启动，CLI 会自动加载这个 boot 文件。

## 请求处理流程

当一个请求到达服务器时，按以下顺序处理：

```
客户端请求
    |
    ▼
① koa-static(publicPath…)      匹配 `publicPath` 配置的静态根（string 或 string[]，相对 cwd）
    | 未命中
    ▼
② koa-static(.next/static/)    匹配 Next.js 构建产物（JS、CSS chunk）
    | 未命中
    ▼
③ hile-http 路由(默认 controllerPrefix 为 `/-`，即 `/-*`)  匹配 *.controller.ts 注册的 API 路由
    | 未命中
    ▼
④ Next.js handler               处理页面渲染、Next.js 内部路由、404
```

**关键规则：**
- API 控制器路由默认前缀为 `/-`（可用 `controllerPrefix` 修改）；`http.load` 使用 **`conflict: "error"`**，路由冲突直接抛错
- Next.js handler 是最后一个中间件，处理所有未被前面层匹配的请求
- Next.js handler 在 `prepare()` 完成后才注册为中间件，不存在未就绪问题

## API 路由（控制器）

控制器默认放在 **`src/controllers/`**（`NODE_ENV === 'development'` 时）或 **`dist/controllers/`**（生产构建后），使用 `@hile/http` 的 `defineController`（可选 `createControllerMetadata` + Zod 校验入参）。与 Next.js 的 **`src/app/`** 目录分离，避免混在同一文件夹。

### Model 层

Model 定义与消费由独立包 **`@hile/model`** 提供，详见 [@hile/model](./model)。

```typescript
// src/models/foo/foo.model.ts
import { defineModel } from "@hile/model";

export default defineModel(async (slug: string) => {
  return { slug };
});
```

```typescript
// src/app/foo/page.tsx
import { loadModel } from "@hile/model";
import fooModel from "@/models/foo/foo.model";

export default async function Page() {
  const data = await loadModel(fooModel, "x");
  return <div>{data.slug}</div>;
}
```

### 基本控制器

```typescript
// src/controllers/post.controller.ts
import { defineController } from "@hile/http";

export default defineController("GET", async (ctx) => {
  return { id: 1, title: "Hello from API", url: ctx.url };
});
```

映射到 `GET /-/post`（默认 `controllerPrefix` 为 `"/-"`）。

### 带中间件的控制器

```typescript
// src/controllers/admin/users.controller.ts
import { defineController } from "@hile/http";

const auth = async (ctx, next) => {
  if (!ctx.headers.authorization) ctx.throw(401);
  await next();
};

export default [
  defineController("GET", [auth], async (ctx) => ({ users: [] })),
  defineController("POST", [auth], async (ctx) => ({ created: true })),
];
```

映射结果：
- `GET /-/admin/users`
- `POST /-/admin/users`

### 路径映射表

（路径相对于默认控制器根目录 `src/controllers/`，前缀为默认的 `/-`。）

| 文件路径 | HTTP 路由 |
|---------|----------|
| `src/controllers/post.controller.ts` | `/-/post` |
| `src/controllers/users/index.controller.ts` | `/-/users` |
| `src/controllers/users/list.controller.ts` | `/-/users/list` |
| `src/controllers/users/[id].controller.ts` | `/-/users/:id` |
| `src/controllers/[category]/[id].controller.ts` | `/-/:category/:id` |

<Note>
  默认前缀为 `/-`，可通过 **`controllerPrefix`** 覆盖。
</Note>

## start() 执行流程

<Steps>
  <Step title="构造函数">
    - 创建 `Http` 实例（Koa + find-my-way）
    - 如果指定了 `publicPath`（`string` 或 `string[]`），对每个路径注册 `koa-static(resolve(cwd, path))`
    - 判断 `NODE_ENV` 设置 `isDevelopment`
    - 解析控制器根路径：`resolve(cwd, src|dist, controllerDirectory || "controllers")`，以及默认的 `controllerPrefix`、`controllerSuffix`
    - 解析 `.next` 产物目录：`nextArtifactsDir || resolve(cwd, ".next")`
  </Step>
  <Step title="注册构建产物静态资源">
    注册 `koa-static(.next/static/)` — 提供 Next.js 构建的 JS/CSS chunk
  </Step>
  <Step title="加载 API 控制器">
    先对主控制器根调用 `http.load(…, { suffix, defaultSuffix, prefix: controllerPrefix, conflict: "error" })`。若配置了 `specialControllers`（`{ directory, prefix }[]`），再按顺序对每一项执行 `http.load(resolve(cwd, src|dist, directory), { …同, prefix: 该项的 prefix })`。conflict 为 `error`，路由冲突直接抛错。
  </Step>
  <Step title="启动 HTTP 服务">
    调用 `http.listen()` 启动 Koa，传入 `onListen` 回调
  </Step>
  <Step title="初始化 Next.js">
    在 `onListen` 回调中：
    - 调用用户传入的 `onListen(server)`（如果有）
    - 创建 `NextServer({ dev, httpServer, dir })` — 与 Koa 共用同一 `http.Server`
    - 调用 `app.prepare()` — Next.js 编译页面、开发模式下 HMR 等
    - 获取 `app.getRequestHandler()`
    - 注册 Next.js 转发中间件（此后未匹配请求由 Next.js 处理）
  </Step>
</Steps>

## API 参考

### HttpNextProps

| 属性 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `port` | `number` | 是 | — | 监听端口 |
| `cwd` | `string` | 否 | `process.cwd()` | 项目根目录 |
| `publicPath` | `string \| string[]` | 否 | — | 静态资源根目录（相对 cwd） |
| `controllerDirectory` | `string` | 否 | `"controllers"` | 相对于 `src/`（开发）或 `dist/`（生产）的子目录名 |
| `controllerPrefix` | `string` | 否 | `"/-"` | 传给 `http.load` 的 `prefix`，API 路由前缀 |
| `controllerSuffix` | `string` | 否 | `"controller"` | 传给 `http.load` 的 `suffix`，即 `*.controller.ts` 中的 `controller` |
| `specialControllers` | `SpecialController[]` | 否 | — | 额外控制器根，主 load 完成后逐项 load |
| `nextArtifactsDir` | `string` | 否 | `resolve(cwd, ".next")` | Next.js 构建产物目录（.next 路径） |
| `keys` | `string[]` | 否 | 随机生成 | Koa 签名密钥 |

其余属性继承自 `@hile/http` 的 `HttpProps`（`ignoreDuplicateSlashes`、`ignoreTrailingSlash` 等）。

### SpecialController

| 字段 | 说明 |
|------|------|
| `directory` | 相对 `src/`（开发）或 `dist/`（生产）的子目录名，如 `"admin-api"` → `src/admin-api/*.controller.ts` |
| `prefix` | 该组控制器的路由前缀，如 `"/admin"` |

路由加载使用 `conflict: "error"`，重复路由直接抛错。

### HttpNext

| 属性/方法 | 说明 |
|----------|------|
| `use(middleware)` | 注册 Koa 中间件，返回当前实例支持链式调用 |
| `load(directory)` | 便捷加载路由，固定使用 `controllerSuffix` / `controllerPrefix` / `conflict: error` |
| `start(onListen?)` | 启动服务，`onListen` 可选回调在 HTTP 启动后、Next.js prepare 前调用，接收 `http.Server`。返回关闭函数 |

### 导出

| 导出 | 说明 |
|------|------|
| `HttpNext`（默认导出） | 主类 |
| `SpecialController` | 额外控制器根配置类型 |
