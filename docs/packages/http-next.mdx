## 安装

```bash
pnpm add @hile/http-next
```

依赖：`@hile/http`、`koa`、`koa-static`、`next`。

---

## 它解决什么问题？

当你的项目同时需要 **API 接口**（由 Koa 处理）和 **SSR 页面渲染**（由 Next.js 处理）时，通常有两个选择：

1. 分别启动两个服务，用反向代理分流 — 部署复杂，无法共享中间件
2. 在同一个服务中运行两者 — `@hile/http-next` 的方案

`@hile/http-next` 将 Next.js 嵌入 Koa 服务，共享同一个 HTTP Server 和端口。API 路由使用 `/-` 前缀与 Next.js 页面路由完全隔离。

## 快速开始

```typescript
import HttpNext from "@hile/http-next";

const httpNext = new HttpNext({
  port: 3000,
  cwd: __dirname,        // 项目根目录
  publicPath: "public",   // 静态资源目录
});

const close = await httpNext.start();
// close() 可关闭服务
```

### 与 @hile/core 集成（推荐用法）

```typescript
// src/index.boot.ts
import HttpNext from "@hile/http-next";
import { defineService } from "@hile/core";
import { fileURLToPath } from "node:url";
import { dirname, resolve } from "node:path";

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

export default defineService(async (shutdown) => {
  const httpNext = new HttpNext({
    port: 3000,
    cwd: resolve(__dirname, ".."),
    publicPath: "public",
  });

  // 可选：在 start() 前注册全局中间件（如请求日志、CORS 等）
  // httpNext.use(async (ctx, next) => { ... await next(); });

  // start() 返回关闭函数，注册到 shutdown
  shutdown(await httpNext.start());

  return httpNext;
});
```

然后用 `hile start --dev` 启动，CLI 会自动加载这个 boot 文件。

## 请求处理流程

当一个请求到达服务器时，按以下顺序处理：

```
客户端请求
    │
    ▼
① koa-static(public/)          匹配 public 目录下的静态文件
    │ 未命中
    ▼
② koa-static(.next/static/)    匹配 Next.js 构建产物（JS、CSS chunk）
    │ 未命中
    ▼
③ hile-http 路由(/-*)           匹配 *.controller.ts 注册的 API 路由
    │ 未命中
    ▼
④ Next.js handler               处理页面渲染、Next.js 内部路由、404
```

**关键规则：**
- 所有 API 控制器路由强制使用 `/-` 前缀
- Next.js handler 是最后一个中间件，处理所有未被前面层匹配的请求
- Next.js handler 在 `prepare()` 完成后才注册为中间件，因此不存在未就绪的问题

## API 路由（控制器）

控制器文件放在 `src/app/` 目录下，使用 `@hile/http` 的 `defineController`：

### 基本控制器

```typescript
// src/app/post.controller.ts
import { defineController } from "@hile/http";

export default defineController("GET", async (ctx) => {
  return {
    id: 1,
    title: "Hello from API",
    url: ctx.url,
  };
});
```

这个文件会被自动映射到 `GET /-/post`。

### 带中间件的控制器

```typescript
// src/app/admin/users.controller.ts
import { defineController } from "@hile/http";

const auth = async (ctx: any, next: any) => {
  if (!ctx.headers.authorization) ctx.throw(401);
  await next();
};

const getUsers = defineController("GET", [auth], async (ctx) => {
  return { users: [{ id: 1, name: "Admin" }] };
});

const createUser = defineController("POST", [auth], async (ctx) => {
  return { created: true };
});

export default [getUsers, createUser];
```

映射结果：
- `GET /-/admin/users`
- `POST /-/admin/users`

### 路径映射表

| 文件路径 | HTTP 路由 |
|---------|----------|
| `src/app/post.controller.ts` | `/-/post` |
| `src/app/users/index.controller.ts` | `/-/users` |
| `src/app/users/list.controller.ts` | `/-/users/list` |
| `src/app/users/[id].controller.ts` | `/-/users/:id` |
| `src/app/[category]/[id].controller.ts` | `/-/:category/:id` |

<Warning>
  路由前缀固定为 `/-`，不可修改。这是为了从路径层面彻底避免与 Next.js 文件路由冲突。
</Warning>

## Next.js 页面路由

Next.js 使用标准的 App Router，页面文件放在 `src/app/` 下：

```typescript
// src/app/page.tsx — 首页 /
export default function Home() {
  return <h1>Hello, Next.js!</h1>;
}

// src/app/about/page.tsx — /about
export default function About() {
  return <h1>About</h1>;
}

// src/app/[id]/page.tsx — 动态路由 /1, /2, ...
export default async function IdPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  return <h1>Page {id}</h1>;
}
```

页面和控制器在同一个 `src/app/` 目录下共存：

```
src/app/
├── layout.tsx           # Next.js 布局 — 由 Next.js 处理
├── page.tsx             # 首页 — 由 Next.js 处理
├── about/
│   └── page.tsx         # /about — 由 Next.js 处理
├── post.controller.ts   # /-/post — 由 hile-http 处理
└── users/
    ├── page.tsx         # /users — 由 Next.js 处理
    └── [id].controller.ts  # /-/users/:id — 由 hile-http 处理
```

Next.js 只关心 `page.tsx`、`layout.tsx` 等约定文件，忽略 `*.controller.ts`。hile-http 只关心 `*.controller.ts`，忽略其他文件。

## SEO 优化

### 静态 Metadata

在 `layout.tsx` 或 `page.tsx` 中导出 `metadata`：

```typescript
// src/app/layout.tsx
export const metadata = {
  title: {
    default: "我的应用",
    template: "%s | 我的应用",  // 子页面标题套用模板
  },
  description: "应用描述",
};

// src/app/about/page.tsx
export const metadata = {
  title: "关于我们",           // 浏览器标题变为「关于我们 | 我的应用」
  description: "关于页描述",
  openGraph: {
    title: "关于我们",
    description: "关于页描述",
  },
};
```

### 动态 Metadata

```typescript
// src/app/[id]/page.tsx
export async function generateMetadata({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  return {
    title: `页面 ${id}`,
    description: `动态页面，当前 id: ${id}`,
  };
}
```

## TypeScript 配置

项目需要两份 tsconfig：

### tsconfig.json（Node.js 编译）

编译控制器、boot 文件等 Node.js 代码：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "outDir": "./dist",
    "rootDir": "./src",
    "jsx": "react-jsx"
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

### tsconfig.next.json（Next.js 编译）

Next.js 专用，通过 `next.config` 指定：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["DOM", "DOM.Iterable", "ES2022"],
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noEmit": true,
    "plugins": [{ "name": "next" }]
  },
  "include": ["src/app/**/*", "next.config.mjs", ".next/types/**/*.ts"]
}
```

在 `next.config` 中指定：

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  typescript: {
    tsconfigPath: "tsconfig.next.json",
  },
};
export default nextConfig;
```

## start() 执行流程

<Steps>
  <Step title="构造函数">
    - 创建 `Http` 实例（Koa + find-my-way）
    - 如果指定了 `publicPath`，注册 `koa-static(public/)` 中间件
    - 判断 `NODE_ENV` 设置 `isDevelopment`
  </Step>
  <Step title="注册构建产物静态资源">
    注册 `koa-static(.next/static/)` — 提供 Next.js 构建的 JS/CSS chunk
  </Step>
  <Step title="加载 API 控制器">
    扫描 `src/app/`（开发模式）或 `dist/app/`（生产模式）下的 `*.controller.ts` 文件，挂载到 `/-` 前缀下（在 `listen()` 之前完成）
  </Step>
  <Step title="启动 HTTP 服务">
    调用 `http.listen()` 启动 Koa，传入 `onListen` 回调
  </Step>
  <Step title="初始化 Next.js">
    在 `onListen` 回调中：
    - 创建 `NextServer({ dev, webpack, httpServer })` — 共享 Koa 的 HTTP Server
    - 调用 `app.prepare()` — Next.js 编译页面、启动 HMR 等
    - 获取 `app.getRequestHandler()` — 保存为 Next 请求处理函数
    - 注册 Next.js 转发中间件（此后未匹配请求由 Next.js 处理）
  </Step>
</Steps>

## API 参考

### HttpNextProps

| 属性 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `port` | `number` | 是 | — | 监听端口 |
| `cwd` | `string` | 否 | `process.cwd()` | 项目根目录 |
| `publicPath` | `string` | 否 | — | 静态资源目录（相对于 cwd） |
| `keys` | `string[]` | 否 | 随机生成 | Koa 签名密钥 |

继承 `@hile/http` 的 `HttpProps`（`ignoreDuplicateSlashes`、`ignoreTrailingSlash` 等）。

### HttpNext

| 属性/方法 | 类型 | 说明 |
|----------|------|------|
| `use(middleware)` | `(middleware: Middleware) => HttpNext` | 注册 Koa 中间件，返回当前实例以支持链式调用 |
| `start()` | `Promise<() => void>` | 启动服务，返回关闭函数 |
