## 安装

```bash
pnpm add @hile/http-next
```

同时确保安装了 peer 依赖：

```bash
pnpm add @hile/http next koa koa-static
```

## 核心概念

### 它解决什么问题？

当你的项目同时需要 **API 接口**（由 Koa 处理）和 **SSR 页面渲染**（由 Next.js 处理）时，通常有两个选择：

1. **分别启动两个服务**，用反向代理（如 Nginx）分流 — 部署复杂，无法共享中间件
2. **在同一个服务中运行两者** — `@hile/http-next` 的方案

`@hile/http-next` 将 Next.js 嵌入 Koa 服务，共享同一个 HTTP Server 和端口。API 路由默认使用 **`/-` 前缀**（可通过 `controllerPrefix` 配置），与 Next.js 页面路由隔离；控制器默认从 **`src/controllers/`**（开发）或 **`dist/controllers/`**（生产）加载。

### 请求处理流程

当一个请求到达服务器时，按以下顺序处理：

```
客户端请求
    │
    ▼
① koa-static(publicPath…)   匹配 publicPath 配置的静态资源（相对 cwd）
    │ 未命中
    ▼
② koa-static(.next/static/)   匹配 Next.js 构建产物（JS、CSS chunk）
    │ 未命中
    ▼
③ hile-http 路由(默认 prefix: /-)   匹配 *.controller.ts 注册的 API 路由
    │ 未命中
    ▼
④ Next.js handler   处理页面渲染、Next.js 内部路由、404
```

**关键规则**：
- API 控制器路由默认前缀为 `/-`，可用 `controllerPrefix` 修改
- `http.load` 使用 `conflict: 'error'`，路由冲突直接抛错
- Next.js handler 是最后一个中间件，处理所有未被前面匹配的请求
- Next.js handler 在 `prepare()` 完成后才注册为中间件

### 什么是 SpecialController？

当一个项目有多个独立的 API 模块时，可以用 `SpecialController` 给每个模块分配不同的路由前缀。例如：

```
src/
  controllers/        → 主控制器  前缀 /-
  admin-api/          → 管理员 API 前缀 /admin
  public-api/         → 公开 API   前缀 /public
```

## 快速开始

### 基本用法

```typescript
import HttpNext from '@hile/http-next'

const httpNext = new HttpNext({
  port: 3000,
  cwd: process.cwd(),    // 项目根目录
  publicPath: 'public',   // 或 string[] 挂载多个静态根目录
})

const close = await httpNext.start()
// 程序结束时调用 close() 关闭服务
```

### 与 @hile/core 集成（推荐用法）

```typescript
// src/services/index.boot.ts
import HttpNext from '@hile/http-next'
import { defineService } from '@hile/core'
import { fileURLToPath } from 'node:url'
import { dirname, resolve } from 'node:path'

const __filename = fileURLToPath(import.meta.url)
const __dirname = dirname(__filename)

export default defineService('http.next', async (shutdown) => {
  const httpNext = new HttpNext({
    port: 3000,
    cwd: resolve(__dirname, '../..'),
    publicPath: 'public',
  })

  shutdown(await httpNext.start())
  return httpNext
})
```

然后用 `hile start --dev` 启动，CLI 会自动加载这个 boot 文件。

## API 路由（控制器）

控制器默认放在 **`src/controllers/`**（开发）或 **`dist/controllers/`**（生产），使用 `@hile/http` 的 `defineController`。

### 基本控制器

```typescript
// src/controllers/post.controller.ts
import { defineController } from '@hile/http'

export default defineController('GET', async (ctx) => {
  return { id: 1, title: 'Hello from API', url: ctx.url }
})
```

映射到 `GET /-/post`（默认 `controllerPrefix` 为 `'-/'`）。

### 带中间件的控制器

```typescript
// src/controllers/admin/users.controller.ts
import { defineController } from '@hile/http'

const auth = async (ctx, next) => {
  if (!ctx.headers.authorization) ctx.throw(401)
  await next()
}

export default [
  defineController('GET', [auth], async (ctx) => ({ users: [] })),
  defineController('POST', [auth], async (ctx) => ({ created: true })),
]
```

映射结果：
- `GET /-/admin/users`
- `POST /-/admin/users`

### 路径映射表

（路径相对于默认控制器根目录 `src/controllers/`，前缀为默认的 `/-`。）

| 文件路径 | HTTP 路由 |
|---------|----------|
| `src/controllers/post.controller.ts` | `/-/post` |
| `src/controllers/users/index.controller.ts` | `/-/users` |
| `src/controllers/users/list.controller.ts` | `/-/users/list` |
| `src/controllers/users/[id].controller.ts` | `/-/users/:id` |
| `src/controllers/[category]/[id].controller.ts` | `/-/:category/:id` |

## API 参考

### HttpNextProps

`HttpNextProps` 是 `HttpNext` 构造函数的配置对象，继承了 `@hile/http` 的 `HttpProps`。

#### 继承自 HttpProps

| 属性 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `port` | `number` | 是 | — | 服务监听端口号 |
| `keys` | `string[]` | 否 | 随机生成 | Koa 签名密钥，用于 signed cookie |
| `ignoreDuplicateSlashes` | `boolean` | 否 | `true` | 是否忽略路径中重复斜杠 |
| `ignoreTrailingSlash` | `boolean` | 否 | `true` | 是否忽略路径尾部斜杠 |
| `maxParamLength` | `number` | 否 | `Infinity` | 路径参数最大长度 |
| `allowUnsafeRegex` | `boolean` | 否 | `false` | 是否允许不安全正则 |
| `caseSensitive` | `boolean` | 否 | `true` | 是否大小写敏感 |

#### HttpNext 特有属性

| 属性 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `cwd` | `string` | 否 | `process.cwd()` | 项目根目录路径。所有相对路径都相对于此目录 |
| `publicPath` | `string \| string[]` | 否 | — | 静态资源根目录（相对 cwd）。可以是单个路径或多个路径的数组，每个路径会注册一个 `koa-static` 中间件 |
| `controllerDirectory` | `string` | 否 | `'controllers'` | 控制器目录名称，基于 `src/`（开发）或 `dist/`（生产）目录下的子目录名 |
| `controllerPrefix` | `string` | 否 | `'/-'` | API 路由的前缀，所有 API 路由都会挂在这个前缀下 |
| `controllerSuffix` | `string` | 否 | `'controller'` | 控制器文件的后缀标记，即扫描 `*.{suffix}.ts` 文件 |
| `specialControllers` | `SpecialController[]` | 否 | `[]` | 额外控制器根目录配置列表。主控制器加载完成后，按顺序逐个加载 |
| `nextArtifactsDir` | `string` | 否 | `resolve(cwd, '.next')` | Next.js 构建产物（`.next`）目录的路径 |

### SpecialController

```typescript
interface SpecialController {
  directory: string   // 相对 src/（开发）或 dist/（生产）的子目录名
  prefix: string      // 该组控制器的路由前缀
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `directory` | `string` | 控制器目录的相对路径（相对于 `src/` 或 `dist/`）。如 `'admin-api'` → 开发时加载 `src/admin-api/*.controller.ts` |
| `prefix` | `string` | 该组控制器的路由前缀。如 `'/admin'` → `GET /admin/users` |

**加载顺序**：主控制器 → `specialControllers[0]` → `specialControllers[1]` → ... → Next.js handler

```typescript
const httpNext = new HttpNext({
  port: 3000,
  specialControllers: [
    { directory: 'admin-api', prefix: '/admin' },
    { directory: 'public-api', prefix: '/public' },
  ],
})
```

### HttpNext 类

#### 构造函数

```typescript
constructor(options: HttpNextProps): HttpNext
```

构造函数执行流程：

1. 从 `process.env.NODE_ENV` 判断是否为开发模式（`NODE_ENV === 'development'`）
2. 创建 `@hile/http` 的 `Http` 实例（通过 `this.http` 访问）
3. 记录项目根目录 `cwd`
4. 如果指定了 `publicPath`，对每个路径注册 `koa-static(resolve(cwd, path))`
5. 解析控制器目录路径：`resolve(cwd, dev ? 'src' : 'dist', controllerDirectory)`
6. 设置默认的 `controllerPrefix`、`controllerSuffix`

#### 实例属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `http` | `Http` | 底层 `@hile/http` 的 `Http` 实例。可以通过它直接访问所有 Http 方法（如 `http.use()`） |
| `isDevelopment` | `boolean` | 是否为开发模式。基于 `process.env.NODE_ENV === 'development'` |
| `cwd` | `string` | 项目根目录路径 |

---

#### `use(middleware)`

注册 Koa 全局中间件，委托给底层的 `this.http.use()`。

```typescript
httpNext.use(async (ctx, next) => {
  console.log(`${ctx.method} ${ctx.url}`)
  await next()
})
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `middleware` | `Middleware` | Koa 中间件函数 |

**返回值**：`this`，支持链式调用。

---

#### `load(directory)`

便捷地加载指定目录的控制器，使用构造时配置的 `controllerSuffix`、`controllerPrefix`，并固定使用 `conflict: 'error'`。

```typescript
await httpNext.load('./additional-controllers')
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `directory` | `string` | 是 | 控制器目录路径 |

**内部等价于**：

```typescript
this.http.load(directory, {
  suffix: this.controllerSuffix,     // 默认 'controller'
  defaultSuffix: '/index',
  prefix: this.controllerPrefix,     // 默认 '/-'
  conflict: 'error',
})
```

**返回值**：`Promise<() => void>` — 异步返回取消注册回调。

---

#### `start(onListen?)`

启动 HTTP 服务并初始化 Next.js。这是 `HttpNext` 的核心方法，按固定顺序执行初始化流程。

```typescript
const close = await httpNext.start((server) => {
  console.log(`Server started on port ${httpNext.http.port}`)
})
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `onListen` | `(server: Server) => void \| Promise<void>` | 否 | HTTP 服务启动后的回调，在 Next.js 准备之前调用 |

**返回值**：`Promise<() => void>` — 返回关闭服务的回调函数。

#### start() 内部执行流程

<Steps>
  <Step title="1. 注册构建产物静态资源">
    注册 `koa-static(resolve(nextArtifactsDir, 'static'))`，提供 Next.js 构建的 JS/CSS chunk。
  </Step>
  <Step title="2. 加载主控制器">
    对主控制器目录调用 `http.load(controllerDirectory, { suffix, defaultSuffix: '/index', prefix: controllerPrefix, conflict: 'error' })`。
  </Step>
  <Step title="3. 加载 SpecialController">
    如果配置了 `specialControllers`，按顺序对每一项执行：
    ```
    http.load(resolve(cwd, src|dist, directory), { ...同, prefix: 该项的 prefix })
    ```
  </Step>
  <Step title="4. 启动 HTTP 服务">
    调用 `http.listen()` 启动 Koa 服务，传入 `onListen` 回调。
  </Step>
  <Step title="5. 初始化 Next.js">
    在 `onListen` 回调中：
    - 调用用户传入的 `onListen(server)`（如果有）
    - 创建 `NextServer({ dev, httpServer, dir })`，与 Koa 共用同一个 `http.Server`
    - 调用 `app.prepare()` — Next.js 编译页面、启动 HMR（开发模式）
    - 获取 `app.getRequestHandler()` 
    - 注册 Next.js 转发中间件（此后的所有未匹配请求由 Next.js 处理）
  </Step>
</Steps>

### Controller 文件约定

#### 默认后缀

默认情况下，`HttpNext` 使用 `'controller'` 作为后缀标记，这意味着它会扫描所有文件名以 `.controller.ts`（或 `.js`、`.tsx`、`.jsx`）结尾的文件。

| 文件名 | 是否匹配 |
|--------|---------|
| `user.controller.ts` | 是 |
| `post.controller.ts` | 是 |
| `admin.handler.ts` | 否（后缀必须为 `controller`） |
| `utils.ts` | 否 |

#### 默认前缀

默认情况下，所有控制器的路由路径都以 `/-` 开头。

| 文件路径 | 路由 |
|---------|------|
| `src/controllers/user.controller.ts` | `/-/user` |
| `src/controllers/post/index.controller.ts` | `/-/post` |
| `src/controllers/admin/setting.controller.ts` | `/-/admin/setting` |

#### 修改前缀和后缀

```typescript
const httpNext = new HttpNext({
  port: 3000,
  controllerPrefix: '/api',     // 改为 /api 开头
  controllerSuffix: 'handler',   // 改为扫描 *.handler.ts
})
```

此时：
| 文件路径 | 路由 |
|---------|------|
| `src/controllers/user.handler.ts` | `/api/user` |
| `src/controllers/post.handler.ts` | `/api/post` |

## 完整示例

### 完整的 Next.js + API 项目

```typescript
// src/services/boot.ts
import HttpNext from '@hile/http-next'
import { defineService } from '@hile/core'

export default defineService('http.next', async (shutdown) => {
  const httpNext = new HttpNext({
    port: 3000,
    cwd: process.cwd(),
    publicPath: 'public',               // 静态文件目录
    controllerDirectory: 'controllers',  // API 控制器目录
    controllerPrefix: '/api',            // API 前缀
    controllerSuffix: 'controller',
    specialControllers: [
      { directory: 'admin-api', prefix: '/admin' },
      { directory: 'webhook-api', prefix: '/webhook' },
    ],
  })

  // 注册全局中间件
  httpNext.use(async (ctx, next) => {
    const start = Date.now()
    await next()
    console.log(`[${ctx.status}] ${ctx.method} ${ctx.url} (${Date.now() - start}ms)`)
  })

  shutdown(await httpNext.start())
  return httpNext
})
```

### 控制器示例

```typescript
// src/controllers/user.controller.ts
import { defineController, createControllerMetadata } from '@hile/http'
import { z } from 'zod'

const listMetadata = createControllerMetadata({
  method: 'GET',
  schema: {
    query: z.object({
      page: z.coerce.number().default(1),
      limit: z.coerce.number().default(20).max(100),
    }),
  },
})

export default defineController(listMetadata, async (ctx) => {
  return {
    users: [],
    page: ctx.query.page,
    limit: ctx.query.limit,
  }
})
```

## 最佳实践

### 1. 为每个 API 模块使用独立的目录

```
src/
  controllers/              → /-/ (默认)
    user.controller.ts
    post.controller.ts
  admin-api/                → /admin
    dashboard.controller.ts
    stats.controller.ts
  webhook-api/              → /webhook
    payment.controller.ts
```

使用 `specialControllers` 配置：

```typescript
specialControllers: [
  { directory: 'admin-api', prefix: '/admin' },
  { directory: 'webhook-api', prefix: '/webhook' },
]
```

### 2. 开发时使用热更新

`NODE_ENV=development` 模式下：
- 控制器从 `src/controllers/` 加载（而非 `dist/`）
- Next.js 在开发模式下运行，支持 HMR
- 修改控制器文件后需要手动重启（或使用 nodemon）

### 3. 关注中间件执行顺序

`use()` 注册的中间件在 `start()` 之前添加，属于**全局中间件**，在所有路由之前执行。

```typescript
const httpNext = new HttpNext({ port: 3000 })

// order matters: 错误处理 > 日志 > CORS > 业务
httpNext.use(errorHandler())
httpNext.use(logger())
httpNext.use(cors())

await httpNext.start()
```

### 4. Controller 文件名不要冲突

避免同时存在 `users.controller.ts` 和 `users/index.controller.ts`，它们都会映射到 `/users`，会触发 `conflict: 'error'`。

## 常见错误排查

<AccordionGroup>
  <Accordion title="路由冲突错误">
    错误信息：`route conflict: GET:/-/users`

    **原因**：多个控制器文件映射到了相同的路由。

    **常见场景**：
    - 同时存在 `users.controller.ts` 和 `users/index.controller.ts`

    **解决方法**：删除或重命名其中一个文件。
  </Accordion>

  <Accordion title="Next.js 初始化失败">
    错误信息：Next.js prepare 阶段抛出的各种错误。

    **解决方法**：
    - 确保 `cwd` 指向了包含 `next.config.js`（或 `next.config.mjs`）的项目根目录
    - 确保 Next.js 已安装：`pnpm add next`
    - 确保 `.next` 目录存在（开发模式会自动生成）
    - 如果指定了 `nextArtifactsDir`，确保指向正确的 `.next` 路径
  </Accordion>

  <Accordion title="静态资源 404">
    请求静态文件（如 `/logo.png`）返回 404。

    **解决方法**：
    - 检查 `publicPath` 是否指向了包含静态文件的目录
    - 检查路径是否相对于 `cwd`
    - 验证目录是否存在
  </Accordion>

  <Accordion title="API 路由返回 404">
    请求 `/-/users` 返回 404。

    **解决方法**：
    - 检查控制器文件是否在正确的目录下（`src/controllers/` 或 `dist/controllers/`）
    - 检查文件名后缀是否匹配 `controllerSuffix`
    - 检查 `controllerPrefix` 是否配置正确（默认 `/-`）
    - 在控制器中打断点或加日志确认文件被加载
  </Accordion>

  <Accordion title="控制器默认导出格式错误">
    错误信息：`invalid service file: xxx.controller.ts (...)`

    **解决方法**：
    - 确保文件 `export default defineController(...)` 或 `export default [ctrl1, ctrl2]`
    - 不要导出一个空数组
    - 不要导出普通函数或对象
  </Accordion>

  <Accordion title="进程不退出的问题">
    关闭服务后进程仍不退出。

    **原因**：Next.js 的 HMR 连接或定时器未清理。

    **解决方法**：
    - 调用 `start()` 返回的关闭函数
    - 在程序的退出信号中调用关闭函数：
      ```typescript
      process.on('SIGTERM', () => { close(); process.exit(0) })
      process.on('SIGINT', () => { close(); process.exit(0) })
      ```
  </Accordion>
</AccordionGroup>
