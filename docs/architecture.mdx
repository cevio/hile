## 分层架构

Hile 按职责分层，各层可按需引入：

```
┌──────────────────────────────────────────────────────┐
│                    应用层 (App)                        │
│   services·controllers·pages；models 承载业务           │
├─────────────────┬────────────────┬────────────────────┤
│   @hile/cli     │   @hile/http   │  @hile/http-next   │
│   命令行启动器   │   HTTP 框架    │   Next.js 桥接     │
├─────────────────┼────────────────┼────────────────────┤
│  @hile/typeorm  │  @hile/ioredis │ @hile/message-modem│
│  数据库集成      │  Redis 集成    │  消息通信抽象       │
├─────────────────┴────────────────┴────────────────────┤
│                     @hile/core                         │
│          异步服务容器 · 生命周期 · 依赖图               │
└──────────────────────────────────────────────────────┘
```

<Note>
上图强调 **经 `@hile/core` 编排** 的常见 Web/数据栈。**`@hile/message-loader`、`@hile/message-ws`、`@hile/micro`** 等可脱离容器在任意 Node 进程中单独使用。
</Note>

### 各层职责（摘要）

<AccordionGroup>
  <Accordion title="基础层：@hile/core">
    **职责：** 管理服务的创建、缓存、依赖追踪与销毁。

    深入：[服务容器](/fundamentals/container)、[生命周期与事件](/fundamentals/lifecycle-and-events)；API 细节：[@hile/core](/packages/core)。
  </Accordion>
  <Accordion title="服务层：HTTP、数据、消息">
    **职责：** 具体基础设施。

    - **`@hile/http`** — Koa + find-my-way，路由与中间件；流程见 [HTTP 请求管线](/fundamentals/http-pipeline)；[@hile/http](/packages/http)。
    - **`@hile/http-next`** — 与 Next 共用端口；见 [HttpNext 与全栈分流](/fundamentals/http-next-pipeline)；[@hile/http-next](/packages/http-next)。
    - **`@hile/typeorm`** / **`@hile/ioredis`** — 见 [数据库](/techniques/database)、[缓存](/techniques/caching)。
    - **消息族** — modem / ipc / worker / ws / loader / micro；见 [消息与微服务发现](/techniques/messaging)。
  </Accordion>
  <Accordion title="编排：CLI">
    **职责：** 扫描 **`*.boot`**、加载服务、信号与日志。

    见 [CLI 概览](/cli/overview)；[@hile/cli](/packages/cli)。
  </Accordion>
</AccordionGroup>
